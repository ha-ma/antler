# 手順書: 車内の PWA を https で開く（pwa-https）

車載の Mac mini が、車ごとの CA で作った証明書で PWA（https）・アラート（wss）・Capture（https）を配る。
スマホは最初に 1 回だけ、その車の CA を入れる（付録 A #9「QR 1 回」）。インターネットは要らない。

- 仕様: `docs/specs/pwa-https/functional.md`（案の比較・決めたこと）、`threat.md`（受け入れたリスク）
- **なぜ https か**: iOS Safari と Android Chrome は、https でないページで GPS（Geolocation）・Wake Lock を出さない。
  `http://<Mac mini の IP>` の PWA では位置が取れず、ゾーン判定と画面の点灯維持が効かない
- ポート: PWA `https 8443`、設定ページと CA の配布 `http 8080`、アラート `wss 8765`、Capture `https 8767`

## 0. 前提

- Mac mini で `docs/runbooks/2026-11-04-mac-mini-day0.md` が済んでいる（`edge/detector` の venv がある）
- Mac mini が車の Wi-Fi の AP（インターネット共有、または旅行用ルーター）になっている
- macOS の `/usr/bin/openssl`（LibreSSL 3.3 以上）か OpenSSL 3 がある（`openssl version`）

## 1. AP の IP を調べる（1 分）

```sh
ipconfig getifaddr bridge100 || ifconfig bridge100 | awk '/inet /{print $2}'
```

確かめる: `192.168.2.1` のようなプライベートの IPv4 が出る。インターネット共有なら多くは `bridge100`。
旅行用ルーターなら、ルーターの管理画面で Mac mini の IP を**固定**にする（変わると手順 2〜4 をやり直す）。
家庭のルーターとよく重なる `192.168.0.x`・`192.168.1.x`・`192.168.2.x` は避け、`10.73.x.1` のような珍しいサブネットにする
（名前制約は IP で効くので、乗る人の家のルーターと同じ IP だと、CA がそのルーターにも効いてしまう）。

以下、この IP を `<IP>` と書く。

## 2. 証明書を作る（1 分。車ごとに 1 回）

```sh
cd ~/work/antler/edge/detector
python scripts/make_tls.py --out tls --ip <IP>
```

確かめる

- `tls/` に `ca.crt`・`ca.key`・`server.crt`・`server.key` ができ、鍵は `-rw-------`（`ls -l tls`）
- `CA の SHA-256 指紋:` と `http://<IP>:8080/` が出る。指紋は手順 5 の設定ページにも出る

注意

- CA は `ezoroad.local` と `--ip` の IP だけに効く（名前制約）。ほかのサイトの証明書を作れない
- **IP を変えたとき**は `--new-ca` を付けて CA から作り直す（名前制約に IP が入っているため）。スマホは CA を入れ直す
- `ca.key` は証明書を作り終えたら車の外（運営の PC・暗号化した USB）へ移す。サーバー証明書の更新（397 日）のときだけ戻す
- `tls/` は git に入れない（`.gitignore` 済み）

## 3. 設定（1 分）

`edge/detector/config.toml`（無ければ `config.example.toml` を写す）に足す:

```toml
[server]
host = "<IP>"

[capture_server]
host = "<IP>"

[tls]
cert = "tls/server.crt"
key = "tls/server.key"
ca_cert = "tls/ca.crt"

[pwa_server]
host = "<IP>"
https_port = 8443
http_port = 8080
dist = "../../apps/pwa/dist"
```

`[tls]` を書くと、アラートは wss、Capture は https になる。証明書が読めなければ**起動しない**（平文に戻らない）。
ログの `server.listening` と `capture.listening` の `"tls": true` で確かめる。

> 検知パイプラインの起動（edge-run、`python -m detector --config config.toml`）は `[tls]` があれば wss で待ち受ける。
> `[tls]` が壊れていれば起動しない（終了コード 2）。

## 4. PWA をビルドする（2 分。IP を変えたらやり直す）

開発用の Mac で（または Mac mini で）:

```sh
cd ~/work/antler
VITE_EDGE_HOSTS=ezoroad.local,<IP> npm run build -w apps/pwa
```

確かめる: `grep -o "wss://<IP>:8765" apps/pwa/dist/index.html` が出る（CSP に入った）。
PWA は**ページを開いたホスト**（一覧にあるとき）の 8765 / 8767 につなぐ。一覧に無いホストで開くと先頭（`ezoroad.local`）につなぐ。

## 5. PWA と設定ページを配る（起動したままにする）

```sh
cd ~/work/antler/edge/detector
python -m detector.pwa_server --config config.toml
```

確かめる

- `pwa_server: https 8443 / http 8080` が出る
- `pwa_server.cert_expiring`（残り 30 日未満）が出たら手順 2 をやり直す。期限切れなら起動しない
- `pwa_server.csp_missing_host` が出たら手順 4 を `<IP>` 入りでやり直す
- 別の端末から `curl -s -o /dev/null -w '%{http_code}\n' --cacert tls/ca.crt https://<IP>:8443/healthz` が `204`

## 6. カードの QR（1 回）

```sh
brew install qrencode   # 初回のみ
qrencode -o card-qr.png "http://<IP>:8080/"
```

車内のカードに印刷する。QR は **http の設定ページ**（CA を入れる前のスマホでも開ける）。
**カードに CA の指紋（手順 2 の `CA の SHA-256 指紋:`）も印刷する。** 設定ページは http なので、同じ Wi-Fi にいる別の端末
（前の借り手が置いていった機器など）が差し替えうる。乗る人はページに出る指紋とカードの指紋を見比べ、違えば入れない。
差し替えた CA には名前制約が無いので、入れるとほかのサイトの通信も読まれうる。Wi-Fi のパスフレーズは返却ごとに変える。

## 7. スマホに CA を入れる（乗る人ごとに 1 回。2〜3 分）

カードの QR を読み、設定ページの手順どおりにする。ページには 4 言語の手順と CA の指紋が出る。
証明書（プロファイル）の名前は **EZO ROAD** のまま（サービス名は 2026-11-08 に SHIKASHI NAVIGATOR に変わったが、CA を作り直さないため。`docs/changes/2026-11-08-shikashi-rebrand.md`）。
**ブラウザの警告を押し切らない**（押し切ると GPS・Wake Lock が出ないことがある）。
**ページの指紋とカードの指紋が同じことを確かめてから**ダウンロードする（先頭と末尾の 4 組だけでもよい）。

iPhone（Safari）

1. 「証明書をダウンロード」→「許可」
2. 設定 → 一般 → VPN とデバイス管理 → EZO ROAD → インストール
3. **設定 → 一般 → 情報 → 証明書信頼設定 → EZO ROAD をオン**（これを忘れると https が通らない）
4. 設定ページに戻ると、3 秒ごとの確認で「SHIKASHI NAVIGATOR を開く」が出る → `https://<IP>:8443/`

Android（Chrome）

1. 「証明書をダウンロード」
2. 設定 → セキュリティ → 暗号化と認証情報 → 証明書をインストール → CA 証明書 → ダウンロードしたファイル
3. 設定ページに戻り「SHIKASHI NAVIGATOR を開く」

返却したら消す（設定ページにも書いてある）

- iPhone: 設定 → 一般 → VPN とデバイス管理 → EZO ROAD → プロファイルを削除
- Android: 設定 → セキュリティ → 信頼できる認証情報 → ユーザー → EZO ROAD を削除

## うまくいかないとき

| 症状                                           | 原因と対処                                                                                                             |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| QR を読んでも設定ページが開かない              | スマホがモバイル回線を優先している。Wi-Fi を車の AP にし、「インターネットに接続されていません」の確認で「接続を維持」 |
| iPhone で Wi-Fi の後に何かのログイン画面が出る | キャプティブポータルの確認。「キャンセル」→「インターネットに接続しないで使用」                                        |
| `ezoroad.local` で開けない（Android）          | Android は `.local`（mDNS）を引けない機種が多い。カードの QR は IP にする（手順 6）                                    |
| 設定ページが「確かめています…」のまま          | iPhone の手順 3（証明書信頼設定）が抜けている。または Mac mini の時計がずれて証明書が「まだ有効でない」                |
| https は開くが B-0 が「つながっていません」    | edge-run が TLS で動いていない（手順 3 の `"tls": true`）。または PWA を `<IP>` 抜きでビルドした（手順 4）             |
| `pwa_server` が起動しない                      | 証明書の期限切れ・`host` の IP が証明書に無い（手順 2 を `--ip <IP>` でやり直す）                                      |
| IP が変わった                                  | 手順 2（`--new-ca`）・4・6・7 をやり直す。旅行用ルーターなら IP を固定する                                             |
| Mac mini の時計が大きくずれている              | オフラインで時刻が合わない。乗る前にインターネットにつないで合わせる（証明書の検証は時計に頼る）                       |

## 確かめた結果（2026-11-06、AC-2）

開発用の Mac（macOS 26.3）で、iOS Simulator の iPhone 15 Pro（iOS 17.5）を使った。

```sh
python edge/detector/scripts/make_tls.py --out <tmp>/tls --ip 127.0.0.1          # /usr/bin/openssl（LibreSSL 3.3.6）
VITE_EDGE_HOSTS=ezoroad.local,127.0.0.1 npm run build -w apps/pwa -- --outDir <tmp>/dist
python -m detector.pwa_server --config <tmp>/detector.toml                       # https 8453 / http 8090
node apps/pwa/scripts/fake-edge.mjs --scenario deer --port 8765 --tls-cert <tmp>/tls/server.crt --tls-key <tmp>/tls/server.key
xcrun simctl keychain <device> add-root-cert <tmp>/tls/ca.crt
xcrun simctl openurl <device> https://127.0.0.1:8453/
```

- Safari のアドレスバーに鍵のアイコンが出て、警告なしで `https://127.0.0.1:8453/` の PWA が開いた（信頼された https ＝ secure context）
- B-0 の「車載との接続」が **つながっています**。偽 edge のログに `client.connected`（wss）。受信/秒 1.0・遅延 120 ms
- 3 つの表示（緑・琥珀・赤）が出て、赤の白枠が点滅した
- 実機（iPhone・Android）での CA の取り込み、GPS・Wake Lock の許可は未確認（Deferred。実車の前に手順 7 で確かめる）
- Simulator のキーチェーンに入れたテスト用の CA は、`xcrun simctl keychain <device> reset` で消せる
