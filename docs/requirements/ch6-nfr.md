## 6. 非機能要件

> 出典: Claude Docs「EZO ROAD システム要件定義書 v1」https://claude.ai/artifact/Jr6zYHcjdSy5xEd1WaG7v8 （2026-11-03 エクスポート）。本文は原文のまま。変更は原文側で行い、再エクスポートする。


| 領域 | 要件 | 測り方 |
| --- | --- | --- |
| A 性能 | PC（内蔵 GPU、1440×900）で 60 fps、スマホ（iPhone 13 / Pixel 6 相当）で 30 fps 以上。初回読込は 3D アセットを除いて 3 秒以内、アセットは A-2 中にプリロード | Chrome Performance、`requestAnimationFrame` 計測を A-7 に記録 |
| A 対応環境 | Chrome / Edge / Safari 最新 2 バージョン。WebGL2 必須、WebGPU はあれば使う。PC 横 1280 以上、スマホ横画面 844×390 以上（縦画面はローテーション案内） | 手動テストマトリクス |
| B 遅延 | カメラフレーム時刻 → スマホ赤表示が 1,000 ms 未満（目標 500 ms）。内訳：推論 ≤ 100 ms、判定（2フレーム）≤ 250 ms、通信 ≤ 50 ms、描画 ≤ 50 ms | フラグ JSON に `t_frame` と `t_sent` を持たせ、スマホで `t_shown` を記録 |
| B 可用性 | 走行中に Wi-Fi が切れたら 5 秒以内に再接続。切断中は PWA がグレーの「未接続」帯を出し、ゾーン表示は継続 | 切断テスト |
| B 誤検知 | 誤検知を抑えるより見逃しを抑える。誤検知率は記録するが MVP では閾値を設けない | 走行ログ |
| セキュリティ | Mac Mini の Wi-Fi AP は WPA2、SSID とパスフレーズは車両ごとに QR で配布。WebSocket は LAN 内のみ。A API はレート制限（記録作成 10/分/IP）。アップロード画像は EXIF 除去 | コードレビュー |
| プライバシー | 第 5 章の「保存しない」を守る。記録 URL は推測困難な 8 文字 ID。削除リンクを A-7 に置く | データ辞書で確認 |
| 計測 | A：画面遷移、選択肢、アラート→ブレーキ時間、衝突/回避をイベントログに。B：検知・遅延・切断をローカルログに。外部解析サービスは使わない | ログの存在 |
