## 3. A：3Dシミュレーションの機能要件

> 出典: Claude Docs「EZO ROAD システム要件定義書 v1」https://claude.ai/artifact/Jr6zYHcjdSy5xEd1WaG7v8 （2026-11-03 エクスポート）。本文は原文のまま。変更は原文側で行い、再エクスポートする。


A の目的は「鹿を見つける」ではなく「自分で描いた旅を最後まで守る」。画面は A-1→A-2→(A-3⇄A-4)→A-5→(A-6 | A-7) の順でつながる。

### A-1 旅をつくる

| ID | 要件 | 優先 |
| --- | --- | --- |
| A1-1 | 入力：人数（1〜8）、運転できる人（1〜人数）、北海道ドライブ経験（はじめて/1〜2回/慣れている）、出発日時、返却・帰国日時、出発地（新千歳/釧路空港/札幌駅/旭川空港/函館空港）、予算（1人・宿と食事） | MUST |
| A1-2 | 楽しみの選択：エリアタブ「道東（釧路方面）」「道央（札幌方面）」。各エリア 12 件以上をマスター（JSON）で持つ。カードは写眐1枚＋名称＋補足（場所・季節・所要） | MUST |
| A1-3 | 選択上限 10 件。選択済みに重さ 1〜5（5段バー）。カウンター「選択 n / 10」を常時表示 | MUST |
| A1-4 | 右パネル「旅のしおり」を入力のたびに再生成：1行タイトル、D1〜Dn の行程、重さの配分バー。重さが大きい楽しみに長い時間を割り当てる（重さ5＝丸１日） | MUST |
| A1-5 | 「この旅が失われるリスク」スコア：エリア・月・日没時刻・経験・夜間移動を含む楽しみ（星空・日の出）から算出し、下域に根拠文を出す | MUST |
| A1-6 | 言語切替（ja/en/zh-TW/ko）、通貨併記（¥ と 概算 USD） | SHOULD |

### A-2 出発前ブリーフィング

| ID | 要件 | 優先 |
| --- | --- | --- |
| A2-1 | 当日ルートを地図に描き、鹿ゾーンを琥珀色の帯で重ねる。ゾーン通過予定時刻と日没・薄暮帯を表示（地図の実装方式は第9章①） | MUST |
| A2-2 | 鹿アラート ON/OFF トグル。ON の説明に B と同じ3状態の凡例を出す。初期値 ON | MUST |
| A2-3 | 当日の条件（運転者、車种、天候・路面、車内人数→曇り）を表示。条件はシード付き乱数で生成し、記録に残す | MUST |
| A2-4 | 操作説明（WASD / Space / クリック。スマホはドラッグ / ブレーキボタン / タップ） | MUST |

### A-3 運転中（3D）

| ID | 要件 | 優先 |
| --- | --- | --- |
| A3-1 | 右ハンドル車の運転席視点。ハンドルとメーターは画面右寄り、ナビは中央、スマホマウントはナビ上。車線中央線が右手すぐ近くに見える（左側通行） | MUST |
| A3-2 | カメラ：マウスカーソル位置に視線が追従（ヨー ±12°、ピッチ ±6°、イージング付き）。スマホはジャイロ。HUD はスクリーン座標に固定して動かない | MUST |
| A3-3 | 操作：W 加速、S 減速・後退、A/D ステア、Space ブレーキ。左クリック＝鹿を指す、ドラッグ＝囲む。スマホ：左円ドラッグでステア・上下で加減速、右円ブレーキ、タップで鹿 | MUST |
| A3-4 | 車両モデル：簡易車両力学（最高 100 km/h、圧雪でグリップ低下、制動距離は時速60kmで約50mを基準に路面係数で増減） | MUST |
| A3-5 | HUD：上部「旅のしおり」ストリップ（達成済み✓・現在・未達）、日・時刻・日没、再生速度 1×/4×/16×と一時停止、左上ゾーン状態（3状態＋次ゾーンまでの距離と到達予定）、天候・運転時間チップ、右上「つぎの楽しみ」カード（写真付き）、同乗者の吹き出し、下部操作・音トグル | MUST |
| A3-6 | タイムラプス：16× でも鹿ゾーンに入った時点で自動的に 1× に戻り、ゾーン内は変更不可 | MUST |
| A3-7 | 「つぎの楽しみ」は写真を自動スライドして注意を引く。アラート中（赤）は不透明度 60% に減光 | MUST |
| A3-8 | 同乗者の会話（テキスト＋音声）とラジオ。アラート時はラジオ自動ミュート | SHOULD |
| A3-9 | 運転交代：運転者が2人以上のとき、停車中に交代でき、疲労値がリセットされる | SHOULD |

### A-4 観光スポット（車を降りる）

| ID | 要件 | 優先 |
| --- | --- | --- |
| A4-1 | しおりの楽しみ地点に到達するとモーダル。写真（1〜3枚）＋短文＋滞在・支出・次到着予定 | MUST |
| A4-2 | 選択肢 2〜3。各選択肢に「鹿ゾーンをいつ通るか（昼/薄暮/日没後/通らない）」と失うもの（金額・楽しみの重さ）を必ず付ける | MUST |
| A4-3 | イベント生成：しおりの楽しみ（確定）＋ランダムイベント（給油、渋滞、天候変化、同乗者の要望）。頃度は離雸と経験値から決め、2〜3時間に1回を目安 | MUST |

### A-5 鹿ゾーン内・検知アラート

| ID | 要件 | 優先 |
| --- | --- | --- |
| A5-1 | 鹿ゾーン進入でゾーン状態が琥珀になり、チャイム 1 回。車内スマホも琥珀。残り距離を表示 | MUST |
| A5-2 | 鹿の出現：遭遇率と頃度はゾーンの重み×時刻（薄暮・夜が高）×季節（10〜11月が高）で決める。出現パターン：路肩静止・林縁で目の反射のみ・車線横断・群れ（2〜5頭）・車前で立ちすくみ | MUST |
| A5-3 | アラート ON のとき：鹿がシーン内で「カメラ検知条件」（距離≤120m、画角内、遮蔽なし、曇り・曗さによる確率低下）を満たしたら、車内スマホを赤にし、画面縁赤ビネット、中央上に「前方に鹿 左/右 nn m」、ビープ＋読み上げ。模擬検知遅延 150〜400 ms | MUST |
| A5-4 | アラート OFF のとき：上記を一切出さない。ゾーン状態の琥珀表示だけ残す | MUST |
| A5-5 | 鹿をクリック/タップ/囲むと「自分でも見つけた」ポイントを加算し、その瞬間のフレームと囲み範囲をキャプチャ（第7章 Capture） | MUST |
| A5-6 | 衝突判定：車両バウンディングボックスと鹿が接触したら A-6。ゾーンを抵けたら緑に戻り、最終日完走で A-7 | MUST |
| A5-7 | 回避成功時に「アラート→ブレーキ時間」「最接近距離」を記録 | MUST |

### A-6 喪失

| ID | 要件 | 優先 |
| --- | --- | --- |
| A6-1 | しおりの残り行程に取り消し線を入れ、衝突地点を✕で挿入 | MUST |
| A6-2 | 失ったもの 4 指標：車両損害（保険金支払平均 61.5 万円を基準値。最大 890 万円を併記。免責・NOC はプレースホルダ）、キャンセル・払い戻しなし（しおりの残り宿・体験×人数から計算）、失った日数、楽しみの達成 n/N（重さ合計も） | MUST |
| A6-3 | 統計カード：2025年 6,705件、釧路方面 1,751件、1件平均61.5万円。出典を表記。数字は設定ファイルから読み、コードに埋めない | MUST |
| A6-4 | 大きなボタンは1つ「鹿アラートをONにして同じ道をやり直す」→ A-2 にアラート ON で戻り、同じシードで再生。副：「衝突の3秒前を見る」「別の旅をつくる」 | MUST |

### A-7 旅の記録

| ID | 要件 | 優先 |
| --- | --- | --- |
| A7-1 | 記録 URL（`/t/{id}`）を発行。ログイン不要で閲覧でき、OG 画像にしおりを描画 | MUST |
| A7-2 | 守れた楽しみ（写真）、ゾーン通過回数、遭遇/回避、アラート→ブレーキ平均、ゾーンでの各回のログ | MUST |
| A7-3 | 「実際の旅にも同じアラートを」ブロックから B の紹介（B-0）へ | MUST |
| A7-4 | しおりを画像（PNG）で保存。「アラート OFF で挑戦」で同じシードを OFF で再生 | SHOULD |
