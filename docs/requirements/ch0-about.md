## 0. この文書について

> 出典: Claude Docs「EZO ROAD システム要件定義書 v1」https://claude.ai/artifact/Jr6zYHcjdSy5xEd1WaG7v8 （2026-11-03 エクスポート）。本文は原文のまま。変更は原文側で行い、再エクスポートする。


この文書は、Claude Code の PM エージェントが EZO ROAD の MVP を 1 週間で実装計画に落とすための要件定義書です。UI/UX は Claude Design キャンバス「北海道ドライブSim UI設計」の v2 ページ（A-1〜A-7、B-0〜B-3、B アーキテクチャ、スマホ横画面 A-3/A-4/A-5）を正とし、本書はその挙動・データ・制約を言葉にしたものです。

**読み方**

- 「MUST」は MVP で必須、「SHOULD」は時間が許せば、「MAY」は将来。
- 第 9 章「ユーザー判断が必要な検討事項」は未決です。PM エージェントは、そこに記入された判断を読んでから設計を確定してください。空欄のままなら、各項目の「推奨」を仮採用し、その旨をプランに明記します。
- デザインシステムは Claude Design の「EZO ROAD Design System」アーティファクトに別途あります（第 8 章）。

**用語**

| 用語 | 意味 |
| --- | --- |
| A（シミュレーション） | ブラウザで動く 3D 運転シミュレーションゲーム。運転前に遊ぶ |
| B（車載検知） | 車載 Mac Mini がカメラ映像から鹿を検知し、ドライバーのスマホに通知するシステム。運転中に使う |
| 旅のしおり | A-1 で生成される旅程カード。タイトル・D1〜D5・楽しみ（重さ付き）を持つ |
| 楽しみ | ユーザーが選んだ観光要素。重さ 1〜5。最大 10 件 |
| 鹿ゾーン | 事故統計に基づく鹿多発区間。地図上の琥珀色の帯 |
| 3 状態 | 緑（ゾーン外）／琥珀（ゾーン内）／赤（鹿検知）。A と B で共通 |
| 喪失 | A で衝突したときの結果画面。失った金額・日数・楽しみを示す |
| キャプチャ | 鹿を発見した瞬間のフレーム画像＋囲んだ範囲＋条件ラベル。教師データになる |
