## 4. B：車載検知システムの機能要件

> 出典: Claude Docs「EZO ROAD システム要件定義書 v1」https://claude.ai/artifact/Jr6zYHcjdSy5xEd1WaG7v8 （2026-11-03 エクスポート）。本文は原文のまま。変更は原文側で行い、再エクスポートする。


B は「鹿が前方にいるか」を 1 秒未満でドライバーに伝える。映像は車外に出さず、スマホにはフラグと小さなフレームだけを送る。

### ハードウェア（MVP 実機）

| ID | 要件 | 優先 |
| --- | --- | --- |
| B1-1 | Mac Mini（Apple Silicon）を DC12V → 正弦波インバーター 300W で駆動。自動ログインと検知プログラムの自動起動 | MUST |
| B1-2 | USB Webカメラ（暗所センサー、60fps）をフロントガラス上部に固定。解像度と fps は設定ファイル | MUST |
| B1-3 | 振動・熱対策（座席下マウント）。将来の小型ボード移行を妨げないよう、検知コードはカメラ・推論・通信をアダプタで分離 | SHOULD |

### 処理パイプライン（jev）

| ID | 要件 | 優先 |
| --- | --- | --- |
| B2-1 | フレーム抽出：640×480 にリサイズ、5〜10 fps に間引き | MUST |
| B2-2 | 一次検知：YOLOv8（CoreML、Neural Engine）で deer クラスのバウンディングボックスと確信度。目標 ≤ 50 ms/フレーム | MUST |
| B2-3 | 二次確認：確信度 0.4〜0.8 の「痑い」フレームのみ VLM に渡す。VLM の結果を待たずに一次検知が 0.8 以上なら即時フラグ | SHOULD |
| B2-4 | 判定：2 フレーム連続で閾値超えでフラグ ON、1.5 秒検知なしで OFF。距離はボックス高さから概算（設定テーブル）、方向はボックス中心の左右 | MUST |
| B2-5 | 検知フレームはローカルに Capture スキーマで保存。走行後に同意のあるものだけアップロード | MUST |
| B2-6 | 誤検知と見逃しを記録するため、ドライバー（同乗者）が音声「いた」「いない」でラベルを付ける | MAY |

### 通信

| ID | 要件 | 優先 |
| --- | --- | --- |
| B3-1 | Mac Mini を Wi-Fi AP 化（SSID `EZOROAD-xxxx`）、スマホは QR で接続。インターネット不要 | MUST |
| B3-2 | WebSocket でフラグ JSON（第7章）を配信。フラグ変化時に即時、それ以外は 1 秒ごとにヒートビート | MUST |
| B3-3 | 検知時は JPEG（320px）のフレームを付ける。スマホは表示しない（記録・デバッグ用） | SHOULD |
| B3-4 | BLE GATT は代替経路としてインターフェースを用意する。MVP では実装しない | MAY |

### スマホ PWA（B-0〜B-3）

| ID | 要件 | 優先 |
| --- | --- | --- |
| B4-1 | B-0 接続：Wi-Fi 接続状況、カメラ受信（fps・遅延）、音量最大の案内、3表示のプレビュー、「テスト音を鳴らして出発」。これが唯一の操作画面 | MUST |
| B4-2 | B-1 ゾーン外（緑）：大きな円＋チェック、「鹿ゾーンまで nn km」を巨大数字で。路線名とゾーン到達予定時刻 | MUST |
| B4-3 | B-2 ゾーン内（琥珀）：三角＋鹿ピクト、「鹿ゾーン走行中」、残り km、「減速 50 km/h 以下に」。進入時にチャイム 1 回 | MUST |
| B4-4 | B-3 検知（赤）：八角＋鹿ピクト、「前方に鹿」、方向矢印と距離を巨大数字で、「ブレーキ」。画面全体が赤と白で点滁（1 Hz）。ビープ最大音量＋読み上げ | MUST |
| B4-5 | ゾーン判定は GPS × 鹿ゾーンDB でスマホ側で行う。Mac Mini がなくても B-1/B-2 は動く（赤は出ない） | MUST |
| B4-6 | 走行中に押すボタンを置かない。画面常時点灯（Wake Lock）、自動回転ロック | MUST |
| B4-7 | 言語：主文は端末言語、副文に他 3 言語の一語（DEER AHEAD ・ 前方有鹿 ・ 전방 사슴）を常に併記 | MUST |
