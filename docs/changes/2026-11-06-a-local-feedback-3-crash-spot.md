## 1. ユーザーの指摘（原文）

1. 「開始後、鹿ゾーンに入るまで10kmではなく、鹿ゾーンに入るまで1km地点からスタートにする」
2. 「運転中のスマホが揺れるのをなくしたい。また、z-indexが誤っているのか、スマホが不自然に浮いて表示されて見えることがある。」
3. 「鹿にぶつかったときに、すぐさま次の画面にいくのではなく、ぶつかった時の衝撃音を出して、段々と画面がまわりから暗くなっていき、視界・意識が途切れていく様子を表現したい」
4. 「鹿をクリックして、鹿を発見する機能がない。鹿を事前に発見できた件数を結果画面に表示したい」

## 2. 推奨で決めた解釈（CLAUDE.md の方針。PR にも書く）

### 2.1 1 km 手前から（指摘 1、R1）

- ステージは「鹿ゾーンの入口の 1 km 手前」から出口まで（`STAGE_LEAD_M = 1000`。前は 5 km。ゾーンが入口の手前で切れている所では「鹿ゾーンまで」が 10 km 近く出ていた）。ルートの始点より前にはしない。区間の長さの上限 8 km・出口でクリアは変えない
- 1 km は 16 倍の再生で約 4〜5 秒。ゾーンの前のおすすめ（drive-tourism）・ゾーンの前の会話が出る時間は短くなる（drive-sound-tourism に申し送り）

### 2.2 スマホの揺れと浮き（指摘 2、R2）

- 原因: drei の `Html transform` は 3D の座標（数十 km の世界座標）を CSS の 3D 行列に入れるので、合成時の単精度で毎フレーム揺れ、重なりの順も HUD とずれる
- 直し方: スマホは 3D の車内に貼らず、**HUD の層の決まった位置（ナビの上あたり、画面の左 40%・下から 64 px）に固定**した。3D の本体と台も外した。視線・カメラの揺れで動かない。HUD の中で最初に描く（ほかの HUD の下）。小さい画面では縮める（0.42 倍）
- アラート OFF では今までどおり描かない

### 2.3 衝突の演出（指摘 3、R3）

- 当たってから約 3.5 秒（`CRASH_MS`）: カメラの揺れ（0.8 秒で弱まる）→ 白く 1 回光る（0.3 秒、点滅しない）→ 周りから暗くなる（ground）→ 3D がぼける（1.0 秒から）→ 衝突の帯、旅の場面は A-6 へ
- reduced-motion では揺れ・光・ぼかしを出さず、暗くなるだけ
- 衝撃音は書かない（drive-sound-tourism がエンジンの `collided` の合図で鳴らす）。合図は HUD が `collided` になる同じフレームで出る（テストで保証）
- run の保存は当たったフレームで始める（演出の途中で離れても残る）。A-6 への移動だけ演出のあと（`onCrashEnd`）
- 演出の色は ink（光）と ground（暗転）。alert-danger は鹿検知専用なので使わない。当たったことは role="alert" で 1 回読み上げる

### 2.4 鹿の発見（指摘 4、R4）

- 3D の鹿をクリック / タップすると「発見」。見えている鹿だけが当たる（150 m 以内・林に隠れていない。夜の目の反射だけの鹿も数える）。外れ・ドラッグ（8 px 超）・同じ鹿の 2 回目・一時停止の間・衝突のあとは数えない
- 「事前に発見」= 発見したとき鹿が車より前で 60 m 以上離れていた（圧雪で 60 km/h から止まれる距離より遠い）。アラート ON と OFF を比べる数には使わない
- 分母の「出た数」は一度でも見えた鹿の頭数
- HUD: 左の列に「鹿を発見 n / m 頭」の小さな 1 行（輪・音なし）
- 結果: `DriveResult.spotting = { appeared, found, early }`。A-6 は URL の `spot=found.early.appeared` で 1 行、A-7 は run の省略できる `spotting` と集計の `totals.spotting` で 1 行（並べ方・見た目は result-screens に任せる）

### 2.5 検知の取りこぼし（親セッションの調査から、R5）

- 調査（晴れ・薄暮・60 km/h、動き 12 種 × シード 40）: ほかの 10 種は 100% 赤（中央値 6.8 秒前）。`dart`（林の陰から至近の飛び出し）は赤が 91% で、出ても衝突まで 1 秒未満が約半数。目の反射だけの鹿は林の中なので 0%
- `dart`・`graze-dash` に限って、検知の遅延を 80〜150 ms（ch3 A5-3 の 150〜400 ms と違う。推奨で決定）、最初の抽選をいちばん近い帯（30 m 未満）の確率にした。ほかの動きは変えない
- 目の反射だけの鹿はスマホでは検知しない（B のカメラにも体が写らない）と仕様に明記し、「鹿の発見」の的にした（目が光っている間）
- 入れないもの: 進路の予測による事前の赤、1 フレームの予備の琥珀 → 赤
