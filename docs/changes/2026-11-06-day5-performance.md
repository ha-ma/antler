# 変更記録 2026-11-06（Day 5）: A の性能

> **この変更の範囲**: A（apps/sim）の運転の描画の重さ、rAF の記録、ビルドの分け方、画面の遅延読込。記録の形には `packages/trip` の `FrameSummarySchema` に省略できる 2 欄を足した。
> 3 状態の色・形・音（alert-ui）、AlertFlag・Capture・TripPlan の形、B は変えていない。CSS・HUD の配置・タッチとジャイロの入力（mobile-landscape）と文言の表（i18n）は、同時に別のセッションが直すので触っていない。
> 仕様は `docs/specs/performance/functional.md`、実測は `docs/reports/2026-11-06-performance-measure.md`。

## 1. 依頼

- ch6「A 性能」を測り、足りないところを直す
  - PC の内蔵 GPU・1440 × 900 で 60 fps
  - スマホ（iPhone 13 / Pixel 6 相当）で 30 fps 以上
  - 初回読込は 3D アセットを除いて 3 秒以内
  - A-2 の間にアセットを先読みする
  - rAF の計測を A-7 に記録する
- ch10 の受け入れ基準（A-3 で PC 60 fps、スマホ横 30 fps）を確かめる

## 2. 分かったこと

- main の時点で、PC 相当・スマホ相当（CPU 4× 減速）の 8 場面とも、走行中は 60 fps に張り付いていた（M2 の GPU で描いたとき）
  - 雪の粒・紅葉と雨・4× の早送りで区間をまたぐ動きのどれでも落ちない
  - vsync を外すと、1 フレームの仕事は p50 で 1〜3 ms だった
- 足りなかったのは初回読込だった
  - main の `/plan` は全画面を 1 つの入口に入れていた（JS 222.6 KB）
  - そのため Slow 4G ＋ CPU 4× で LCP が 3.80 秒だった
- スマホと Windows の内蔵 GPU は、この方法（M2 の GPU で描く）では測れない

## 3. 推奨で決めたこと（PR にも書く）

| 項目               | 決めたこと                                                                                                                                                                                     |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 落ちたフレームの線 | 40 ms を超えた間隔（その瞬間に 25 fps を割った）。30 fps に張り付く端末の揺れ（33.3〜36 ms）は数えない                                                                                         |
| 数える範囲         | 走っている間だけ数える。一時停止の間と、終わった後（衝突・完走のバナーの間）は数えない。落ちたフレームと数えたフレームは走行の全体で数え、やり直しで 0 に戻す                                  |
| 記録               | `FrameSummarySchema` に省略できる `dropped`・`counted` を足した（0〜1,000 万の整数）。両方ある場合と両方無い場合だけを通し、`dropped` が `counted` を超えるものは弾く。表の作り直しは要らない  |
| 開発用の表示       | `/drive?fps=1` のときだけ左下に数字を出す（読み上げない・押せない・訳す文言なし）                                                                                                              |
| 描くもの           | 変えない。計測ではどの場面も合格だった                                                                                                                                                         |
| 安全網             | DPR の自動の段を入れた: 最初の 2 秒は判定しない。その後、2 秒の窓が 2 つ続けて「遅い」なら 1.5 → 1.25 → 1 と下げ、戻さない。「遅い」は PC で 45 fps 未満、スマホ（粗いポインタ）で 27 fps 未満 |
| 遅延読込           | A-1 は入口に残し、ほかの画面はルートの `lazy` で読む。A-1 だけ残すのは、`/` と知らないパスの行き先で 1 往復を足さないため                                                                      |
| 先読み             | A-2 を読んだら、空いたとき（最長 2 秒）に運転のチャンクと 3D を先読みする。データ節約（Save-Data）の端末ではしない                                                                             |
| 回線の条件         | 合格は Fast 4G（RTT 150 ms・9 Mbps ＋ CPU 4×）で `/plan` と `/drive` の LCP が 3 秒以内。Slow 4G の値は記録する                                                                                |
| CI                 | バンドルの上限（画面ごと・3D・全部、gzip）を local-ci の検査にした。上限は実測の約 1 割増し                                                                                                    |

## 4. 結果

- **fps**: PC の 4 場面とスマホ相当の 4 場面が合格（150 秒ずつ、vsync あり）
  - 走行中と赤の出始めの 1 秒に、33.4 ms 超のフレームは 0
  - 長いフレームは「もう一度」直後の作り直しの 1 回だけ（スマホ相当で 133 ms）
- **初回読込**: Fast 4G で `/plan` の LCP は 0.91 秒（main は 1.45 秒）、`/drive` は 1.28 秒（main は 2.27 秒）
  - Slow 4G の `/plan` は 2.63 秒（main は 3.80 秒）
  - Slow 4G で A-2 を通らずに直接開いた `/drive` は 3.96 秒で、3 秒を超える
- **バンドル**: `/plan` は 228.6 → 186.1 KB（gzip）。3D は 246.5 KB で、運転の画面に入った後と A-2 の先読みでだけ読む
- **GPU なし**（参考）: 自動の段で DPR が 1 まで下がった（Canvas 2160 × 1350 → 1440 × 900）

## 5. 残したこと

- 実機の確認（Deferred、期日は 2026-11-08）: iPhone 13 か Pixel 6 で `/drive?fps=1` の p5 を見る。Windows の内蔵 GPU で 60 fps を見る
- 30 fps を割ったときの見直しの順: 霧で隠れる木の打ち切り → 雪・雨の粒の数 → ミラーの頻度
- 「もう一度」の作り直しを複数のフレームに分けるか（実機で目立てば）
- A-2 の先読みが A-2 の操作に響くかの計測。A-7 の画面に fps を出すこと（文言が増えるので i18n の後）
