## 2. 推奨で決めた解釈（CLAUDE.md の方針。PR にも書く）

### 2.1 A-1 の送信ボタン（指摘 1）

候補 3 つから (a) を選んだ。押すと起きる 2 つ（しおりができる・次の A-2 で鹿ゾーンを地図で見る）が両方分かる。

| 候補         | 文言                               | 選ばなかった理由                                                    |
| ------------ | ---------------------------------- | ------------------------------------------------------------------- |
| (a) **採用** | しおりを作って鹿ゾーンを確かめる → | —                                                                   |
| (b)          | この旅の鹿ゾーンを地図で見る →     | しおりを作る（Claude がタイトルを書く・待ちがある）ことが分からない |
| (c)          | しおりを仕上げて次へ →             | 何のために次へ行くのかが分からない                                  |

4 言語: en「Make my plan & check deer zones →」、zh「製作手冊並確認鹿區 →」、ko「일정표 만들고 사슴 구역 확인하기 →」（「鹿區」「사슴 구역」は A-2 と同じ語）。320 px 幅でも 1 行に収まることを確かめた。

### 2.2 A-6 のカードが落ちて積み重なる（指摘 2）

- 落ちるもの: Claude の文の欄・4 指標の各タイル・しおりのカード・統計カード。導線（ボタン）は落とさず、並びの位置で静かに現れる。見出しと事実の 1 文は最初から出す（遷移のフォーカスと読み上げが最初に読むもの）
- 順番は DOM の順（＝読み上げ・Tab の順）。画面の上（−70vh）から加速して落ち、着地で少し潰れて小さく 2 回弾み、わずかに傾いて（1° 以内、しおりは今までどおり −1.5°）止まる。1 枚 820 ms、150 ms ずつ遅れる（全部で 2 秒前後）
- 色は変えない（喪失の金額は clay、✕ の行だけ alert-danger）。傾きは決まった表（乱数なし）
- 動きを減らす設定では落下なし。同じ順に不透明度だけで現れる。落ちる前の要素に Tab でフォーカスが入ったら即座に見せる

### 2.3 A-7 の「クリア」（指摘 3）

- 鹿にぶつからずに走りきった直後: 3 状態の safe と同じ円（alert-safe）が描かれて塗られ、チェックが描かれ、大きな「クリア」（spruce）と「D{n} を、鹿にぶつからずに走りきりました。」が出て、控えめな紙吹雪（spruce・alert-safe・spruce-deep の 24 片）が 1 回だけ落ちる。数字のカウントアップは作らない（「3 / 4」のような値の途中を読み上げ・画像の保存が拾うため）
- **衝突のあと（A-6 の「この旅の記録を見る」から）は一切出さない**: リンクが location state の合図を付け、A-7 はそれを見て祝いを出さない。記録のデータだけでは分からない（OFF の挑戦の衝突でもその日の結果は ON の完走のまま・衝突の run の保存は裏で続く・所有者でない端末は保存しない）ため
- 祝いは 1 つの履歴につき 1 回（戻る・再読み込みで繰り返さない）。開いたあとに取り直した記録で判定する（古いキャッシュで決めない）
- 合図の無い直の訪問（共有のリンク）は、最後の日が完走なら出す。OFF だけの完走も「クリア」
- 動きを減らす設定では描き終わった形で出し、紙吹雪は出さない。「クリア」の文字と説明は出す

### 2.4 触らなかったもの・文言だけ直したもの

- 「衝突の 3 秒前を見る」: 衝突の 3 秒前から衝突までのリプレイは、2026-11-06 にユーザーが見送った（推奨は入力の記録＋決定的な再シミュレーション、約 1.5〜2 日・1 回 1〜3 KB）。調べると、このボタンは 3 秒前には戻らず、その日の最初から走るだけだったので、**文言を「この日を最初から走り直す」（4 言語）に直した**（行き先・コードは変えない。仕様 R6）
- 鹿の発見の件数の 1 行（「事前に発見した鹿 n / m」）: drive-crash-spot のセッションが A-6・A-7 に足す。A-6 は `dropSequence` の次の番号を渡せば落ちる並びに入る。A-7 の祝いの帯は見出しの上の 1 つの塊で、下に何が足されても位置は変わらない
- `features/drive/**` と `app/DriveRoute.tsx`、api の SSR の `/t/:id`（共有の記録には祝いを出さない）

## 3. 残したこと（Deferred）

- 本人が OFF の挑戦で衝突した直後に、新しいタブ・ブックマークで A-7 を開くと、その日の ON の完走で「クリア」が出る。正確にするには TripRecord に「保存順で最後の run の結果」を足す（@antler/trip・api・SSR に及ぶので別 feature）
- 動きの強さ（速さ・弾み・紙吹雪の量）はユーザーの見た目の確認で調整する（CSS の変数だけを直す）
