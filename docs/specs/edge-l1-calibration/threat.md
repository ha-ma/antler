# 脅威: edge-l1-calibration（ラベルの書き出しと温度の学習）

どちらも開発者が手で回すオフラインのスクリプト。ネットワークに出ない・待ち受けを開かない。
守るものは 1 つ: **`calibration.json` は「L1 で赤を下げてよいか」を決める**（edge-l1 R5）。壊れた・偏った・合成のデータから緩い温度を書くと、
実行時に本物の鹿の赤が下がる。なので「誰が何を書けるか」より「どのデータからなら書いてよいか」を表にする。

## IDOR / Mass Assignment チェック

### トレース（sim → export_l1_labels.py）

- [ ] 読むのは R1 の欄だけ。余分な欄は捨てる。語彙・有限の数・昇順を検証し、1 行でも違えば全体を拒否（TR-1b）
- [ ] 緯度経度・端末識別子・人の情報を持たない（道の座標 s・d だけ）
- N/A: IDOR — 資源を ID で指す操作が無い（ファイルを丸ごと読むだけ）

### 答えのファイル（bench_l1.py → calibrate.py）

- [ ] 読むのは `id`・`model`・`probs`・`labels`・`meta.traceId`・`meta.source`（と評価の内訳の `meta.pattern`）だけ。余分な項目で閾値・温度・モデル名は変わらない
- [ ] 確率は有限の 0〜1、選択肢が揃わなければ全体を拒否（FIT-1f）
