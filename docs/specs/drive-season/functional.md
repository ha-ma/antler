# 仕様: drive-season（季節と天気で路面・景色・ブレーキを変える）

## 概要

ユーザーの 2 回目の指摘（`docs/changes/2026-11-06-a-local-feedback-2-season.md`）のうち「季節で道路の表現を変えたい（常に雪道）」「雪道や雨でブレーキが効きにくく」を、運転（`apps/sim/src/features/drive/`）と当日の条件の表（`packages/trip/src/day/conditions.ts`、brief-map R4）に入れる。
要件: ch3 A3-2（3D の景色）・A3-4（車両力学）・A2-3（当日の条件）、ch6「A 性能」。前の feature: drive-3d（R3・R6・R12）、drive-tune（R3・R5）、brief-map（R4）。ここで変わるルールはそれぞれの仕様にも書き直す。

**Tier 1**: 認可・永続化・外部への副作用・並行性に触れない（条件はシードから決まり保存しない）。

**範囲外**: 鹿の出方（drive-deer）、車内の会話・音（drive-audio-chat の後継のセッション）、HUD の配置（`components/hud/` は天候の文言 1 行だけ）、B の L1 の天候の語彙（`dataset/`・edge）、時刻（見本の場面は 16:40 のまま）。

**drive-deer（2026-11-06、先にマージ）との合流**: 鹿の数・動き・検知の画角が drive-deer で変わった。この仕様の景色・ブレーキ（UC-4a・UC-4b の停止距離）はその上でも同じ値で通ることを、合流の後に確かめた。

## Example Map

Story: 北海道を走る旅行者として、自分の旅の季節の道（雪・雨・乾いた道）で、その路面の止まりにくさを体で覚えたい。

- R1: 天候と路面は旅の日の月と種で決まる（当日の条件 v2）
  - 天候は `clear | cloudy | rain | snow | fog`（`rain` を足す。推奨で決定）。表は変更記録 §3.2（冬 12〜3 月は v1 のまま、4・11 月、5・6・9・10 月、7・8 月）
  - 雨の日の路面は濡れ（4・11 月は 1 割が凍結）。雪の日に乾燥は出ない（v1 のまま）。5〜10 月に圧雪・凍結は出ない。12〜3 月に雨と濡れは出ない
  - 雨・雪・霧の日は窓の曇りを 1 段上げる（v1 の雪・霧に雨を足す）
  - 表を変えたので `CONDITIONS_VERSION` は 2。同じ種・同じ日・同じ月なら同じ条件。冬の表は変えないので、12〜3 月の旅は版以外 v1 と同じ条件（200 シード × 1〜5 日を v1 の指紋と照らす）
  - 表に重み 0 の項目を置かない（`pickWeighted` はキーの順に区間を割り当てるので、0 の項目やキーの順の入れ替えで他のシードの結果が黙って変わる）
  - 天候を指定できる（`weather`。見本の場面の切り替え用）: その月の表に無い天候は指定を無視する。乱数の列は指定しないときと同じだけ進める（路面だけが指定の天候の表から引かれる）
  - 雨の日の条件は `DayConditionsSchema`（`packages/trip/src/day/schema.ts` の zod）を通る（A-2・drive・A-6 の検証で落ちない）
  - **版の波及（推奨で決定）**: v1 は再現しない（4〜11 月の保存済みの旅は A-2 の条件が変わる。受け入れる）。会話・立ち寄りの保存済みの束のキーは routes・zones のままにする（会話の api は別のセッションの領域で永続化の形に触れるため。冬の旅は条件が v1 と同じなので、ずれるのは 4〜11 月の旅で v1 のときに作った束だけ）。api と sim は同じ PR で入れる（`z.literal(CONDITIONS_VERSION)` なので版がずれると応答が検証で落ちる）
- R2: 見本の場面で季節を選べる
  - `/drive?month=N`（N は 1〜12 の整数）: 見本の旅の種・2 日目・月 N（`departMonth` も N）で当日の条件（R1）を決め、出発は 2027 年 N 月 15 日 16:40（+09:00）
  - `&weather=W`: R1 の天候の指定。`month` が無いときは 2 月として扱う。言葉は正しいがその月の表に無い天候（2 月の雨）は、指定なしと同じ（その月の抽選）
  - どちらも無い・読めない（`month=13`・`month=abc`・`weather=hail`）ときは今までどおり 2 月 15 日 16:40・圧雪・曇り・窓の曇り light（drive-tune・鹿の受け入れテストの前提）。**`?month=2` は表の抽選なので既定と違う**（見本の種・2 日目は晴れ・凍結）
  - 出発の案内（見本の場面だけ）に季節の切り替え 6 つ（URL・文言・天候・路面は見本の種・2 日目で決まる）:

    | id      | URL                      | 文言               | 天候・路面 |
    | ------- | ------------------------ | ------------------ | ---------- |
    | default | `/drive`                 | 既定（2 月・薄暮） | 曇り・圧雪 |
    | winter  | `?month=2&weather=snow`  | 冬・雪（2 月）     | 雪・圧雪   |
    | frozen  | `?month=2&weather=clear` | 冬・晴れ（2 月）   | 晴れ・凍結 |
    | thaw    | `?month=4&weather=rain`  | 雪どけ・雨（4 月） | 雨・濡れ   |
    | summer  | `?month=7&weather=clear` | 夏・晴れ（7 月）   | 晴れ・乾燥 |
    | autumn  | `?month=10&weather=rain` | 秋・雨（10 月）    | 雨・濡れ   |

  - リンクはいまの URL の他の値（`alert=off`）を保ち、month・weather だけ差し替える。いま選んでいるものは `aria-current`。**ページを読み直すふつうのリンク**（`DrivePage` はエンジンを読み込みのときに 1 回だけ作るので、SPA の遷移では場面が変わらない。spec-adversary C1）
  - 見本の場面の条件も出発の案内に出す（旅の場面と同じ「天候・路面」）
  - 旅の URL（`?trip=…`）に `month`・`weather` があっても無視する（場面の条件はその日の DayPlan。走行の記録が条件を持たないので、上書きを許すと凍結の日を乾燥で走った記録が残る）
- R3: 景色は月で、車道は路面で決める
  - 景色の季節（`sceneSeasonOf`）: 12〜3 月 冬、4 月 雪どけ、5〜9 月 緑、10 月 紅葉、11 月 初冬。路面が圧雪なら月に関係なく冬
  - 景色の月は場面の `startAt`（JST）の月。旅の場面では最初の移動の出発で、その日の `date`（当日の条件の月）と同じ日（drive-link）。見本の場面は R2 の月 N
  - 季節ごとに 地面・路肩・路肩の外の法面（冬と雪どけは雪の壁、ほかは草）・針葉樹の雪（冬だけ）・広葉樹の葉（緑は緑、紅葉は黄と橙、ほかは葉なし）を変える。法面の形（高さ）は季節で変えない（鹿の足の高さ `terrainHeight` を変えない）
  - 車道: 乾燥はアスファルト、濡れは暗く照り返す（光沢）、圧雪は白っぽく轍が見え線がかすれる、凍結は青白く照り返す
  - 降るもの: 雪の日は雪、雨の日は雨。ほかは降らない
  - 空: 晴れは今までどおり、曇り・雨・雪・霧は空を灰色に寄せる。霧の距離は天候の係数（雨 0.7）
  - 色は `scene/palette.ts` だけに書く（UI の色は tokens.json。alert-danger をシーンに使わない）
- R4: ブレーキは路面の μ で効きが変わる（drive-tune R3 の μ をそのまま使う）
  - 場面の路面がエンジンの車両力学に渡る: 40 km/h から 乾燥 約 7.9 m < 濡れ 約 11 m < 圧雪 約 17.3 m < 凍結 約 78.5 m（±10%）
  - 雨の日（R1）の場面は濡れで、乾燥より止まりにくい。雪の日の場面は圧雪か凍結
  - ABS の灯は乾燥以外で点く（drive-tune R3 のまま）
  - μ はスタッドレスタイヤが前提（北海道の冬のレンタカー。タイヤを替える 4・11 月も同じ値を使う）
- R5: 文言
  - 天候「雨」: HUD・出発の案内 `雨`、A-2 の条件 4 言語（雨 / Rain / 雨 / 비）
  - 季節の切り替えの文言（日本語。HUD の他の文言と同じく日本語のみ）
- R6: 性能（ch6 A 性能、drive-3d R12）
  - 降るものは粒をまとめた 1 描画コール（雪・雨のどちらか）。粒の数は定数の上限まで。バックミラーには描かない。ライトは増やさない
  - 季節で描画コール数を増やさない（林は種類ごとに InstancedMesh 1 つのまま。葉は木の形に含める）。季節ごとの林の三角形数を報告に残す
  - PC 60 fps・スマホ 30 fps を落とさない

推奨で決定（CLAUDE.md の方針。PR にも書く）: 変更記録 §3 のすべて（雨を天候に足す、表の割合、景色の季節の区分、見本の場面の URL と切り替え、16:40 のまま）と、版の波及の扱い（R1）。spec-adversary の指摘（C1・M1〜M4・m1〜m6、2026-11-06、`docs/reports/2026-11-06-spec-adversary-drive-season.md`）は上の各ルールに取り込んだ。

## ユースケース

### UC-1: 当日の条件 v2（R1）

- **Given**: 旅の種・日・月（と、見本の場面の天候の指定）
- **When**: `dayConditions` で当日の条件を決める
- **Then**: その月の表から天候と路面が出る。雨の日は濡れ、冬は雪・凍結が主、夏は乾燥か濡れ

### UC-2: 見本の場面の季節（R2）

- **Given**: `/drive?month=7&weather=rain`
- **When**: 見本の場面を作る
- **Then**: 7 月 15 日 16:40、雨・濡れ。出発の案内に「雨・湿潤」と季節の切り替えが出る

### UC-3: 景色（R3）

- **Given**: 場面の月・路面・天候
- **When**: 3D のシーンを組み立てる
- **Then**: 季節の地面・法面・木と、路面の車道、天候の降るものと空になる

### UC-4: ブレーキ（R4）

- **Given**: 同じ道で路面だけが違う場面
- **When**: 40 km/h から踏みきる
- **Then**: 停止距離が路面の μ の順に長くなる
