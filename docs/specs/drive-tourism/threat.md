# 脅威: drive-tourism（A-3 運転中の観光の会話と、鹿ゾーンの前のおすすめ）

**drive-audio-chat と同じ。新しいルートなし。** HTTP の操作は既存の `POST /api/trips/:id/day/:n/chat` だけで、認可（ownerToken）・レート制限・1 日の上限・同時の枠・保存の単位は `docs/specs/drive-audio-chat/threat.md` のまま。
この feature で変わるのは (1) 応答・保存の行に `pleasure`（楽しみの id。マスターの slug）が増える、(2) Claude に渡す材料に楽しみの拠点の地名・時間帯・所要の区分・切り口が増える、(3) 保存の鍵の版が `chat:v2` になる、の 3 つ。おすすめのカード（sim）はサーバーに何も送らない。

## IDOR / Mass Assignment チェック

### POST /api/trips/:id/day/:n/chat

- **IDOR**: drive-audio-chat のまま（ownerToken のハッシュが旅の行と合うときだけ）
- **クライアントから受け取るフィールド**: パスの `id`・`n`、ヘッダの `Authorization` だけ（body は読まない）
- **サーバー側で設定するフィールド**: 行の `pleasure` を含む束の全部。`pleasure` は旅のしおり（`TripPlan.days[].stops`）とマスターから決め、Claude の出力からは取らない（Claude は text だけを書く）
- **クライアントから受け取ってはいけないフィールド**: `pleasure`・切り口・文（body を読まないので受け取りようが無い）
- **検証方法**: 応答の schema（`chatLineSchema`、strict）で `pleasure` は `string | null`。sim は zod で確かめ、マスターに無い id は null にする（任意のパスの画像を読ませない。写真の URL は `photoOf` の記録からだけ作る）

## 横断的セキュリティチェック

- [x] CORS・レート制限・エラーメッセージ・secrets・body の上限: drive-audio-chat のまま
- [x] プロンプトインジェクション: 材料はマスターの値だけ（利用者の自由入力を含まない）。楽しみの名前・地名は 4 言語のマスター

## Test List への追加

マトリクスの ❌ セルは 3 つ（会話の POST の未認証、鍵の版を上げた後の未認証、所有者の上限）。drive-audio-chat の AUTH-41・AUTH-45 と同じ守りを、鍵の版を上げた後（v1 の束がある旅）で確かめる。ID は sfad-drift の形（`AUTH-数字`）に合わせて 61 から:

- [x] AUTH-61: 応答の行の `pleasure` はしおりの楽しみの id か null だけ（Claude の出力に id の欄があっても使わない。domain の割り当てから来る）
- [x] AUTH-62: v1 の束を保存した旅・日でも、トークンが無ければ 403 OWNER_REQUIRED（鍵の版を上げても Claude を呼ばせない）
- [x] AUTH-63: v1 の束も数えて 1 つの旅 30 束に達していたら、v2 の鍵の作成は 409 CHAT_LIMIT（Claude を呼ばない）
