# 脅威: pwa-uplink（PWA → edge の速度・ゾーン・光）

edge の WebSocket（`ws://ezoroad.local:8765/alerts`）を叩けるのは WPA2 の AP に入った端末だけ（edge-judge の threat.md と同じ前提。AP と QR は別 feature）。
ここで増えるのは「クライアントから届く新しい入力 `vehicle`」と「その入力が L1 の問い合わせの state に入る」こと。L1 は赤を**下げる**ことしかできず、条件（校正後 0.9 以上・今のエピソード・赤の候補が 1 つ・`lane` でない・2.0 秒以内）は変えない。

## Authorization Matrix

| 操作                                                  | クライアント（AP に入った端末。PWA も別の端末も区別しない）                                          | AP の外の端末      | edge の判定（内部）                                   |
| ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------- | ------------------ | ----------------------------------------------------- |
| `vehicle`（速度・ゾーン・光）を送る                   | ✅ 形が合うものだけ受ける。置き換えで保持（最後に届いた有効なものが勝つ）                            | N/A: AP に入れない | N/A: 受ける側                                         |
| `vehicle` で緯度経度・精度・時刻・端末識別子を送る    | ❌ strict で拒否。前の値を残す。保持も記録もしない（AUTH-2）                                         | N/A: AP に入れない | N/A: 受ける側                                         |
| `vehicle` だけで赤にする・赤を解く                    | ❌ 赤は L0 だけ。受信は fusion と送信を呼ばない（AUTH-1）                                            | N/A: AP に入れない | N/A: 判定は自分の入力だけで決める                     |
| `vehicle` で L1 の降格を起こす（`zone=outside` など） | ❌ 降格の条件は変わらない。校正なし・前のエピソード・赤の候補でない・`lane` なら降格しない（AUTH-1） | N/A: AP に入れない | ✅ 条件をすべて満たすときだけ降格（edge-l1 R5）       |
| `vehicle` で設定・閾値・校正・接続先を変える          | ❌ ネットワークからは変えられない（AUTH-3）                                                          | N/A: AP に入れない | ✅ 起動時の設定ファイルだけ                           |
| 64 KB 超・1 秒 5 通超の `vehicle` を送る              | ❌ 超過は捨てる（64 KB は接続を切る）。赤の送信は止まらない（AUTH-4）                                | N/A: AP に入れない | N/A: 受ける側                                         |
| 古い `vehicle` を使い続けさせる                       | ❌ edge が 10 秒（単調時計）で固定値に戻す。端末の時刻は使わない                                     | N/A: AP に入れない | ✅ 固定値（60 km/h・inside・night・low）に戻す        |
| `vehicle` の値を読む                                  | ❌ 配信しない（flag にも載せない）                                                                   | N/A: AP に入れない | ✅ L1 の問い合わせの state とログ（zone・light のみ） |

## IDOR / Mass Assignment チェック

### vehicle（クライアント → サーバー）

- [ ] 余分な項目（`lat`・`lon`・`accuracy`・`timestamp`・`deviceId`・`remainingKm` など）を足すと、メッセージ全体を拒否する（MASS-1）。必要な 3 項目だけを読んで残りを捨てる方式にはしない（位置が紛れ込んでも通さない）
- [ ] 本文をそのままログや判定に流さない。ログに出すのは zone・light の値と、速度が有るかだけ
- [ ] 値は範囲・型を検証してから使う（速度 0〜300 の有限の数、zone・light は列挙）。検証に通らなければ前の値を残す
- N/A: IDOR — ID でほかの資源を指す操作が無い（接続は全員同じ配信を受け、`vehicle` は 1 つの共有の状態を置き換えるだけ）

### vehicle の使い道（edge 内部）

- [ ] `vehicle` の値は JudgeRequest の `state` の 3 項目にだけ入る。距離・TTC・左右・`conf`（AlertFlag の数値）には入らない
- [ ] `headlight` は常に固定値。`vehicle` で変えられない

## 横断的セキュリティチェック

- [x] CORS: N/A（HTTP の API を足さない。WebSocket の Origin は見ない。LAN 内の信頼の境界は AP の WPA2）
- [ ] レートリミット: PWA は 1 秒に 1 通。edge は 1 接続 1 秒 5 通・64 KB の既存の上限（ack と合わせても 2 通以下）
- [ ] エラーメッセージ: クライアントに検証エラーを返さない（無視するだけ。内部の情報を返さない）
- [ ] ログマスキング: 本文・クライアントのアドレス・速度の値・位置を出さない
- [ ] 位置: 緯度経度は PWA の端末の外に出ない（ネットワーク・ログ・storage）。`vehicle` の型に位置の席が無い
- [ ] 見逃しの向き: `vehicle` の誤り・偽りは、L1 への入力を変えるだけ。L0 の赤は変わらず、降格は 0.9 以上の校正済みの答え 1 つ分の条件を満たさなければ起きない。さらに、固定値で学習した校正のもとでは実値を使わず（`context` が `real` のときだけ使う）、速度は学習の下限 30 km/h で持ち上げる。固定値で学習した校正のもとでは、偽の `zone=outside`・`speed=0` で降格が増えない（AUTH-5）。残るリスク（security-auditor W-1）: 校正が `context: "real"` のとき、AP 内の端末が学習範囲内の state（低速・ゾーン外・昼）へ L1 の入力を誘導できる。降格の既存条件（校正後 0.9 以上・今のエピソード・赤の候補 1 つ・`lane` でない・2.0 秒以内）は変わらず、AP に入れる人だけが相手（edge-judge と同じ前提）。許容する。`vehicle_state = "fixed"` で実値を切り離せる
