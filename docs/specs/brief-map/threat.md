# 脅威: brief-map（A-2 出発前ブリーフィング・その日のルートとゾーン）

この feature の HTTP の操作は `GET /api/trips/:id/day/:n` の 1 つ（読み出しだけ。書き込みは無い）。
守るものは「旅の中身（人数・日程・選択。個人は特定しない）を ID を知らない人に見せないこと」「所有者の印（ownerToken のハッシュ）を出さないこと」「読み出しの濫用（ルート計算の CPU）」の 3 つ。
ブラウザは地図の背景（スタイル・タイル・フォント）を外部の提供元（OpenFreeMap）から読む。送るのはタイルの座標だけで、旅の ID や中身は送らない。

plan-trip の threat.md は「読み出しで所有者トークンを照合する」と書いたが、brief-map では照合しない（推奨で決定）。
理由: A-7 の記録 `/t/{id}` はログイン不要で ID を知る人に見せる（A7-1）、A-6 からの「同じ道をやり直す」（A6-4）や別の端末で開いた記録からも読む。旅の ID は英数 8 文字（62^8 ≒ 2.2 × 10^14）で推測できないので、ID そのものを「見る権利」とする。ownerToken は削除（record）にだけ使う。

**✅ (公開) の理由**: 付録 A #9「A が登録なしで最後まで」と A7-1「ログイン不要で閲覧」。旅は個人を特定する情報を持たない（plan-trip の threat.md のデータ分類）。ID は推測困難で、総当たりはレート制限で抑える。

## IDOR / Mass Assignment チェック

- **IDOR**: 対象は URL の `id` で決まる。所有者の概念で絞らない（上の理由）。ID を知らなければ届かない。無い id と形の違う id は同じ 404（ID の形を探られない）
- **クライアントから受け取るフィールド**: パスの `id`（英数 4〜16 文字）と `n`（1 以上の整数）だけ。クエリ・body は読まない
- **サーバー側で設定するフィールド**: 応答のすべて（plan・details は保存した値、day は計算した値）
- **クライアントから受け取ってはいけないフィールド**: N/A: 書き込みが無い（GET のみ）
- **検証方法**: zod でパスを検証（`n` は `^[1-9][0-9]{0,2}$`）。応答は `{ plan, details, day }` を明示して組み立て、保存した行（ownerTokenHash を含む）をそのまま返さない

## Data Classification

| データ                                                               | 分類                                                            | 保存先                           | 露出先                         | 削除方針                                          |
| -------------------------------------------------------------------- | --------------------------------------------------------------- | -------------------------------- | ------------------------------ | ------------------------------------------------- |
| TripPlan・TripDetails（人数・日程・出発地・予算・選択・Claude の文） | 内部（個人を特定しない。ID を知る人にだけ見せる）               | SQLite（plan-trip が保存済み）   | この API の応答（ID を知る人） | 所有者の削除（record）。この feature では消さない |
| DayPlan（ルート・時刻・ゾーン・条件）                                | 公開してよい（地点は空港・観光地のマスター、ルートは OSM 由来） | 保存しない（毎回計算）           | この API の応答                | N/A: 保存しない                                   |
| ownerTokenHash                                                       | 機密（削除の権利の照合）                                        | SQLite（plan-trip）              | 外に出さない（応答に含めない） | TripPlan と同時                                   |
| routes.json（地点間のルート）                                        | 公開（OSM 由来、ODbL）                                          | リポジトリ（packages/trip/data） | api の計算に使う               | N/A: 公開データ                                   |
| 地図タイルの要求（座標・ズーム）                                     | 公開                                                            | 保存しない                       | OpenFreeMap（ブラウザから）    | N/A: 送るのはタイルの座標だけ                     |

ログのマスキング: 旅の ID はアクセスログの path に残してよい（読み出しの鍵だが、ログは運用者だけが見る。運用者は DB も読める）。応答の本文・ownerTokenHash はログに出さない。IP はレート制限のためにメモリで持つだけで、保存・ログ出力しない。

応答は plan を丸ごと返す（泊まる町・人数・日程・seed を含む）。A-7 の記録と同じく、ID を知る人には旅を見せる。seed で鹿の出方が先に分かっても、シミュレーションの中のことで害は無い（spec-adversary [5]、推奨で決定）。
タイルの要求で旅の ID を外に出さないよう、sim の HTML は `referrer` を `strict-origin` にする（外へは origin だけ）。

## 横断的セキュリティチェック

- [x] CORS: 既存の `CORS_ORIGINS`（`*` は起動で拒否）をこの route にも当てる
- [x] レートリミット: `GET /api/trips/:id/day/:n` に IP あたり 1 分 60 件（既存の rate-limit の middleware）
- [x] エラーメッセージ: 例外は error-mapper で code と短い文だけ。スタックトレースは返さない
- [x] ログマスキング: 応答の本文と ownerTokenHash を出さない
- [x] secrets: N/A: この feature はキーを使わない（OSRM・OpenFreeMap はキー不要）
- [x] 外部通信: api は実行時に外部へ通信しない（ルートは同梱）。ブラウザは OpenFreeMap だけに行き、旅の ID・中身を URL に載せない
- [x] 地図のスタイル URL は `VITE_MAP_STYLE_URL`（ビルド時の値）。利用者の入力から作らない
- [x] ファイルアップロード: N/A（この feature はファイルを受けない）
