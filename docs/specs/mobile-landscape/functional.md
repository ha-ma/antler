# 仕様: mobile-landscape（A をスマホの横画面で使う）

## 概要

A（`apps/sim`）をスマホの横画面（844×390 以上）と PC（1280 以上）で使えるようにする。ロードマップ Day 5。
要件: ch6「A 対応環境」（スマホ横画面 844×390 以上、縦画面はローテーション案内。PC 横 1280 以上。確かめ方は手動テストマトリクス）、ch3 A3-2（スマホはジャイロで視線。HUD はスクリーン座標に固定）・A3-3（スマホ: 左円ドラッグでステア・上下で加減速、右円ブレーキ）、ch8 規約 6（タップ領域 44px 以上、アイコンだけのボタンに aria-label）、ch10 の受け入れ基準（A-3 でスマホ横 30 fps、HUD はカメラを動かしても固定）。

**Tier 1**: 認可・永続化・外部への副作用・並行性に触れない（端末の向きのセンサーの許可はブラウザの許可で、サーバの認可ではない）。

**範囲外**: 文言の表（`*-text.ts`・`text.ts`）の既存の中身（4 言語化は i18n のセッション。ここでは新しく足す文言だけ）、`scene/` の描画の重さ・バンドル・fps の実測（performance のセッション）、鹿を指す・囲む操作（PC のクリックも未実装。下の Deferred）。

**事前の確認（2026-11-06、`docs/reports/img/mobile-landscape-before/`）**: `/plan`・A-2（`/trip/:id/brief`）・A-6（`/loss/:id`）・A-7（`/t/:id`）は 844×390・1280×800・390×844（縦）のどれでも横にはみ出さず、縦にスクロールして読める。崩れているのは `/drive`（A-3・A-5）だけ:

- 844×390 で左の列（ゾーン状態・区間の案内）と上の帯（時刻・再生速度）が重なる。右の列（会話・おすすめ・音量）が画面の 4 割を取る。下のキーの説明が 2 段になり、左下の速さ・音トグルと重なる
- 出発の案内が画面の高さに収まらず、上が切れる
- 車内のスマホ（drei の Html）が、出発の案内・HUD の上に重なる（1280×800 でも。z-index が 1,600 万台で、`.drive__scene` が重なりの文脈を作っていない）

## Example Map

Story: 北海道のレンタカー旅行者として、出発前にスマホを横にして、指とスマホの向きで運転の練習をしたい。

**指で操る端末の判定**（R1〜R4 で共通）: 円・ジャイロは `(any-pointer: coarse)`（指で触れるポインタが 1 つでもある。タッチの PC・キーボード付きの iPad も含む）。キーの説明を隠す・縦画面の案内は `(pointer: coarse)`（主のポインタが指）。どちらも走っている途中に変わったらその場で切り替える（画面の外の matchMedia の変化を購読する）。

- R1: 運転画面の配置（844×390〜1280×800 のどれでも重ならない）
  - 大きさの区分は 2 つ。**小さい画面** = 幅 1100px 以下 **または** 高さ 560px 以下。それ以外は今までどおり
  - 小さい画面: 右の列の幅 `--drive-chat-w` を `min(260px, 30vw)`、左の列の幅 `--drive-left-w` を 240px、画面の端の余白を space-3 にする。PC の右の列 360px の決まり（drive-tune R4）は大きい画面でそのまま
  - 上の帯（時刻・再生速度・天候のチップ）は、左の列の右端から右の列の左端までの間の中央に置く（大きさによらず左の列・右の列と重ならない）。小さい画面の上の帯は詰める（ボタンの間を space-1）が、ボタンは 44px のまま
  - ステージのクリアの帯・赤のバナー（前方に鹿）は、上の帯・左の列より下（どの大きさでも上から 176px。`--drive-banner-top`）
  - 高さが 560px 以下では、左の列の区間の案内を区間・残り・到着予定・ステージだけにする（今日の楽しみの一覧は出さない。右の列のおすすめが受け持つ。赤のバナーと重ねない）
  - 高さが 560px 以下では、右の列のおすすめカードの一言（note）を出さず、カードの高さを列の 45% までにする（音量の操作を押し出さない）
  - 出発の案内・終了の帯は画面の高さに収める（はみ出す分は中でスクロール）。小さい画面は内側の余白を space-4
  - 車内のスマホ（3D の中の Html）は HUD・出発の案内・終了の帯・縦画面の案内より下に描く（`.drive__scene` が重なりの文脈を作る）
  - 指で操る画面（R3）では、キーの説明を出さず、操作の円を出す。速さと音トグルは左右の円の間（下の中央寄り）
  - 見える範囲: `viewport-fit=cover` は使わない（iPhone の横のノッチ側の safe-area はブラウザが空ける）。運転画面は `position: fixed; inset: 0` なので、Safari のツールバーで高さが 390 より小さくなっても見える範囲に合わせる
  - 844×390 より小さい横画面（667×375・740×360 など）は対応環境の外。案内は出さず、同じ小さい画面の配置で崩れないことだけ手動で見る（重なってもよいが、ボタンが画面の外に出ない）
  - 重ならないことは jsdom では確かめられないので、手動テストマトリクス（下）で、Playwright のタッチの模擬で HUD の箱の重なりを測って記録する
- R2: 縦画面のときのローテーション案内（`/drive` だけ）
  - 主のポインタが指（`(pointer: coarse)`）で縦（`(orientation: portrait)`）のとき、運転画面の全面に「横にしてください」の案内を出す。アイコン（端末が回る絵）はインライン SVG（stroke）
  - 文言は 4 言語。主文はその旅の言語（見本の場面は ja）、副文に残り 3 言語を常に併記（AlertState と同じ形）
  - 運転中に縦にしたら一時停止する（タブが隠れたときと同じ。横に戻しても自動では再開しない）。縦の間は一時停止のボタンも案内の下に隠れる（案内が全面を覆う）。横に戻したら一時停止のボタンで再開する
  - PC の細長いウィンドウ（マウス）では出さない。`/plan`・A-2・A-6・A-7・停車の出来事は縦でも読めるので出さない（推奨で決定。共有された A-7 を縦で開いた人を止めない）
  - 案内は操作要素を持たない。読み上げは role="alert"（縦にするたびに 1 回読む）
  - 案内の間は、下の画面（3D・HUD・出発の案内）を `inert` にする（見えないボタンに Tab・読み上げで届かない。accessibility-checker C2）
- R3: 指の操作（A3-3）
  - 指で操る端末で、走っている間（出発後・衝突／完走の前）で縦の案内が出ていないときだけ、左下に「左の円」、右下（右の列の左）に「右の円」を出す
  - 左の円（直径 120px、中のつまみ 48px）: 円の中で触れ始めてドラッグする。つまみは指に付いていき、円の外には出ない。中心からのずれ（半径で割った −1〜1）で、横が −0.3 より左 → 左（A）、0.3 より右 → 右（D）、縦が −0.3 より上 → 加速（W）、0.3 より下 → 減速・後退（S）
  - 右の円（直径 88px）: 押している間ブレーキ（Space）
  - 1 つの円は最初に触れた指だけを使う（2 本目の指は無視）。円の外で触れ始めて滑り込ませても使わない。左右の円は同時に使える（指ごとにポインタを捕まえる）
  - 指を離す契機: pointerup・pointercancel・lostpointercapture、window の blur、タブが隠れる、円が消える（走り終わる・縦にして案内が出る）。どれでも、その円の入力を全部離す（指の入力元だけ。キーの押下は残す）。逆に、キーの blur はキーの入力元だけを離す（今までどおり。指の入力は指の契機で離す）
  - キーと指の入力は 1 か所で合わせる（`InputMixer`。入力元ごとに自分の押下を渡し、エンジンにはどれかが押していれば押している（OR）を渡す）。キーの hook もエンジンではなく合わせる口に渡す
  - 一時停止の間も押下はそのまま（エンジンは止まっていて進まない）。再開したら押しているものが効く
  - 円の上と運転画面ではスクロール・拡大・長押しのメニュー・文字の選択をしない（`touch-action: none`・`-webkit-touch-callout: none`・`user-select: none`）
  - 読み上げ: 左の円は role="group" と aria-label「ハンドルとアクセル（ドラッグ）」、右の円は button と aria-label「ブレーキ」。目に見える文字のラベル（ハンドル・ブレーキ）も付ける。色は surface・line・spruce（alert-danger・clay は使わない）。タップ領域は 44px 以上
  - 出発の案内の操作の説明は、主のポインタが指の端末ではキーの代わりに「左の円: ドラッグでハンドルと加減速」「右の円: ブレーキ」「スマホの向き: 視線」
- R4: ジャイロの視線（A3-2）
  - 指で操る端末だけ。「出発」「もう一度」の操作の中で、音の解錠（今までどおり）と同じ同期の流れの中で `DeviceOrientationEvent.requestPermission` があれば呼ぶ（iOS。ユーザーの操作の中でないと許可を聞けない）。結果を待たずに走り出す（許可のダイアログが出ている間も走れる）。`granted` か、関数が無い（Android・iOS 12 以前）ときだけ聞き始める。`denied`・例外・reject・`DeviceOrientationEvent` が無いときは聞かない（出発は止めない）
  - 端末の背面の向き（alpha・beta・gamma から求めた、背面が指す方角と仰角）を使う。縦横どちらの持ち方でも同じ式
  - 最初に届いた向きを基準にする。視線の目標 = 基準からのずれ（方角のずれ ÷ 12°、仰角のずれ ÷ 6°、それぞれ −1〜1 に丸める）を `lookTarget` に渡す（ヨー ±12°・ピッチ ±6°。イージングは今の `easeLook`）
  - 基準は時定数 5 秒でいまの向きに寄っていく（持ち方を変えても、しばらくすると正面に戻る）。一時停止の間も同じ（視線は止まっていても動かせる）。「もう一度」で基準を取り直す
  - 背面がほぼ真上・真下（仰角の絶対値が 70° 超）のときは方角が定まらないので、方角のずれは前の値のまま
  - 許可されない・向きが届かない（beta か gamma が null）・1 秒届かないときは、ジャイロを使わず:
    - マウスは今までどおり Canvas の上のカーソルの位置
    - 指は運転画面（円・ボタンの外）をドラッグした量で視線を動かす（画面の幅の半分で右いっぱい、高さの半分で上いっぱい）。指を離したら正面に戻す（目標を 0 にし、イージングで戻る）
  - ジャイロの視線は止められる（WCAG 2.5.4。accessibility-checker C1）: 指で操る端末では、出発の案内に切り替えのボタン（「スマホの向きで視線を動かす」、aria-pressed、既定 ON）を置く。OFF なら許可を聞かず、向きも聞かず、視線は指のドラッグだけ。操作の説明の 3 つ目も「画面をドラッグ: 視線」にする
  - 走り終わる・画面を離れるときは聞くのをやめる。ジャイロでも HUD は動かない（DOM で、カメラに付いてこない）

推奨で決定（CLAUDE.md の方針。PR にも書く）: 小さい画面の区分（幅 1100px 以下か高さ 560px 以下）、指で操る端末の判定（any-pointer / pointer の使い分け）、案内を `/drive` だけにすること、運転中に縦にしたら一時停止、円の大きさと 0.3 の遊び、指の視線は離したら正面に戻すこと、基準の時定数 5 秒と 70° の打ち切り、`viewport-fit=cover` を使わないこと。spec-adversary の指摘（2026-11-06、Critical 3・Major 6・Minor 3）と accessibility-checker の Critical 2 は上の各ルールに取り込んだ。

## ユースケース

### UC-1: 配置（R1）

- **Given**: 844×390 または 1280×800 の画面
- **When**: 運転画面を開いて出発する
- **Then**: 左の列・上の帯・右の列・下の操作が重ならず、出発の案内は画面に収まり、車内のスマホは HUD の下に描かれる

### UC-2: 縦画面の案内（R2）

- **Given**: 指で操る端末を縦に持つ
- **When**: `/drive` を開く（または走っている途中で縦にする）
- **Then**: 4 言語の「横にしてください」が全面に出る。走っている途中なら一時停止する

### UC-3: 指の操作（R3）

- **Given**: 指で操る端末で走っている
- **When**: 左の円を上や横にドラッグする、右の円を押す
- **Then**: 加速・ステア・ブレーキがエンジンに入る。キーの入力と打ち消し合わない

### UC-4: ジャイロ（R4）

- **Given**: 指で操る端末で「出発」を押した
- **When**: 端末を右に回す・上に傾ける
- **Then**: 視線が右・上に動く（±12°・±6° まで）。許可が無ければドラッグで動き、離すと正面に戻る
