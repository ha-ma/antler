# 脅威: drive-audio-chat（A-3 運転中の音・車内の会話）

この feature の HTTP の操作は `POST /api/trips/:id/day/:n/chat` の 1 つ（その日の会話の束を作る・保存済みなら返す）。音（sim の Web Audio）はサーバーに何も送らない。
守るものは「Claude の費用（何度も呼ばせる濫用）」「他人の旅で Claude を呼ばせないこと」「所有者の印と保存の鍵を出さないこと」の 3 つ。

旅の id は記録 `/t/{id}`（A7-1、ログインなし）で共有される公開の値なので、Claude の費用を使う権利にしない。旅を作った端末だけが持つ ownerToken（plan-trip R7。api はハッシュだけを持つ）を `Authorization: Bearer` で求める（stop-deck と同じ。推奨で決定）。トークンの無い端末（共有の URL で開いた人）は、端末の見本の会話で走る（R18・R19。画面は欠けない）。

**残るリスク（security-auditor、`docs/reports/2026-11-06-security-auditor-drive-audio-chat.md`）**: (1) 失敗の記憶（10 分）・single-flight・同時の枠はプロセスの中だけなので、Vercel の複数インスタンスでは効かない。外れ続ける鍵を再送されると、1 要求あたり最大 2 回 Claude を呼ぶ（上限は IP あたり 1 分 10 件と共有の 1 日の上限）。(2) Claude の呼び出し中に旅が削除されると、`trip_chats` に孤児の行が残りうる（中身は旅程から決まる短い文。次の旅の削除の機会には消えない。濫用ではないので許す）。(3) 保存の鍵は旅・日・データの版で決まるので、1 つの旅に 30 束に届くのはデータの版が何度も変わったときだけ（上限は保険）。

**残るリスク**: 1 日の上限は plan-trip・stop-deck・loss と丸ごと共有で、会話専用の下位の枠が無い。所有者が旅を作り直して会話の束を 30 まで作ると、その分だけ当日の他の生成の枠を使う（費用は上限で頭打ち。旅の作成自体が IP あたり 1 分 10 件・1 日の上限で抑えられている）。濫用が見えたら会話に全体の一部までの別の数え上げを置く。

## IDOR / Mass Assignment チェック

### POST /api/trips/:id/day/:n/chat

- **IDOR**: 対象はパスの `id` と `n`。ownerToken のハッシュが旅の行と合うときだけ作る・返す。無い旅・形の違う id は 404（トークンの確かめより前に旅を読む。旅が無いことは id を知らない人には区別できない値なので、stop-deck と同じ順）
- **クライアントから受け取るフィールド**: パスの `id`・`n`、ヘッダの `Authorization: Bearer <ownerToken>` だけ（body は読まない）
- **サーバー側で設定するフィールド**: 束の全部（行・きっかけ・話題・話し手・文）、保存の鍵、`createdAt`、`tripId`・`day`（パスから）、データの版
- **クライアントから受け取ってはいけないフィールド**: 文・行・鍵・版（body を読まないので受け取りようが無い）
- **検証方法**: n は 1 以上 999 以下の整数（zod）。トークンは 16 進 64 文字（形が違えば 403）。旅の行の ownerTokenHash と、受けたトークンの SHA-256 を比べる（stop-events の `isTripOwner`）。応答は `{ chat: { tripId, day, lines, data } }` を明示して組み立てる（鍵のハッシュを返さない）

## 横断的セキュリティチェック

- [x] CORS: 既存の `CORS_ORIGINS` をこの route にも当てる（allowHeaders の Authorization は stop-events で追加済み）
- [x] レートリミット: IP あたり 1 分 10 件（`rateLimit` の名前 `chats.prepare`）。Claude の 1 日の上限と同時の枠は plan-trip と共有
- [x] エラーメッセージ: error-mapper で code と短い文だけ。スタックトレースは返さない
- [x] ログマスキング: ownerToken・Claude の本文・材料・API キーを出さない
- [x] secrets: `ANTHROPIC_API_KEY` は既存の env。新しい秘密は無い
- [x] body の上限: body は読まない（1 KB の上限で 413）
- [x] ファイルアップロード: N/A（この feature はファイルを受けない）
- [x] 音: 外部の音声ファイルを読まない（すべて Web Audio の合成）。CSP の変更は要らない
