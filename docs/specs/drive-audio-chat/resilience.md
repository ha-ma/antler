# 障害耐性: drive-audio-chat（A-3 運転中の音・車内の会話）

運転（A-3）はデモの中心なので、**音と会話は運転を止めない**。Claude・api・Web Audio が失敗しても、運転・鹿の警告（alert-ui）はそのまま動く。会話は端末の見本の会話（R19）に落ち、音は鳴らないだけになる。

## トランザクション境界

### 操作: POST /api/trips/:id/day/:n/chat

1. 旅を読む（無ければ 404）→ ownerToken の確かめ（403）→ 日の範囲（404）→ DayPlan を作り直す（409）
2. 束の計画（純粋関数）→ 鍵で保存済みの行を読む。あれば返す（200。Claude を呼ばない、数えない）
3. 行が 0 の束（移動の無い日）は Claude を呼ばずに保存して返す。そうでなければ旅の保存済みの数を数え、30 なら 409 CHAT_LIMIT
4. 同時の枠を取る（無ければ 503）→ 呼び出しごとに当日の通し番号を進めて上限を確かめる（429）→ Claude（トランザクションの外）。外れたら 1 回だけ作り直す
5. 1 行の INSERT（`ON CONFLICT DO NOTHING`）。0 件なら保存済みの行を読んで返す

1 行の書き込みだけなので UnitOfWork のトランザクションは使わない。失敗したら何も残らない（pending の行を作らない。loss と同じ。推奨で決定）。

## 競合 / レース対策

### 同じ日の同時の 2 要求

同じプロセスの中では、usecase が鍵ごとに処理中の Promise を持ち、2 本目は 1 本目の結果を待つ（single-flight。Claude は 1 回）。1 本目が失敗すれば 2 本目も同じ失敗を受け、終われば Map から消す。別のプロセスでは両方が Claude を呼びうるが、5 の主キーで片方だけが保存され、もう片方は保存済みの束を返す（CONC-1）。

### 1 つの旅の上限（30）

数えてから保存するまでのあいだに別の鍵が来ると、31 件目がわずかに通りうる（費用の目安なので許す）。
