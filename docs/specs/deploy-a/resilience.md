# 障害耐性: deploy-a（Vercel・Turso・Vercel Blob）

方針: **関数は 1 回の失敗を覚えない**（起動の失敗は次の要求でやり直す）。**Turso が落ちてもレート制限で利用者を止めない**（DB を使う操作はどのみち失敗する。費用の上限は 1 日の上限とコンソールで守る）。**Capture の完成のしるしは Turso の行だけ**（画像だけ残っても完成品ではない）。

| 関数の起動                 | 同時の最初の要求                             | 組み立ての Promise を 1 つ共有                        | 組み立ては 1 回。全員が同じ結果を待つ                                                                                     | 変化なし                                           | なし                                                                                  |
| Turso                      | 届かない・トークンが切れた                   | libsql の例外                                         | レート制限はインスタンスのメモリで数える。DB を使う操作は 500。`/health/ready` は 503                                     | 旅の作成・記録が失敗の表示                         | logger.warn（`rate_limit.counter_unavailable`、1 分に 1 回まで）・既存の `http.error` |

## Concurrency / Idempotency

| 対象             | 並行実行されうるか             | 二重実行されうるか | 冪等性要件                                 | 実装方針                                                                                                                                                             |
| ---------------- | ------------------------------ | ------------------ | ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 関数の組み立て   | 最初の要求が同時に来る         | ありうる           | **必須**（組み立ては 1 回）                | Promise を 1 つ持つ。失敗したら捨てて、次の要求でやり直す                                                                                                            |
| レート制限の数え | 複数のインスタンス・同時の要求 | ありうる           | 不要（数えるのが仕事。1 文で原子的に足す） | `INSERT … ON CONFLICT DO UPDATE SET count = count + 1 RETURNING count`（1 文で読み書き）                                                                             |
| 窓の掃除         | 複数のインスタンスが同時に     | ありうる           | 不要（消すのは過ぎた行だけ。何度でも同じ） | `DELETE … WHERE expires_at <= ?`。インスタンスごとに 1 分に 1 回まで                                                                                                 |
| Capture の保存   | 同じ id の同時の要求           | 再送               | **必須**（同じ本文で同じ結果）             | 行を `pending` で先に取る（`ON CONFLICT(key) DO UPDATE … WHERE 古い pending`）。取った 1 つだけが画像を置いて `done`。画像の名前は中身のハッシュ（上書きしても同じ） |
| マイグレーション | 運用者が 2 回流す              | ありうる           | **必須**                                   | `CREATE TABLE IF NOT EXISTS`。版は `max(今の版, 新しい版)`                                                                                                           |

## トランザクション境界

- レート制限: 1 文（`INSERT … ON CONFLICT DO UPDATE … RETURNING`）。トランザクションを張らない
- Capture: Blob（外部）と Turso（行）はまたいで原子にできない。**行を `pending` で取る → 外部の副作用（画像）→ 完成のしるし（`done`）**の順（plan-trip の `trip_requests` と同じ形）。行を取れなければ画像を置かない。`done` でなければ完成品ではない（画像は中身のハッシュの名前なので、引き継いだ再送で同じものになる）
- マイグレーション: `client.batch(STATEMENTS, 'write')`（1 つのバッチ。途中で失敗したら全部戻る）
