# 脅威: edge-capture（検知フレームの保存・走行後の同意・アップロード）

この feature には HTTP の入口が 2 つある: **api の `POST /api/captures`**（インターネット側。認証なし。付録 A #9）と、**edge の Capture サーバー**（車内の Wi-Fi AP の中だけ。B3-1）。
守るものは 4 つ: **(1) 同意の無い画像を api に入れない**、**(2) 画像・Capture に個人情報・精密な位置・メタデータを入れない**、**(3) すでにある Capture を上書き・読み出し・消せない**、**(4) 車内ネットワークの端末や別サイトのページに、車の画像と同意の状態を触らせない**。
認可（ログイン・ロール）は無いので、行は「誰が」ではなく「何をしようとするか」を中心にし、拒否は検査の規則として書く。

**✅ (公開) の理由**: 付録 A #9「A が登録なしで最後まで」。送るのは同意した利用者の匿名の画像と区間だけ。悪用（容量・偽データ）はレート制限・件数の上限・厳しい検証・読み出し口を作らないことで抑える。偽の画像を送られうること自体は防げない（学習側で検証する。Deferred）。

edge の Capture サーバーは車内の AP の内側だけに開く。AP のパスワード（B3-1）が境界。同じ AP の他の端末は一覧を読めるが、書けるのは許可リストのオリジンか、ブラウザ以外のクライアントだけ。

## IDOR / Mass Assignment チェック

### POST /api/captures

- **クライアントから受け取るフィールド**: multipart の `capture`（Capture の JSON。CaptureSchema の欄だけ）と `image`（画像ファイル）
- **サーバー側で決めるフィールド**: 保存する論理の `image` のパス（`captures/{id}.jpg|png`）と実ファイル名（`{key}-{sha 先頭12桁}.{ext}`）、`consent`（true であることを確かめたうえで保存）、`receivedAt`、`bodyHash`、画像の sha256
- **クライアントから受け取ってはいけないフィールド**: 保存先のパス、`receivedAt`、`bodyHash`、個人情報のキー（氏名・メール・電話・端末識別子・緯度経度）
- **検証方法**: `CaptureSchema` は `strictObject`（知らない欄は 400）。`roadSegment` は英数字とハイフンだけ（座標を書けない）。`image` の文字列は形だけ検査し、保存には使わない。画像は先頭のバイト・寸法・メタデータの有無を `inspectCaptureImage` で確かめる
- **IDOR**: `id` で資源を指す読み出し・変更の API を作らない。再送（同じ `id`）は同じ本文のときだけ成功し、違えば 409

### POST /captures/consent・/captures/uploaded（edge）

- **クライアントから受け取るフィールド**: `consent`（真偽）、`ids`（`cap_` + 16 進 12 桁、1〜200 件）
- **サーバー側で決めるフィールド**: 変更される欄は JSON の `consent` と送信済みのしるしだけ。ほかの欄（画像・boxes・roadSegment・l1Probs）は書き換えられない
- **検証方法**: JSON のみ、8 KB まで、型・長さ・正規表現。存在しない id は数えない（存在の有無を教えない: `updated` の件数だけ返す）

## 横断的セキュリティチェック

- [x] CORS: api は既存の `CORS_ORIGINS`（明示。`*` は起動で拒否）。edge は許可リストが空なら CORS ヘッダを一切付けない
- [x] レートリミット: api は `POST /api/captures` に IP あたり 1 分 60 件。edge は本文 8 KB・同時 8 接続・5 秒の打ち切り
- [x] エラーメッセージ: 例外は error-mapper で code と短い文だけ。edge の応答にパス・例外文を出さない
- [x] ログマスキング: 上のとおり
- [x] 画像: 先頭のバイトで判別し、ファイル名・Content-Type を信用しない。メタデータを持つ画像を保存しない。寸法を Capture と照合する
- [x] パス: `id` を検査してからパスにする（edge は `cap_[0-9a-f]{12}`、api は `cap_[A-Za-z0-9]+`）。クライアントが送った `image` のパスを使わない
- [x] 書き込み: 一時ファイル → ハードリンクまたは `os.replace`（途中の状態を見せない・既存を上書きしない）。ディレクトリ 0700、ファイル 0600
- [x] secrets: この feature に秘密は無い（API キーなし）
- [x] 開発バイパス: 同意の検査を外す環境変数・フラグを作らない
