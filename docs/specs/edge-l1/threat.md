# 脅威: edge-l1（L1 への問い合わせと fusion）

L1 の接続先は Mac mini 上の local-jev（`http://127.0.0.1:8766`）。detector は**クライアント**で、新しい待ち受けを開かない。
WebSocket（`/alerts`）の認可は edge-judge のまま。ここで増えるのは「どこへ何を送るか」と「誰の答えで赤が下がるか」。

## IDOR / Mass Assignment チェック

### L1 の答え（local-jev → detector）

- [ ] 読むのは 4 問の答え（choice の確率 3 つ・noul 3 つ）と応答の `model` だけ。余分な項目は捨てる（SDK が `extra="ignore"`）（MASS-1）
- [ ] 確率は有限の 0〜1 で、選択肢が揃っていなければ答え全体を捨てる（`bad_response`）。壊れた答えで降格しない
- N/A: IDOR — 資源を ID で指す操作が無い（問い合わせは毎回独立）

### 問い合わせ（detector → local-jev）

- [ ] 送るのは `JudgeRequest` の state（track の数値・固定の車の状態）と固定の 4 問だけ。画像・位置・端末識別子を送らない（pydantic の `extra="forbid"` で拒否）
- [ ] API キーは環境変数か `local`。ログに出さない

| データ                                              | 分類                                    | 保存場所                               | 配信方法                                       | 削除タイミング                                   |

## 横断的セキュリティチェック

- [x] CORS: N/A（detector は HTTP のクライアント。待ち受けを足さない）
- [ ] 接続先: ループバックだけ。環境変数に車外の URL があっても送らない（RUN-1i）
- [ ] レートリミット: 問い合わせは同時 1 つ・2〜3 Hz・失敗が続けば 2 秒まで間隔を延ばす（local-jev と YOLO を詰まらせない）
- [ ] エラーメッセージ: 例外の型名と理由だけをログに出す。応答の本文・URL のパス・キーを出さない（LOG-1a）
- [ ] ログマスキング: SDK のロガーは warning 以上だけ（SDK は debug で本文を出す）
