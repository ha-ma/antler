# 脅威: edge-judge（鹿の判定とフラグ配信）

edge の WebSocket サーバー（`ws://ezoroad.local:8765/alerts`）を叩けるのは、WPA2 の AP に入った端末だけ（ch6「セキュリティ」。AP と QR は別 feature）。
ログインやロールは無い。認可マトリクスは「誰がどの操作をできるか」を、サーバーの側から書く。

## Authorization Matrix

| 操作                                         | クライアント（AP に入った端末。PWA も別の端末も区別しない） | AP の外の端末                                  | edge の判定（内部）               |
| -------------------------------------------- | ----------------------------------------------------------- | ---------------------------------------------- | --------------------------------- |
| `/alerts` に接続して AlertFlag を受け取る    | ✅ 流れる情報は個人を含まない                               | N/A: AP に入れない（WPA2 は別 feature で検証） | N/A: 配信する側                   |
| `/alerts` 以外のパスに接続する               | ❌ 404                                                      | N/A: AP に入れない                             | N/A: 配信する側                   |
| 接続数の上限（16）を超えて接続する           | ❌ 503（既存の接続に影響しない）                            | N/A: AP に入れない                             | N/A: 配信する側                   |
| ack・label を送る                            | ✅ 形が合うものだけ受ける                                   | N/A: AP に入れない                             | N/A: 受ける側                     |
| AlertFlag の形をサーバーへ送る（なりすまし） | ❌ 無視。判定に影響しない                                   | N/A: AP に入れない                             | N/A: 判定は自分の入力だけで決める |
| 64 KB を超えるメッセージを送る               | ❌ その接続だけ切る                                         | N/A: AP に入れない                             | N/A: 受ける側                     |
| 閾値・距離表・ホストを変える                 | ❌ ネットワークからは変えられない                           | N/A: AP に入れない                             | ✅ 起動時の設定ファイルだけ       |
| 走行ログ（ack・flag.sent）を読む             | ❌ ネットワークからは読めない                               | N/A: AP に入れない                             | ✅ 自分のログに書く               |

## IDOR / Mass Assignment チェック

### ack・label（クライアント → サーバー）

- [ ] 余分なフィールドがあっても、必要な項目（`type`・`t_shown`・`value`）だけ読んで残りは捨てる。落ちない（MASS-1）
- [ ] 本文をそのままログや判定に流さない。ログに出すのは `t_shown` の値と型名だけ
- N/A: IDOR — ID でほかの資源を指す操作が無い（接続は全員同じ配信を受ける）

### AlertFlag（サーバー → クライアント）

- [ ] 項目は `@antler/schema` の AlertFlag だけ。画像・位置情報・端末識別子を持たない（`frameJpegB64` は常に null）
- N/A: IDOR — 配信先ごとの出し分けが無い

## Data Classification

| データ                               | 分類                             | 保存場所                                     | 配信方法                                     | 削除タイミング                                   |
| ------------------------------------ | -------------------------------- | -------------------------------------------- | -------------------------------------------- | ------------------------------------------------ |
| AlertFlag（deer・距離・方向・時刻）  | 内部（個人を特定しない）         | 保存しない（走行ログに t_frame/t_sent だけ） | LAN 内の WebSocket                           | 配信後に破棄                                     |
| 走行ログ（flag.sent・ack・client.*） | 内部（個人を特定しない）         | Mac Mini のローカルのログ                    | 外へ出さない（外部の解析サービスは使わない） | Deferred（ログのローテーションは起動の feature） |
| ack の t_shown                       | 内部                             | 走行ログ                                     | LAN 内の WebSocket（受信）                   | 走行ログと同じ                                   |
| クライアントのアドレス               | 内部（端末の識別につながる）     | ログに出さない（接続数だけ）                 | N/A: 配信しない                              | N/A: 保存しない                                  |
| カメラの画像                         | 機微（車外の映像。人が写りうる） | メモリ上だけ。保存しない・送らない           | N/A: 配信しない（B3-3 の JPEG は Deferred）  | フレームごとに破棄                               |

## 横断的セキュリティチェック

- [x] CORS: N/A（HTTP の API を持たない。WebSocket の Origin は見ない。LAN 内の信頼の境界は AP の WPA2）
- [ ] レートリミット: 接続数 16・メッセージ 64 KB・ping・1 接続 1 秒 5 通で上限を置く（ack の連打でログと計測を汚されない）
- [ ] エラーメッセージ: クライアントに内部の情報（パス・スタック）を返さない。404/503 は本文なし
- [ ] ログマスキング: クライアントの本文・アドレス・画素をログに出さない
