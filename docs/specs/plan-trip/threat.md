# 脅威: plan-trip（A-1 旅をつくる・Claude がしおりを仕上げる）

この feature の HTTP の操作は `POST /api/trips` の 1 つ。登録なし（付録 A #9）なので、誰でも旅を作れる。
守るものは「Claude の費用（濫用）」「保存する欄（Mass Assignment）」「旅の所有者の印（後の削除の権利）」の 3 つ。読み出し・削除の API は record / brief-map の feature で、そこで所有者トークンを照合する。

**✅ (公開) の理由**: 付録 A #9「A が登録なしで最後まで」。旅は個人を特定する情報を持たない（人数・日程・選択肢だけ）。費用の濫用は R9 のレート制限と 1 日の上限で抑える。

冪等キーは「同じ body と同じキー」でだけ結果を返す。キーが同じで body が違う → 409 `IDEMPOTENCY_MISMATCH`（別の人の旅を取れない）。

## IDOR / Mass Assignment チェック

### POST /api/trips

- **クライアントから受け取るフィールド**: lang、party（size・drivers・experience）、depart（at・place）、return（at・place）、budgetPerPersonJPY、area、pleasures（id・weight）、ヘッダ Idempotency-Key
- **サーバー側で設定するフィールド**: id、seed、title、days、riskScore、alertEnabled（true）、details（titles・dayNotes・skipped・createdAt）、ownerToken とそのハッシュ
- **クライアントから受け取ってはいけないフィールド**: id、seed、title、days、riskScore、alertEnabled、ownerToken、details の各欄
- **検証方法**: `infrastructure/http/schemas/` の zod の strictObject で許可する欄だけを受け、知らない欄は 400。楽しみの id はエリアのマスターにあるものだけ（R2）。days と riskScore は api が `packages/trip` で計算し直す

## 横断的セキュリティチェック

- [x] CORS: 許可オリジンを `CORS_ORIGINS` で明示（既存。`*` は起動で拒否）
- [x] レートリミット: `POST /api/trips` に IP あたり 1 分 10 件（IPv6 は /64 で 1 枠）、全体の 1 日の Claude の呼び出しの上限（失敗も数える）、同時呼び出しの上限
- [x] エラーメッセージ: 例外は error-mapper で code と短い文だけにする。Claude の応答・スタックトレースは返さない
- [x] ログマスキング: ownerToken・冪等キー・API キー・Claude の本文を出さない
- [x] secrets: `ANTHROPIC_API_KEY` は env（`z.string().min(1)`、既定値なし）
- [x] 開発バイパス: Claude のフェイクはテストの差し込みだけ。本番の DI では使わない（環境変数で切り替えない）
- [x] ファイルアップロード: N/A（この feature はファイルを受けない）
