# 仕様: sticky-cta（次へ進むボタンを、最初の画面で分かり、スクロールしても見える場所に置く）

> 2026-11-08 main の rebrand-shikashi（#65、`docs/specs/rebrand-shikashi/functional.md`）を取り込んだ。同じ `apps/sim/src/shared/components/` に `BrandLogo` が入り、各画面のヘッダーが SHIKASHI SIMULATOR とロゴになった。帯（`ActionBar`）と主ボタンの決まりは変えていない。

## 概要

ユーザーの依頼（2026-11-08）:「次のページに移動したり、モードに入るといったアクションボタンのあるセクションは、スクロールしても位置が固定化されていたり、かなり目立つような形にしてファーストビューで『次はここを押す』ということがはっきりわかるようにしたい」。

各画面の「次へ進む」主ボタンを、画面の下に固定した帯（アクションバー）に載せる。帯は 390×844（スマホ縦）・844×390（スマホ横）・1280×800（PC）のどれでも最初の画面に見え、スクロールしても同じ場所に残る。主ボタンは画面でいちばん目立つ要素にする（`spruce` の面・`on-spruce` の文字・`spruce-deep` の押し込み影）。

要件: ch8 規約 1（トークンの色だけ）・6（タッチターゲット 44px 以上）、ch5 アクセシビリティ（4.5:1、キーボード、動きを減らす設定）、`docs/design/README.md` の原則（`alert-*` は 3 状態の専用。主ボタンは `spruce`）、ch6「A 対応環境」（844×390 以上・PC 1280 以上。縦は読める）。
画面: UI キャンバス v2 の A1_Plan・A2_Brief・A6_Loss・A7_Record。

**Tier 1 の理由**: 画面の配置と見た目だけが変わる。ボタンの行き先・押したときの振る舞い・ルーティングは変えない。認可・永続化・外部副作用・並行性に触れない。

**範囲外**: ボタンの文言（plan-trip・result-screens・loss・record の仕様が決めたもの。この feature では新しい文言を足すだけ）、3D の運転画面の HUD と AlertState の振る舞い（AlertState.md の契約）、ブランド名（rebrand のセッション）、結果の数字の動き（result-countup のセッション）、写真の描画（motion-photos のセッション）。

## Example Map

Story: 台湾から初めて北海道をレンタカーで旅する 4 人の代表として、スマホで A-1 を開いたら、どこまでスクロールしても「しおりを作って鹿ゾーンを確かめる」が画面の下に見えていて、入力が足りなければ何を直せばいいかがその横に出ている。A-2・A-6・A-7 でも、次に押すボタンが最初の画面の下にある。

Questions は 2026-11-08 にすべて推奨で決定した（ユーザーの方針「推奨案のある判断は推奨案で決めて進める」、2026-11-03）。

- R1 アクションバー（共通の部品 `shared/components/ActionBar.tsx`・`action-bar.css`）
  - 画面の下に固定する（`position: fixed; bottom: 0`、左右いっぱい）。どの幅でも同じ形（推奨で決定。広い画面で列の中に sticky にする案は、A-6・A-7 の列が `align-items: flex-start` で短く、スマホでは右の列が下に回るので効かない）
  - 下の余白は `env(safe-area-inset-bottom)` を足す。`viewport-fit=cover` は今までどおり使わない（mobile-landscape R1。いまは 0 になるが、将来 cover にしても切れない）
  - 面は `surface`、上に 1px の `line`。新しい色を使わない。`alert-safe / alert-zone / alert-danger` を使わない
  - 中身は最大幅 1360px（各画面の本文と同じ）の中で右に寄せる。主ボタンの幅は 420px まで。左に補足（R3 の直すところ・作成の失敗）
  - 幅 640px 以下は補足を上、主ボタンを横いっぱいにする。高さ 560px 以下（スマホ横）は上下の余白と主ボタンを低くする（主ボタン 48px）
  - 幅 640px 以下は主ボタンの横の余白を space-3 に詰める（390px で A-6 の文言が 1 行に収まる）。2 行に折れるときは文節で折り行の長さをそろえ（`word-break: auto-phrase`・`text-wrap: balance`）、帯の高さの予約は 2 行の分を足した 112px（2026-11-08、rebrand の取り込みのあとのスクリーンショットで「…やり直 / す」の折れを見つけた）
  - ボタンは 1 つだけ（今のボタンを帯に移す。同じボタンを 2 つ描かない）。DOM の位置は今の場所のまま（Tab と読み上げの順は変わらない）
  - 帯は本文を隠さない: 各画面の本文の下の余白に帯の高さ（`--action-bar-reserve`）を足す。補足が出る A-1 の狭い画面では、補足の分も足す
  - 帯は落ちるカード（A-6 の `.loss-drop`）より上に描く（z-index 50）
  - Tab で進んだ先が帯の下に隠れない（WCAG 2.4.11）: 帯がある画面だけ `scroll-padding-bottom` に帯の高さを入れる（`:root:has(.action-bar)`）
- R2 主ボタンの見た目（いちばん目立つ要素）
  - `spruce` の面、`on-spruce` の文字、`heading`（16px・700）、高さ 56px（R1 の低い画面は 48px）、`radius-l`、影 `0 6px 0 var(--spruce-deep)`（押し込み影。night のテーマでも spruce-deep に合う）
  - 色は画面ごとに変えられる（2026-11-08 追加。lead 経由のユーザーの指示で A-6 の主ボタンを `alert-danger` の赤にするため）: 主ボタンの面・文字・影・ホバー・押下・処理中・アイコンの線は `var(--accent, var(--spruce))`・`var(--on-accent, var(--on-spruce))`・`var(--accent-deep, var(--spruce-deep))` を読む。帯の CSS は `--accent` 系を定義しない（既定は spruce 系のまま、見た目は変わらない）。A-6 の root の値は result-countup（`loss.css`）が置く。R1 の「`alert-*` を使わない」は帯の CSS の決まりで、画面が `--accent` に置く色はその画面の仕様が決める
  - ホバーは `spruce-deep`、押すと 2px 沈む、フォーカスは `ink` の 3px の輪
  - 処理中（A-1 の送信中、`aria-disabled`）は `spruce-deep` の面と `cursor: progress`
  - night のテーマ（A-6）では spruce-deep の上の on-spruce が 3.07:1 で 4.5:1 に届かないので、ホバー・処理中も面は spruce のまま下線で示す（自己レビューで見つけた。今までの A-6 の主ボタンのホバーも同じ組み合わせだった）
  - 注意を引く動き: 画面を開いて 0.6 秒後に、主ボタンが 3px 浮いて戻るのを 2 回（1 回 1.4 秒）。最後の形は止まった形。`prefers-reduced-motion: reduce` では動かさない（`animation: none`）。点滅しない
  - 文字のコントラスト: on-spruce / spruce は trip・night とも 4.5:1 以上（tokens.json）
- R3 A-1 の直すところ（入力が通らないあいだ）
  - 主ボタンは押せるまま（押すと今までどおり送らない。React Hook Form が最初の欄にフォーカスを移す）。帯の左に「直すところ: 人数・返却」のように、問題のある欄の名前（入力欄のラベルと同じ語）を並べて出す。色は `clay-deep`（入力欄の誤りと同じ。surface の上で 4.5:1）
  - 主ボタンは `aria-describedby` でその文を指す。新しいライブリージョンは作らない（入力欄の下の `role="status"` が今までどおり読む。二重に読ませない）
  - 文言は 4 言語（ja「直すところ: {fields}」、en「Fix: {fields}」、zh「需修正：{fields}」、ko「수정할 항목: {fields}」）。欄の名前の区切りは ja・zh「・」/「、」、en・ko「, 」
  - 作成の失敗（429・つながらない・それ以外。`CreateTripStatus`、「もう一度」のボタンつき）は帯の中、主ボタンの左（狭い画面は上）に出す（押した場所の近くで分かる）。`role="alert"` の箱はいつも描いておく（今までどおり）
- R4 A-2 の主ボタン
  - 運転のある日:「エンジンをかける」を帯に載せる（行き先は今までどおり `driveHref`）
  - 運転の無い日:「この日は運転しません」のカードは今の場所のまま、「次の日（DAY n）へ」だけを帯に載せる。最後の日（次の日が無い）は帯を出さない
- R5 A-6・A-7 の主ボタン
  - A-6: 主ボタン（R9 の文言）を帯に載せる。主ボタンは `.loss-drop` の外に置く（`.loss-drop` の transform の中では fixed が画面に付かない）。副の導線の `nav`（`.loss-actions`）は今までどおり落ちる順の位置でフェードで現れる（result-screens R2 の DROP-2 の並びは変わらない）。主ボタンは最初から見える（推奨で決定。ユーザーの依頼「ファーストビューで分かる」を優先）
  - A-7:「別の旅をつくる」を帯に載せる。「アラート OFF で挑戦」は今の `nav` に残す。ヘッダの「リンクをコピー」は今のまま（小さい 44px のボタン。帯の主ボタンは大きさと影で上回る）
- R6 運転の画面（`/drive`）は変えない
  - 出発の案内・終了の帯は画面の真ん中に高さを収めて出し、高さ 560px 以下では「出発」「もう一度」の行が案内の下に留まる（mobile-landscape ML-1c）。1280×800・844×390 の両方で、スクロールしなくても「出発」が見えることをスクリーンショットで確かめた（下の手動テストマトリクス）
  - 指で操る端末の縦（390×844）は「横にしてください」の案内が全面に出る（mobile-landscape R2）。マウスの 390×844 も確かめた
  - `drive/` を直すと 6 つの仕様（drive-3d・drive-crash-spot・drive-link・drive-tune・mobile-landscape・drive-tourism）の対象に触れるので、必要が無いかぎり触らない

## ユースケース

### UC-1: A-1 で主ボタンが帯にある

- **Given**: A-1 をペルソナの入力で開いた
- **When**: 画面が出る
- **Then**: 「しおりを作って鹿ゾーンを確かめる →」のボタンが 1 つだけあり、アクションバーの中にある。直すところの文は無い

### UC-2: A-1 で入力が通らない

- **Given**: A-1 で運転できる人を人数より多くした
- **When**: 画面が描き直される
- **Then**: 帯に「直すところ: 運転できる人」が出て、主ボタンの `aria-describedby` がその文を指す。直すと消える

### UC-3: A-2 で主ボタンが帯にある

- **Given**: 運転のある日の A-2 / 運転の無い日の A-2（次の日がある）/ 運転の無い最後の日
- **When**: 画面が出る
- **Then**: 「エンジンをかける」/「次の日（DAY n）へ」が帯の中に 1 つだけ / 帯が無い

### UC-4: A-6・A-7 で主ボタンが帯にある

- **Given**: A-6 を衝突の情報で開いた / A-7 を記録で開いた
- **When**: 画面が出る
- **Then**: 主ボタンが帯の中に 1 つだけで、`.loss-drop` の中に無い。副の導線は帯の外に今までどおりある

## 状態パターン

### S-1: 動きを減らす設定

- **Given**: `prefers-reduced-motion: reduce` → **Then**: 主ボタンの注意の動きが `animation: none`。動きの最後の形は止まった形（global.css が時間を縮めたときも止まった形で終わる）

### S-2: 送信中

- **Given**: A-1 で送信中 → **Then**: 主ボタンは帯の中で「しおりを仕上げています…」、`aria-disabled` と `aria-busy`（今までどおり）
