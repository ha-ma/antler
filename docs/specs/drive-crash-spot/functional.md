## Example Map

Story: 北海道を走る旅行者として、鹿ゾーンの手前を長く走らされず、揺れない車内のスマホを見ながら、自分の目で鹿を先に見つけ、ぶつかったときにはその重さを感じたい。

- R1: ステージは鹿ゾーンの入口の **1 km 手前**から（指摘 1。drive-tune R1 の 5 km を置き換え）
  - 1 回の走りは「1 km ＋ ゾーン（最大 8 km。drive-deer R2）」。実測: 置き換え前は見本の場面で 0 → 12.9 km（入口 4.86 km）、旅の 2 日目で 5 km ＋ 2.5 km と 5 km ＋ 8 km
  - 出発のとき、HUD の「鹿ゾーンまで」は 1.0 km（入口がルートの始点から 1 km 以内なら、その距離）。見本の場面・旅の場面とも
  - ステージの始まりがルートの始点より前になるときは始点から（今までどおり）。前の出口から次の 1 km 手前までが 0 以下ならまとめる（今までどおり）
  - ゾーンを出たらクリア、次のステージへ移る、最後でその日をクリア（今までどおり）
- R2: 車内のスマホは画面に固定する（指摘 2）
  - スマホ（`AlertState` compact。B の PWA と同じもの）は 3D の中に貼らず、HUD と同じ DOM の層に、画面の決まった位置（下の中央より左、ナビの上に当たる所）に置く。視線（カーソル・ジャイロ・ドラッグ）でも、車の揺れでも動かない
  - 理由: drei の `Html transform` は、世界の座標（ルートの始点から数十 km）を CSS の 3D 行列に載せる。合成の段で単精度に丸められて数 px 揺れ、3D のスマホの板からずれて浮いて見える。3D の本体と画面の DOM の重なり順も 3D の遮蔽に従わない
  - 3D の車内からスマホの本体と画面の板を外す（固定した DOM と、視線で動く 3D の本体がずれるため）。マウント（台座）は残してよい
  - スマホは枠（スマホの外形。radius-xl・line）で囲み、物として見えるようにする。アラート OFF では出さない（今までどおり）
  - 重なり: 3D の上、HUD の帯・赤の縁（DangerOverlay）・終わりの帯・衝突の演出の下。ポインタを奪わない（`pointer-events: none`）。音は今までどおり `AlertState` がコントローラへ渡す
  - 横画面（mobile-landscape）で指の操作（左右の円）・下の帯・右の列と重ならない
- R3: 衝突の演出（指摘 3）
  - 鹿に当たったフレームで、エンジンは今までどおり `collided` の合図を `onCue` に出し、同じ `frame()` の中で HUD の `outcome` が `collided` になる（音を鳴らす側はこの合図で衝撃音を鳴らす。演出の始まりと合図が同じフレーム）
  - 走行の結果は今までどおり当たったフレームで `onFinish(result)` に 1 回だけ渡す（run の保存はそのフレームで始まる。演出の途中で離れても run は残る）。遅らせるのは A-6 への移動だけ: 約 3.5 秒の演出が終わったら `onCrashEnd(result)` を 1 回だけ呼び、app 層（DriveRoute）がそこで A-6 に移る
  - 演出の計りは実時間。一時停止・タブを隠しても止めない（衝突のあとはシミュレーションが進まないので、結果は変わらない）
  - 当たったときに、スクリーンリーダーに「鹿と衝突しました」を伝える（role="alert"、4 言語）
  - 演出: 0〜0.8 秒 カメラが揺れる（強く始まって弱まる。実時間）・0〜0.3 秒 白く光る（`ink`。赤 alert-danger は鹿検知専用なので使わない）→ 0.3〜3.2 秒 画面の周りから暗くなる（ビネットが内側へ閉じ、最後は全面が `ground`）・1.0〜3.2 秒 ぼやける → 3.5 秒で終わり
  - `prefers-reduced-motion: reduce` では揺れ・光・ぼかしを出さず、暗くなるだけ（同じ 3.5 秒）
  - 演出の間は終わりの帯（EndBanner）を出さない。演出が終わってから出す（見本の場面は A-6 に移らないので帯が出る）
  - 演出の間に画面を離れたら（アンマウント）、`onCrashEnd` を呼ばない（離れた先から A-6 に飛ばない）。「同じシードでもう一度」で戻したときも呼ばない
  - 完走（`completed`）は今までどおりすぐ `onFinish`（`onCrashEnd` は呼ばない）
- R4: 鹿の発見（指摘 4・A5-5）
  - 3D の鹿をクリック / タップすると「発見」。当たりの判定はカメラからのレイと鹿の当たりの球（体の中心。目の反射だけの鹿は目の位置）。球の半径は 1.2 m か、遠いほど大きく（距離 × 0.02）
  - **見えている鹿だけが当たる**（spec-adversary C2）: 車から 150 m 以内で、林に隠れていない（`occluded` でない）鹿。目の反射だけの鹿は、目が光っている間（昼でなく、反射の強さ 0.02 超）だけ。見えない鹿はレイの上にあっても無いものとして、その後ろの見える鹿に当たる。もう発見した鹿も同じく素通りする（群れを順に見つけられる）
  - 数えないもの: 外れたクリック、ドラッグ（押してから 8 px を超えて動いた。指ごとに測る。スマホの視線のドラッグ）、同じ鹿の 2 回目以降、一時停止の間、衝突・完走のあと、もう消えた鹿、見えていない鹿。判定はエンジン（domain）が持ち、画面は鹿の id を渡すだけ
  - 「出た数」は、その走りで**一度でも見えた**鹿の頭数（0.1 秒ごとに上の「見えている」で数える。目の反射だけの鹿も含む。spec-adversary M2）。見えないままステージのクリアで消えた鹿・林の中だけの鹿は入らない
  - 「事前に発見」（推奨で決定）: 発見したとき、鹿が車より前にいて、車から **60 m 以上**離れていた。60 m は圧雪で 60 km/h から止まれる距離（反応 0.75 秒 12.5 m ＋ 制動 約 40 m）より遠い所。アラートの赤（120 m の検知）を見てから押しても 60 m より遠ければ事前に入るので、アラート ON と OFF の比べには使わない（spec-adversary M1。A-7 にも比べる文は書かない）
  - 発見の記録は World の中に持つ。「同じシードでもう一度」で 0 に戻る（spec-adversary M3）
  - 発見したことは、左の HUD に「鹿を発見 n / m 頭」の小さな 1 行で分かる（輪・音は出さない。読み上げの割り込みもしない）。まだ見えた鹿が無ければ出さない
  - 走行の結果（`DriveResult.spotting`）に `{ appeared, found, early }` を残す
  - A-6（喪失）: 衝突の URL に `spot=found.early.appeared` を足し、画面に 1 行「自分で見つけた鹿 n / m 頭（60 m より前で k 頭）」を出す（喪失文の api には送らない）。`spot` はほかの欄と別に読む: 形（0〜999 の 10 進の整数 3 つを `.` でつなぐ。先頭の 0 は不可）か範囲（early ≤ found ≤ appeared）が違えば行を出さない（ほかの欄は読む）。`spot` が 2 回あるときは今までの決まりどおり URL ごと読まない。見えた鹿が 0 なら行を出さない
  - A-7（記録）: run に省略できる `spotting`（`.optional()`）を足す。記録の集計の `totals.spotting` も省略できる欄で、その日の結果にした run（日ごとに 1 つ）が**すべて** `spotting` を持つときだけ合計を入れる（欄の無い古い run が混ざれば出さない。一部の合計を全体に見せない。spec-adversary M4）。OFF の挑戦の run の発見は A-7 に出ない（集計の決まりどおり）。画面に 1 行出す。古い run（欄なし）はそのまま読める
  - 配る順番: api と sim は同じリポジトリから同時に出す。api の検証（`DriveRunInputSchema`）と sim の読み（`TripRecordSchema`）は同じ `packages/trip` を使うので、欄はどちらも省略できる形にする。古い sim → 新しい api と、古い記録の読み込みは通る。新しい sim → 古い api は strict のため 400 になるので、api を先に（または同時に）出す（code-reviewer W1）
  - 4 言語の文言は表に置く（i18n 規則 5）
  - 乱数は使わない（同じ入力の列・同じクリックなら同じ結果）
- R5: 至近の飛び出しの検知と、目の反射だけの鹿（親セッションの取りこぼしの調査、2026-11-06。推奨で決定）
  - 調査: 晴れ・薄暮・60 km/h で、ほかの 10 種の動きは 100% 赤（中央値 6.8 秒前）。`dart`（林の陰から至近の飛び出し）は赤が 91%、出ても衝突まで 1 秒未満が約半数。林から車線まで約 1 秒に、遅延 150〜400 ms と遠い帯の見逃しが重なるため
  - `dart` と `graze-dash`（至近の飛び出し。drive-deer の `NEAR_MOTIONS`）に限って、検知の遅延を **80〜150 ms** にし、捉えるかの最初の抽選を**いちばん近い帯（30 m 未満）**の確率で引く。ほかの動きの見逃し・遅延（150〜400 ms、帯ごとの引き直し）は変えない。**ch3 A5-3 の「150〜400 ms」と違う**（B の L0 経路の 1 フレームの推論＋判定に寄せた）
  - 目の反射だけの鹿（`eyeshine`）は林の中（occluded）にいるので、スマホでは検知しない（赤にしない。B の車載カメラにも体が写らないため）。運転者が自分の目で見つける鹿として、R4 の「鹿の発見」の対象にする（目が光っている間）。林から出た鹿（ほかの動き）は今までどおり検知の対象
  - 入れないもの: 進路の予測による事前の赤、1 フレームの予備の琥珀 → 赤（3 状態の定義と B の現実からずれる）

推奨で決定（CLAUDE.md の方針。PR にも書く）: R1 の 1 km、R2 の画面に固定（3D から外す）、R3 の時間配分と色・保存はそのフレームで移動だけ遅らせる、R4 の当たりの球・見えている鹿だけ・ドラッグ 8 px・事前 = 60 m・分母は見えた頭数・表示は件数の 1 行・A-7 の集計の仕方。

spec-adversary の指摘（2026-11-06。`docs/reports/2026-11-06-spec-adversary-drive-crash-spot.md`）: C1（保存は当たったフレーム、移動だけ遅らせる）・C2（見えている鹿だけ）・M1（60 m の根拠を止まれる距離にし、ON / OFF の比べに使わない）・M2（分母は見えた頭数）・M3（World に持ち、やり直しで 0）・M4（省略できる欄・混ざれば出さない）・m1（`spot` は別に読む・role="alert"・指ごとの 8 px・onCrashEnd は 1 回）は上の各ルールに取り込んだ。キーボードだけの人が鹿を指せない件は、A-6・A-7 の行を見えた鹿があるときだけ出すことにとどめる（指す操作の代わりは A3-3 の範囲外）。

## ユースケース

### UC-1: 1 km 手前から（R1）

- **Given**: その日のルートとゾーンの区間（見本・旅）
- **When**: 運転の場面を作る
- **Then**: 最初のステージは最初の入口の 1 km 手前から始まり、HUD の「鹿ゾーンまで」は 1.0 km

### UC-2: スマホの固定（R2）

- **Given**: アラート ON の運転
- **When**: 走る・視線を動かす
- **Then**: スマホは HUD の層の決まった位置に出て、3D の中には無い

### UC-3: 衝突の演出（R3）

- **Given**: 鹿に当たる運転
- **When**: 当たったフレーム
- **Then**: 同じフレームで `collided` の合図と `onFinish`、演出が始まり、約 3.5 秒後に 1 回だけ `onCrashEnd`

### UC-4: 鹿の発見（R4）

- **Given**: 鹿が出ている運転
- **When**: 鹿をクリック / タップする
- **Then**: 1 頭 1 回だけ発見に数え、60 m より前なら事前、結果・A-6・A-7 に 1 行で出る

### UC-5: 至近の飛び出しの検知（R5）

- **Given**: アラート ON で、`dart` / `graze-dash` の鹿が林から出る
- **When**: カメラの条件（距離・画角・遮蔽なし）を満たす
- **Then**: 最初の抽選はいちばん近い帯の確率、赤は 80〜150 ms 後。目の反射だけの鹿は赤にしない
