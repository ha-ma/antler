# 障害耐性: loss（A-6 喪失・Claude が「失ったもの」を書く）

A-6 はデモの核（付録 A #3 の 30–75 秒）なので、**Claude が落ちても画面の 4 指標・しおり・統計カードは出す**（端末の純粋関数で決まる）。失敗するのは喪失文の欄だけ。

## トランザクション境界

### 操作: POST /api/trips/:id/losses

1. 旅を読む（無ければ 404）→ `checkCollision`（400 / 409）
2. 鍵で保存済みの行を読む。あれば返す（200。Claude を呼ばない、数えない）。無ければ旅の保存済みの件数を数え、20 件なら 429 LOSS_LIMIT
3. 同時の枠を取る（無ければ 503）→ 呼び出しごとに当日の通し番号を進めて上限を確かめる（429）→ Claude（トランザクションの外）。外れたら 1 回だけ作り直す
4. 1 行の INSERT（`ON CONFLICT DO NOTHING`）。0 件なら保存済みの行を読んで返す

1 行の書き込みだけなので UnitOfWork のトランザクションは使わない。失敗したら何も残らない。

## 競合 / レース対策

### 同じ記述子の同時の 2 要求

同じプロセスの中では、usecase が鍵ごとに処理中の Promise を持ち、2 本目は 1 本目の結果を待って同じ応答を受ける（single-flight。Claude は 1 回。UC-5f）。1 本目が失敗すれば 2 本目も同じ失敗を受け、終われば Map から消す。
別のプロセス（1 プロセス前提の外）では両方が Claude を呼びうるが、4 の主キーで片方だけが保存され、もう片方は保存済みの文を返す（CONC-1）。pending の行は作らない（失敗の状態を持たないので、落ちても作り直しを止める行が残らない。推奨で決定）。

### 1 つの旅の上限（20 件）

数えてから Claude を呼ぶまでのあいだに同じ旅の別の鍵が来ると、21 件目がわずかに通りうる（上限は費用の目安なので許す）。
