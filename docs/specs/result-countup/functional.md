# 仕様: result-countup（A-6・A-7 の結果の数字をカウントアップする。A-6 のアクセントを赤にする）

> 2026-11-08 main の rebrand-shikashi（#65）と sticky-cta（#66）を取り込んだ。A-6 の主ボタンは sticky-cta の固定の帯（`ActionBar`）に移り、帯の CSS が `--accent`・`--on-accent`・`--accent-deep` を読むので、R7 の `.loss` の変数で赤になる（ブラウザで trip・night とも確かめた）。`LossPage.tsx` の import だけが重なり、両方を残した。この仕様のルールは変えていない。

## 概要

ユーザーの依頼（2026-11-08）「結果ページ（衝突した場合も、衝突しないで成功した場合も）の数字は、カウントアップして動きのあるようにしたい」。

同じ日のユーザーの依頼「鹿にぶつかったあとの結果画面の表現は、緑ではなく赤をアクセントカラーに使ったほうが良いと思います」も、この feature で入れる（R7）。

A-6（`/loss/:id`、衝突の結果）と A-7（`/t/:id`、旅の記録。完走のあとの「クリア」の画面を含む）の結果の数字を、見えたときに 0 から最後の値まで数え上げる。最後の 1 コマは今の表示と 1 文字も違わない（通貨の記号・3 桁区切り・小数・単位・言語ごとの書き方）。

要件: ch3 A6-2・A6-3・A7、ch5（アクセシビリティ・4 言語）、ch8 規約 4（数字は等幅・tabular）、`docs/design/README.md`（StatTile の値は num-l）。
画面: UI キャンバス v2 の A6_Loss・A7_Record。

**Tier 1 の理由**: 画面の表示の動きだけが変わる。値の求め方（`assessLoss`・`STATS`・`buildRecordView`）・認可・永続化・外部副作用・並行性に触れない。

**result-screens R3 との関係**: result-screens（2026-11-06）は「数字のカウントアップは作らない」を推奨で決めていた（理由: 途中の値を読み上げ・画像の保存が拾う）。2026-11-08 のユーザーの依頼でこれを替える。2 つの理由には次のように答える: 読み上げは最後の値だけを読む（R3）。画像の保存は api が描く PNG（`useSaveImage` → `recordImageUrl` ＝ `/t/:id/og.png`）で、画面の DOM を写さないので途中の値は入らない。

**範囲外**: api の SSR の `/t/:id`（JS なしの共有ページ）と OG 画像（静的のまま。`apps/api` は変えない）、値の求め方とデータ、画面の並び・導線のボタン（sticky-cta が直している）、ブランドの文言（rebrand が直している）。

## Example Map

Story: 台湾から来た 4 人の代表として、D2 をアラート OFF で挑戦して衝突した。A-6 でカードが落ちて積み重なり、着地した 4 指標の金額が ¥0 から数え上がって止まるのを見て、失ったものの大きさを感じる。そのあと ON でやり直して走りきり、A-7 で「クリア」と、守れた楽しみ・避けた鹿の数が数え上がるのを見る。

Questions は 2026-11-08 にすべて推奨で決定した（ユーザーの方針「推奨案のある判断は推奨案で決めて進める」、2026-11-03）。

- R1 数え上げる数字（推奨で決定）: 上の「数字の一覧」のとおり。結果の値（StatTile の値）と統計カードの件数・金額だけ。番号・時刻・年・期間・補足の文・生成した文章は動かさない
- R2 最後の 1 コマ（推奨で決定）
  - 数え上げは、出来上がった文字列（例: `¥615,000（約 $4,100）`・`3 / 4`・`1.2`）の中の数字の並び（3 桁区切りのカンマ・小数を含む）だけを替える。数字でない部分（記号・空白・単位・括弧・「約」）はそのまま
  - 途中のコマは、元の数字と同じ小数の桁数・同じ 3 桁区切りの有無で書く。整数は四捨五入（小さい値でも途中で 1 に届く）
  - 進みが 1 のコマは元の文字列をそのまま返す（作り直さない。1 文字も違わない）
  - 止めたままにする数字（分母）は、呼ぶ側が数字の並びの番号で指定する（`hold`）。`/` の前後で決め打ちしない（A-7 の「遭遇 / 回避」は両方動く）
  - 文の中の数字は、文の型（`fillText` の `{key}`）の置き場所の名前で差し込む（言語ごとに順番が違うので、並びの番号では選ばない）。loss の `fillNodes`
- R3 読み上げ（推奨で決定）
  - 動いているあいだだけ、見える数字を `aria-hidden`、最後の値を透明（`opacity: 0`）の写しに置く。読み上げは写しを読み、途中の値は読み上げに出ない
  - 写しは見える数字と同じ場所に重ね（`display: inline-grid`）、最後の値の幅をとるので、桁が増えても文が折り返し直さない（`visibility`・`display` で隠すと読み上げからも消えるので使わない）
  - 終わったら、ふつうの文字だけ（今と同じ 1 つの文字の並び）に戻る。見出し（統計カードの `aria-labelledby`）の名前も最後の値
  - `aria-live` は付けない（数え上げを知らせない）
- R4 動かさないとき（推奨で決定）: `prefers-reduced-motion: reduce`、`IntersectionObserver`・`requestAnimationFrame` の無い環境（古いブラウザ・テストの jsdom）では、最初から最後の値をふつうの文字で出す（R3 の分けた形を作らない）
- R5 動きの速さと始まり（推奨で決定）
  - 1 つの数字は 1200 ms、ease-out（3 次。`1 − (1 − t)³`）。`requestAnimationFrame` で進める
  - 画面に入ったとき（`IntersectionObserver` の最初の交差）に始める。下にあって見えない数字は、スクロールして見えたときに始まる。1 回の mount で 1 回だけ（画面の外に出て戻っても数え直さない）
  - 始まりは「見えたとき」と「mount から `notBeforeMs` 経ったとき」の遅いほう
  - A-6 は落ちるカードが着地してから数える: `notBeforeMs` ＝ そのカードの番号 × 150 ms ＋ 820 ms（`loss.css` の `--loss-drop-stagger`・`--loss-drop-duration`。`utils/drop.ts` の `dropLandedMs`）。統計カードの中の数字はそこから 80 ms ずつずらす
  - A-7 の StatTile は 300 ms ＋ 番号 × 100 ms（「クリア」の円が描き始めてから。並びで少しずつずれる）
  - 数え上げの途中で再描画されても最初からやり直さない。値（文字列）が変わったら、新しい値を最後の値として出す（数え直さない。値は画面を開いたあとに変わらない）
- R6 見た目（推奨で決定）: 数字は `font-variant-numeric: tabular-nums`（桁の幅が揃い、数え上げの途中で揺れない）。書体は今の場所のまま（StatTile の値は IBM Plex Mono の num-l、統計カードの文は文の書体）。色を足さない（金額の clay はそのまま）。数字は最後の値の幅の中で右に寄せる（1 の位が動かない）
- R7 A-6 のアクセントを赤にする（2026-11-08 ユーザー判断「鹿にぶつかったあとの結果画面の表現は、緑ではなく赤をアクセントカラーに使ったほうが良い」。親セッション経由。`docs/design/README.md` の冒頭の注記）
  - 衝突の結果画面（A-6 `/loss/:id`。読み込み中・読めない画面を含む）だけ。成功の結果（A-7）は `spruce` のまま
  - `loss.css` の `.loss`（ページの root）で `--accent: var(--alert-danger)`・`--on-accent: var(--on-alert-danger)`・`--accent-deep`（`oklch(from var(--alert-danger) calc(l - 0.15) c h)`。alert-danger の明度だけを下げた濃い赤で、テーマで変わらない。押したときと主ボタンの影）を定義する。色は直書きしない。tokens に `alert-danger-deep` を足すと凍結の alert-ui の公開 API が増えるので、ページの CSS で作る（推奨で決定）
  - アクセントを読むもの: 主ボタン（白文字 4.6:1）・フォーカスの枠（線。night の ground で 4.02:1、紙の ground で 4.34:1。3:1 以上）・導入（いつ・見出し・事実）の左の帯（6 px）・4 指標の上の線（4 px。surface で 3.47:1）・しおりの済みの ✓（図形。紙の ground で 4.34:1）。固定の導線（sticky-cta の ActionBar）の主ボタンも同じ `--accent`・`--on-accent`・`--accent-deep` を読むので赤になる
  - 文字の色には使わない（推奨で決定）: alert-danger は night の ground で 4.02:1、surface で 3.47:1 で、4.5:1 に届かない。数え上げる数字は今の色のまま（金額は clay で 7.66:1、日数・楽しみは ink）。例外は今までの ✕ の衝突の行（大きい文字）だけ
  - 済みの ✓ もアクセントの赤にする（親セッションの指示）。✕ と同じ色になるが、形（✓ と ✕）・「済み」の読み上げの文字・✕ の行の大きい文字で分かる（色だけで分けない）

## ユースケース

### UC-1: A-6 の 4 指標が着地してから数え上がる

- **Given**: A-6 を衝突の情報としおりで開いた（動きを減らす設定ではない）
- **When**: 4 指標のカードが落ちて着地する
- **Then**: 「車両の損害」の値が `¥0（約 $0）` から `formatBudget(平均, lang)` まで 1200 ms で数え上がり、最後は今の表示と同じ文字列。「楽しみ」は `0 / 2` から `1 / 2`（分母は動かない）

### UC-2: 下にある統計カードはスクロールして見えたときに数え上がる

- **Given**: 狭い画面で、統計カードが画面の下にある
- **When**: スクロールして統計カードが画面に入る
- **Then**: 件数・金額が 0 から数え上がる。年と期間は最初から最後の値

### UC-3: A-7 の 4 つの値が数え上がる

- **Given**: 完走の記録の `/t/:id` を開いた
- **When**: 画面が出る
- **Then**: 楽しみ 達成（分母は動かない）・鹿ゾーン通過・遭遇 / 回避・アラート→ブレーキの平均の秒（小数 1 桁）が順に少しずつずれて数え上がる。「—」は動かない

### UC-4: 読み上げは最後の値だけ

- **Given**: 数え上げの途中
- **When**: 読み上げが値を読む
- **Then**: 最後の値（視覚的に隠した要素）だけを読み、途中の数字（`aria-hidden`）は読まない。統計カードの見出しの名前も最後の値

## 状態パターン

### S-1: 動きを減らす設定

- **Given**: `prefers-reduced-motion: reduce` → **Then**: 最初から最後の値をふつうの文字で出す（分けた形・見えない写しを作らない）

### S-2: IntersectionObserver が無い

- **Given**: `IntersectionObserver` か `requestAnimationFrame` が無い → **Then**: S-1 と同じ（最初から最後の値）

### S-3: 数え上げが終わった

- **Given**: 1200 ms が過ぎた → **Then**: 要素の文字は最後の値の 1 つの並び（`textContent` が今の表示と同じ）
