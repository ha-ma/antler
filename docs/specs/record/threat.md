# 脅威: record（A-7 旅の記録・走行の記録・記録ページ・削除）

この feature の HTTP の操作は 5 つ: 走行の記録の保存（書き込み）、記録の読み出し（JSON）、共有用の SSR ページ、OG 画像、旅の削除。
守るものは「他人の記録を書き換え・消させないこと（所有者トークンの照合）」「削除をすぐに効かせること（失効）」「所有者の印（ハッシュ）とトークンを外に出さないこと」「公開ページからの注入（XSS）」「描画・書き込みの濫用（CPU・保存容量）」の 5 つ。

読み出し（記録・SSR・OG）は brief-map と同じく **旅の ID を知る人に見せる**（A7-1「ログイン不要で閲覧」）。ID は英数 8 文字の暗号論的乱数（62^8 ≒ 2.2 × 10^14）。
書き込み（run の保存）と削除は **所有者トークン**（plan-trip R7。`HMAC(OWNER_TOKEN_SECRET, 冪等キー)`、api はその SHA-256 だけを保存）を要求する。

**✅ (公開) の理由**: A7-1「ログイン不要で閲覧」と付録 A #9「登録なし」。記録は個人を特定する情報を持たない（下のデータ分類）。ID は推測困難で、総当たりはレート制限で抑える。
**書き込みに所有者トークンを求める理由**（推奨で決定）: 記録は URL を知る人が見るので、トークンなしで run を書けると、共有されたリンクを見た人が他人の記録に偽の走行（衝突など）を差し込める。

**存在の区別**: トークンが違う（403）と旅が無い（404）は区別して返す。記録は ID を知る人に公開なので、「その ID の旅がある」ことは秘密ではない（GET でも分かる）。403 から分かるのは存在だけで、中身もトークンも分からない。

## IDOR / Mass Assignment チェック

### POST /api/trips/:id/runs

- **IDOR**: 対象の旅はパスの `id`。トークンの SHA-256 をその旅の保存したハッシュと比べる（他の旅のトークンでは 403）。run の主キーは（旅の id, runId）で、別の旅の runId と衝突しない
- **クライアントから受け取るフィールド**: `runId`・`day`・`alertEnabled`・`outcome`・`zonePasses`・`encounters[]`（`pattern`・`at`・`alertToBrakeMs`・`closestM`・`outcome`）・`frames`
- **サーバー側で設定するフィールド**: 旅の id（パスから）、保存時刻 `createdAt`、保存の順番
- **クライアントから受け取ってはいけないフィールド**: 旅の id（body）、`createdAt`、`seed`、所有者のハッシュ、Capture の画像・位置（この feature では受けない）
- **検証方法**: zod の strict（知らない欄は 400）。範囲（日数・件数・ms・m）を上限つきで確かめる。`day` は保存した旅の日数以下

### DELETE /api/trips/:id

- **IDOR**: 対象はパスの `id`。消す前にその旅のハッシュとトークンの SHA-256 を長さ一定で比べる。違えば何も消さない
- **クライアントから受け取るフィールド**: パスの `id` と `Authorization` ヘッダだけ。body は読まない
- **サーバー側で設定するフィールド**: N/A: 消すだけ
- **クライアントから受け取ってはいけないフィールド**: 消す範囲（run だけ・別の旅など）。範囲はサーバーが決める（その旅の全部）
- **検証方法**: `Authorization: Bearer [0-9a-f]{64}` の形でなければ 401（照合しない）

### GET /api/trips/:id/record ・ /t/:id ・ /t/:id/og.png

- **IDOR**: ID を知る人に見せる（上の理由）。所有者で絞らない
- **クライアントから受け取るフィールド**: パスの `id`（英数 4〜16 文字）だけ。クエリ・body は読まない
- **サーバー側で設定するフィールド**: 応答のすべて（保存した旅と run から集計）
- **クライアントから受け取ってはいけないフィールド**: N/A: 書き込みが無い（GET のみ）
- **検証方法**: 応答は `{ plan, details, record }` を明示して組み立て、保存した行（ownerTokenHash・runId）を返さない。HTML と SVG に入れる文字はすべてエスケープする（タイトルは Claude の生成物で、利用者の入力ではないが、信用しない）

## Data Classification

| データ                                                      | 分類                                              | 保存場所                       | 配信方法                               | 削除タイミング                                                   |
| ----------------------------------------------------------- | ------------------------------------------------- | ------------------------------ | -------------------------------------- | ---------------------------------------------------------------- |
| 走行の記録（日・ON/OFF・結果・回数・遭遇の時間と距離・fps） | 内部（個人を特定しない。ID を知る人にだけ見せる） | SQLite `trip_runs`             | 集計した形で記録の JSON・SSR・OG 画像  | 所有者の削除（即時）。保持期間は Deferred（暫定は消さない）      |
| TripPlan・TripDetails                                       | 内部（plan-trip の threat.md）                    | SQLite `trips`                 | 記録の JSON・SSR・OG 画像              | 所有者の削除（即時）。保持期間は Deferred                        |
| ownerToken                                                  | 機密（書き込みと削除の権利）                      | 端末の localStorage（sim）だけ | `Authorization` ヘッダ（HTTPS で送る） | 削除の成功で端末から消す。api は保存しない                       |
| ownerTokenHash                                              | 機密（照合）                                      | SQLite `trips`                 | 外に出さない                           | 旅と同時                                                         |
| 冪等キーの行（キーのハッシュ・旅の id）                     | 内部                                              | SQLite `trip_requests`         | 外に出さない                           | 旅の削除と同時（その旅を指す行）                                 |

| IP（レート制限の鍵）                                        | 個人に紐づきうる                                  | プロセスのメモリだけ           | 外に出さない                           | 窓（1 分）ごとに忘れる                                           |

ログのマスキング: ownerToken・`Authorization` ヘッダはログに出さない（アクセスログは method・path・status・ms だけ）。run の中身・HTML・画像はログに出さない。旅の ID は path としてログに残してよい（brief-map と同じ）。

OG 画像を取ったクローラー（SNS）の側に残ったものは、api の削除では消えない。sim の削除の確認に「共有先に表示されたカードは残ることがあります」と書く。
api のメモリに持つ OG 画像（100 枚）は、読み出しのたびに DB を引いてから使うので、削除のあとに返ることはない（プロセスの再起動で消える）。

**見せる欄の絞り込み**: 記録の JSON は画面に出す欄（`RecordTrip`）だけを返し、予算・seed・リスク・TripDetails を返さない（記録の URL は SNS で広く共有される）。
**残る課題（ハッカソン後）**: 記録の ID は旅の ID と同じなので、記録の URL を見た人は brief-map の `GET /api/trips/:id/day/:n` で旅を丸ごと（予算・seed を含む）読める。A-6 のやり直し・別の端末からの運転がこの ID で動くため、今は分けない（推奨で決定）。分けるときは記録用の別の乱数 ID を発行する。
**Capture**: A5-5 の Capture は旅の id を持たない（`packages/schema` の Capture）。旅を消しても、同意して送った鹿の画像は残る（旅とは結びつかない）。capture の feature で削除の確認文に足す。

## 横断的セキュリティチェック

- [x] CORS: 既存の `CORS_ORIGINS`。`allowHeaders` に `Authorization` を足す（`DELETE` は `allowMethods` にある）。SSR と OG は同じ origin で読むので CORS に頼らない
- [x] レートリミット: 書き込み 10 件 / 分 / IP（ch6）、読み出し 60 件、OG 20 件と同時 2 枚（描いた画像はメモリに 100 枚。持っている画像は枠を使わない）
- [x] 公開 URL: og:url・og:image・リンクは env（`PUBLIC_API_URL` など）だけから作り、`Host` ヘッダを使わない
- [x] エラーメッセージ: error-mapper で code と短い文だけ。トークンの照合の失敗理由（長さ・どこまで一致したか）を返さない
- [x] ログマスキング: `Authorization`・ownerToken・run の中身を出さない
- [x] XSS: SSR は `hono/html` の自動エスケープ。SVG の文字は XML エスケープ。SSR に `<script>` を置かず CSP で禁止
- [x] クリックジャッキング: SSR の CSP に `frame-ancestors 'none'`（secureHeaders の X-Frame-Options も）
- [x] 検索エンジン: `X-Robots-Tag: noindex` と meta robots
- [x] 長さ一定の比較: トークンのハッシュの比較は 16 進 64 文字どうしの XOR の和（途中で抜けない）
