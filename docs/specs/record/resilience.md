# 障害耐性: record（A-7 旅の記録・走行の記録・記録ページ・削除）

方針: **走行は保存できなくても終わらせる。記録は今ある分で出す。削除は全部か何もしないか。**
外部への通信は無い（OG 画像はサーバーの中で描く）。失敗しうるのは SQLite・画像の描画・端末の保存先（localStorage・clipboard）・回線。

## Concurrency / Idempotency

| 対象                     | 並行実行されうるか               | 二重実行されうるか                           | 冪等性要件                  | 実装方針                                                                                                 |
| ------------------------ | -------------------------------- | -------------------------------------------- | --------------------------- | -------------------------------------------------------------------------------------------------------- |
| POST /api/trips/:id/runs | 同じ旅の 2 つのタブから同時に    | 再送・二度押し                               | 同じ runId は 1 行          | 主キー（trip_id, run_id）で `INSERT … ON CONFLICT DO NOTHING`。件数の確認と挿入は 1 つのトランザクション |
| 件数の上限（1 日 20 件） | 同時の保存で 21 件目が 2 つ      | N/A: 再送は同じ runId なので件数を増やさない | 上限を超えない              | 件数の確認と挿入を同じトランザクションで（SQLite の書き込みは 1 本ずつ）                                 |
| DELETE /api/trips/:id    | 同じ旅の削除が 2 つ同時          | 二度押し                                     | 2 回目は 404（もう無い）    | 照合と削除を 1 つのトランザクションで。消えた後は旅が無いので 404                                        |
| 削除と走行の保存の同時   | 片方のタブで削除、もう片方で保存 | N/A: 別々の操作の同時（二重ではない）        | 削除のあとに run が残らない | 保存は旅の存在とハッシュの照合を挿入と同じトランザクションで行う（旅が無ければ 404）                     |
| OG 画像の描画            | クローラーと利用者から同時に     | N/A: 読み出しなので何度描いても同じ          | N/A: 読み出し               | 同時 2 枚まで（超えたら 503）。描画は毎回 DB を読む（削除がすぐ効く）                                    |

## トランザクション境界

### 操作: POST /api/trips/:id/runs

1. ヘッダと body の検証（DB の前）
2. トランザクション開始
3. 旅を読む（無ければ 404）→ トークンのハッシュの照合（違えば 403）→ 日数の確認（400）
4. 同じ runId があれば、それを返す（200）
5. その日の件数の確認（20 件で 409）→ 挿入
6. コミット

- 補償処理: N/A: 1 つのトランザクションで、外部への副作用が無い

### 操作: DELETE /api/trips/:id

1. ヘッダの検証（DB の前）
2. トランザクション開始
3. 旅を読む（無ければ 404）→ 照合（違えば 403）
4. `trip_runs`・`trip_requests`（その旅を指す行）・`trips` の順に消す
5. コミット

- 補償処理: N/A: 失敗すればトランザクションが戻る。sim は成功を受けてからトークンを消す

### 操作: GET /api/trips/:id/record ・ /t/:id ・ /t/:id/og.png

1. パスの検証
2. 旅と run を読む（読み出し 2 回。トランザクション不要）
3. 純粋関数で集計 → JSON / HTML / SVG → PNG

- 補償処理: N/A: 書き込みが無い
