# dataset-synth の事前の確かめ: 3D の鹿 M01〜M04 を Blender 4.5 で開く

2026-11-07、メインセッション。roadmap と引継ぎの「最初に .blend の動作が再生できるかを確かめる」の結果。
仕様: `docs/specs/dataset-synth/functional.md`（「事前の確かめ」節）。

## 環境

- Blender 4.5.15 LTS（arm64、blender.org の DMG。配布元の SHA-256 と照合済み）。Homebrew の cask は Intel 版で、Apple Silicon では Rosetta で遅いので使わない
- 開き方: `blender -b --factory-startup --disable-autoexec`（.blend の中のスクリプトを動かさない）
- 実体: main の checkout の `dataset/external/deer3d/<ID>/`（SHA-256 は deer3d の manifest と照合）

- .blend に同梱のテキストはメモとライセンス（CC0）だけで、スクリプトは無い
- `Stand` は 1 フレームだけ、`Idle` は全部の動作を並べた長い帯なので使わない。倒れる・攻撃・跳ぶは路上の鹿として不自然なので使わない

## 見つかった落とし穴と対処（`dataset/synth_render.py`）

1. **glTF の読み込みは全動作を NLA の帯に積み、後から読んだ GLB（骨格の名前が同じ）の帯も前の骨格に積む** → 動作を選ぶたびに NLA の帯を消す
2. **4 体で動作・材質・画像の名前がぶつかる**（Blender が `.001` を付ける。M02 で「`Idle` が無い」になった）→ 読み込んだ直後に `<id>/<元の名前>` に改名し、元の名前で引く
3. **.blend から物だけを取り込むと画像が付いてこない**（M03 で「画像 `head` が無い」）→ 画像も取り込む
4. **動作はすべての骨にキーを持たない**ので、前の動作の脚の形が残った（M01・M02 の並びで脚が折れて見えた）→ 動作を変えるたびに骨を静止の姿勢に戻す
5. **M03・M04 の材質**は 4.5 で単色になる → Principled BSDF ＋ 画像を `UVMap` の UV で張り直す（`Projection*` の UV は合わない。UV を描いて確かめた）。目は暗い光沢にする
6. 鹿でない物（ライト・カメラ・地面の `Plane*`・`Icosphere`）を描かない

## 大きさの確かめ

前脚の付け根の骨（`FrontUpperLeg.L` / `Frontleg_L`）の前後位置（体長の ±6%）の胴の上端 − 足の最も低い点を肩の高さとした（M03・M04 は頭・角・目のメッシュを除く）。
4 体を肩 1 m にそろえて横から並べた描画（`synth.py check` の `check.png`、`dataset/private/self-synth/` に書く）で、4 体とも背の上端が 1 m の線に合うことを目で確かめた。

## 射影の突き合わせ

`synth.py check` が、決めた 5 点（路面の上・遠近・左右・下向きの角の違い）を Blender のカメラで射影し、Python の射影（`synth.project`）と比べる。ずれは 2 px 以内で合格（終了コード 0）。

## 試しの run で直したこと（仕様の Questions に記録）

- 夜の 2 本はドラレコの取り付けが朝と違い上を向いていた（消失点 y ≈ 880〜940）→ `pitch_deg = [-16, -13.5]`
- ヘッドライトの強さを固定すると、背景の路面の明るさ（4〜36）に合わない → 背景の路面の帯の明るさで強さを決める（`road_ref`）
- EEVEE はライトの強さから決めた距離で光を打ち切り、20 m より遠い鹿が真っ黒になった → 打ち切り距離を 200 m に広げた
- `min_contrast` 8 では、目でもほとんど見えない鹿に箱が付いた → 10
