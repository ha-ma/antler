# 敵対レビュー結果: drive-crash-spot（2026-11-06、spec-adversary）

対象: `docs/specs/drive-crash-spot/functional.md`（初版）。取り込みは仕様の「spec-adversary の指摘の取り込み」に書いた。

## Critical

**C1 [甘い仮定 → R3] 演出の途中で離れると、衝突した run が残らない**
- R3 は「run の保存もそのぶん遅れる」「演出の間に画面を離れたら onFinish を呼ばない」。`apps/sim/src/app/DriveRoute.tsx` では `saveRun` と A-6 への移動が同じ `onFinish` の中にあるので、3.5 秒の間に戻る・再読み込み・タブを閉じると run が保存されない（record R11 から後退）。`summarizeRecord` は日ごとに ON の最後の run を結果にするので、衝突直後の再読み込みで前の completed が A-7 に残る。
- 提案: 衝突したフレームで結果を渡して保存し、遅らせるのは A-6 への移動だけにする。
- 補足: `advance()` は衝突のあと何もしないので、3.5 秒後の `result()` は衝突したフレームと同じ値。

**C2 [Example: R4] 見えない鹿に当たる。前方の連打で「事前」が増える**
- 鹿は 300 m 手前で置かれ、林の中の鹿は `occluded`。R4 の当たりはレイと球だけで、球は 300 m で半径 6 m。道の先や林の中を連打すると、見えていない鹿を「事前に発見」として数える。
- 追加する Example: 隠れた鹿はクリックしても発見にならない（`cameraSees` と同じ条件）。霧・夜でライトの外の鹿の扱い。目の反射だけの鹿は目が光っている間だけ当たる。

## Major

**M1 「事前」の意味が、アラート ON と OFF で同じにならない** — 検知は 120 m。60 m 以上で事前なら、赤を見てから 60〜120 m でクリックしても事前。選択肢: (a) その鹿の alert-start より前、(b) 120 m 以上、(c) 60 m のまま比べ方を A-7 に書かない。

**M2 分母に、見る機会のなかった鹿が入る** — `deer-appear` は 300 m 手前。ステージのクリアで消した鹿、ずっと林の中の鹿も分母に入る。1 km 手前にするとクリアが増えて膨らむ。提案: 「一度でも見えた頭数」にする。群れの球が重なるときの扱いも決める。

**M3 発見の記録とやり直し** — 記録が World の外にあるとやり直しで消えない。World の中に置き、やり直しで 0。クリックはエンジンのメソッドで受け、一時停止・終了の判定もエンジン側。UC-4j「restart のあとは found = 0」。

**M4 スキーマを足す順番と、古い run と新しい run が混ざったとき** — POST の検証・保存行の読み直し・`TripRecordSchema` はどれも strict。新しい sim と古い api で 400、戻すと黙って集計から外れる、古いタブが新しい api の応答で A-7 を読めない。記録の `spotting` は `.optional()`。混ざったときの扱い、OFF の挑戦の発見が A-7 に出ないことを明記。

## Minor（まとめ）

- A-6 の URL: `parseCollision` は strict。`spot` を先に取り出して別に検証する。範囲 `early ≤ found ≤ appeared`、上限、`spot` が 2 回のとき。
- 演出中の一時停止・タブを隠したときの計りの扱い。
- onFinish が 1 回だけか（`navigate` の同一性の変化、StrictMode）。
- アクセシビリティ: キーボードだけの人は鹿を指せない（0 / m と出る）。衝突をスクリーンリーダーに伝える文（role="alert"）。「発見 n / m」を aria-live にするか。
- スマホの枠の下の鹿、指ごと（pointerId ごと）の 8 px 判定。

## 問題なし

- 光は `ink`、暗転は `ground`。alert-danger を使っていない。光は 1 回だけで 1 Hz の規約に触れない。reduced-motion では暗転だけ。完走は今までどおり。i18n は表に置く方針。
