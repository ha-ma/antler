# sim-3d-architect: drive-tune の 3D（バックミラーとダッシュボード）

日付: 2026-11-06 / ブランチ: feat/drive-tune / 担当: `apps/sim/src/features/drive/scene/` だけ

## 課題（言い直し）

- R5（指摘 5、docs/changes/2026-11-06-a-local-feedback.md §2.5）: ルームミラーに後ろの映像（別のカメラ、15 fps 程度、解像度は抑える、左右反転、車内は映さない）。PC 60 fps を崩さない
- 右ハンドルのメーター: 速度・回転・ギア（D と段、後退 R）・時計（JST hh:mm）・外気温・ABS の灯・ナビの次の案内（UC-4b〜UC-4d）。毎フレーム `dashboardOf(world)` を読み、React を毎フレーム再描画しない
- 既存の車内スマホ（PhoneScreenHtml）を壊さない。R3F 9.3.0・drei 10.7.6 のまま

## 採った案

### バックミラー（scene/RearMirror.tsx）

- 後ろ向きの `PerspectiveCamera` を車内（cabin の group）の子に置く（車の座標 [0, 1.32, 1.1]、真後ろ、5% 下向き、縦の画角 15°、far は本体と同じ 1,400 m＝空の球まで届く）。屋根の後ろの端（z 1.05）より後ろなので、車内は画角に入らない（層や visible の切り替えは要らない）
- drei の `useFBO(256, 72)`（既定の HalfFloat のまま。描画先はトーンマップ前の線形の値なので、8 bit だと夜の暗い階調が数段に潰れてフォグに縞が出る。256 × 72 なら増えるのは約 37 KB）に `useFrame`（新しい `PRIORITY.mirror = -10`、置き終わった後・本体の描画の前）で描く。実時間の累積で 1/15 s ごと（60 fps で 4 フレームに 1 回。丸めで 5 フレームにならないよう 2 ms の余裕）
- 左右反転は鏡の面の UV（u → 1 − u、`buildMirrorFace`）。投影行列を反転すると面の裏表の判定が逆になるので使わない
- 描画先はトーンマップ前の線形の値なので、`MeshBasicMaterial` の `toneMapped` は既定（true）のまま貼る（本体の画面と同じ色になる）
- 鏡の面は実車の大きさ（0.21 × 0.058 m）に広げ、運転者の方へ yaw 0.2・pitch 0.12 rad 向けた（枠は殻に合成、描画コールは増えない）
- テスト（@react-three/test-renderer の偽の WebGL）ではフレームバッファが作れず `setRenderTarget` が落ちるので、マウント時に `createFramebuffer()` が作れるかを見て、作れないときは描かずに組み立てだけする（ブラウザの WebGL2 では必ず描く）

### ダッシュボード（scene/Dashboard.tsx・dashboard-text.ts・dashboard-paint.ts）

- 文字盤は 2D canvas（900 × 330 px）の `CanvasTexture` を板（0.30 × 0.11 m）に貼る。針（速度・回転）は 3D のメッシュで毎フレーム回す（滑らか）。canvas は表示の文字の鍵（速さの整数・ギア・時計の分・気温・ABS・ナビの文字）が変わったときだけ、多くても 12 Hz で描き直す（ABS の点灯・消灯は待たない）。回転数とブレーキは鍵に入れない
- 文字の決め方は純粋関数 `formatDashboard(Dashboard) → DashboardText`（JST は `Date(ms + 9h).getUTCHours()`。端末のタイムゾーンに左右されない）。描き方は `paintCluster(ctx, text)`（2D の文脈の一部だけを受ける。テストは記録するだけの偽物）
- Web フォントの読み込み（`document.fonts.status` の変化）で描き直す（最初は代わりの字体で描かれるため）。字体は `@antler/alert-ui` の `tokens.font.mono / sans`
- 配置: 目（x 0.3）からハンドル（x 0.44）の延長で、輪の上の内側に見える位置（中心 [0.5, 1.03, −0.3]）。下端はダッシュボードの上面（y 0.97）より上、上端は輪の上端に掛からない
- 並び: 左に回転計（0〜6 × 1000 r/min、5 以上は clay）、右に速度計（0〜120 km/h、真ん中に数字の速さ）、真ん中の列に時計｜外気温、ABS の灯＋ギア（大）、ナビの案内の帯（「n km 先 鹿ゾーン」「鹿ゾーン 残り n km」「目的地まで n km」。10 km 未満は小数 1 桁）

### 変えた既存の物（scene/ の中）

- `cabin-models.ts`: メーターの位置と大きさ（`METER_CENTER` [0.44, 0.985] → [0.5, 1.03]、`METER_SIZE_M` 0.30 × 0.11）、ひさしを短く高く、殻の 3D の目盛りを外した（canvas が描く）、ハンドルの中心 y 0.98 → 1.0（輪の上端がメーターの上の行に掛かっていた）、スポークを上・下・左から右・左・下に（上のスポークがメーターを隠していた。3 本スポークの普通の形）、`buildNeedle(lengthM)`、`meterAngle` は `dashboard-paint.ts` の `speedAngle / rpmAngle` に置き換え
- `Cabin.tsx`: 針を外し `<Dashboard />` と `<RearMirror />` を入れた。冒頭の「3D には文字を置かない」（drive-3d で捨てた「3D の文字」）を改めた旨を書いた
- `palette.ts`: `CLUSTER`（計器の canvas の色）を足し、tokens から `ink-muted` `line` `clay`（night）を借りた。`CABIN.meterHub` を足し、使わなくなった `meterTick` を外した
- `frame-state.ts`: `PRIORITY.mirror = -10`

## 捨てた案

| 案                                                | 捨てた理由                                                                                                                                                                          |
| ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| three の `Reflector`（examples の鏡）             | 毎フレーム全解像度で描く（15 fps・小さい描画先にできない）。運転者の視線で映りが変わり、車内も映る                                                                                  |
| 本体の Canvas の一角に scissor で後ろの映像を描く | 画面に固定された HUD になり、視線と一緒に動く車内の物にならない（R10・A3-2）                                                                                                        |
| ダッシュボードを drei の `Html` で DOM に         | DOM は常に 3D の上に重なり、ハンドルの輪の後ろに隠れない。CSS 3D の変換が毎フレーム。PhoneScreenHtml の Html 不具合（R3F 9.8）の再発の心配                                          |
| drei の `Text`（troika の SDF）                   | 字体を外から読み込む（既定は CDN）、日本語の字形が重い                                                                                                                              |
| 針も canvas に描く                                | 12 Hz の描き直しでは針がカクつく。60 Hz にすると 1.2 MB のテクスチャの転送が毎フレーム                                                                                              |
| ABS の灯を alert-zone（琥珀 #E8A64A）             | 琥珀はすぐ隣のスマホの 3 状態の「鹿ゾーン」の色。計器で同じ色が光ると意味が混ざる（palette.ts の「琥珀・赤は計器に使わない」）。代わりに tokens の clay night #F0A26B（注意の役割） |

## 計測（2026-11-06、開発機 Apple M2・ANGLE Metal、Chromium の Browser pane、1440 × 900・dpr 1.5 → 描画バッファ 2160 × 1350、運転中 85〜100 km/h・薄暮）

注意: 下の表のミラーは 8 bit の描画先で測った。その後 HalfFloat（drei の既定）に戻した（再計測は未実施。256 × 72 なので差は小さい見込み）。

**rAF の間隔の p50 / p95 は未計測。** Browser pane が隠れていて rAF が 1 Hz に間引かれていた（測った値 p50 1,001 ms は間引きの値で、性能ではない）。代わりに、ページの中で本体とミラーの描画を直接呼び、`readPixels` で GPU の終わりまで待った時間を測った（60 回）:

| 描画                                             | 時間 p50 / p95                             | 描画コール | 三角形                                                        |
| ------------------------------------------------ | ------------------------------------------ | ---------- | ------------------------------------------------------------- |
| 本体（2160 × 1350）                              | 4.1 / 6.5 ms                               | 17         | 約 3.6 万                                                     |
| ミラー（256 × 72）                               | 0.3 / 0.5 ms                               | 8          | 約 3.2 万（林のインスタンスは丸ごと描くため本体と同じくらい） |
| ミラー → 本体（ミラーを描くフレーム）            | 4.3 / 5.4 ms                               | 25         | 約 6.8 万                                                     |
| 本体＋文字盤のテクスチャ転送（毎回 needsUpdate） | 2.1 / 3.7 ms（本体だけとの差はノイズの中） | 17         | —                                                             |

- ミラーを描くフレームでも 16.7 ms の予算の 1/3 以下。ミラーの平均の上乗せは 0.3 ms × 15/60 ≒ 0.08 ms/フレーム
- 文字盤の 2D の描き直しは 0.1 ms 未満（目安の描画で測定）。転送の差は測れないほど小さい
- 画面で確かめたこと: 文字盤に 16:40・−9°C・D1→D5→D6・速さの数字・「4.9 km 先 鹿ゾーン」→「1.7 km 先 鹿ゾーン」が出て、針が速さと回転に付いて動く。走り出して 100 m を越えるとミラーに後ろの道・林・中央線が映る（出発直後はルートの始まりより後ろに道が無いので雪原と空だけ）。ハンドルの輪の内側から文字盤全体が読める
- 確かめていないこと: ミラーの左右の向き（UV の反転はテストで確認、向きは理屈だけ。80 px ほどの縮小した画面では判別できなかった）、ABS の灯が画面で点くところ（pane が隠れていて 1 Hz のため。テストで灯の塗り分けを確認）、昼のミラーの色、スマホ横（30 fps）

## 仮採用した判断

- 仮採用: ABS の灯の色 = tokens の clay（night #F0A26B）。依頼は「琥珀か黄」だが、琥珀（alert-zone）は 3 状態の色なので計器に使わない
- 仮採用: 回転計の上限 6,000 rpm（powertrain のシフトアップ 3,000 rpm より上に余白。5,000 以上を clay の目盛り）
- 仮採用: ナビの距離は 10 km 未満を小数 1 桁、以上を整数（AlertState の `formatKm` とは別。HUD と揃えるなら合わせる）
