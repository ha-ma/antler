# 敵対レビュー結果: brief-map（2026-11-03、spec-adversary）

対象: `docs/specs/brief-map/functional.md` の初版。エージェントに Write が無いため、メインセッションが返答を写した。
各指摘の「決定」は 2026-11-03 に推奨で決定したもの（functional.md に反映済み）。

## 追加すべき Example

### [1] R2: 2 つの時間計算（直線の目安と OSRM × 1.2）で、移動が重なる・返却に遅れる

- 指摘: `buildItinerary` は直線 × 1.3 ÷ 50 km/h で `startMs` を決め、R2 は到着を OSRM × 1.2 で出す。前の移動の到着が次の出発を越えうる。A-1 のリスクの「暗い時間の運転」と A-2 の光が食い違いうる
- 決定: その日の 2 本目以降の出発は「しおりの出発」と「前の移動の到着」の遅い方（重ならない）。不変条件 `arriveAt(i) ≤ departAt(i+1)` を AC-1 に足す。返却の 1 時間前を越えても到着はそのまま出す（しおりの組み立ては plan-trip の目安のまま）。全ての組で OSRM × 1.2 と直線の目安の比を記録するテストを足す

### [4] R3: ゾーンの名前・日をまたぐ移動・時刻の丸め

- 指摘: (a) `planRoute` は zoneIds をアルファベット順に並べるので「最初のゾーン」が通る順でない (b) 翌日に着く移動の表示が無い (c) 12:00〜24:00 が JST と書いていない、到着地点が曖昧 (d) 表示は分、光の判定は ms で境目がずれる
- 決定: 名前は区間の入口に最も近いゾーンの道路名。翌日に着く時刻は「翌 0:30」と出す。日没の地点は最後の移動の `to`（無ければ滞在地）で、地名をチップに出す。時刻は分に切り捨て、光の判定も切り捨てた分の時刻で行う

### [6] R4: 車が旅の途中で変わる・天候と路面が矛盾する

- 指摘: 4WD を日ごとの月で決めると 10/31 → 11/1 で車が変わる。天候と路面を別々に引くと「雪・乾燥」が出る
- 決定: 車種と 4WD は出発の月（JST）で旅全体に固定。路面は天候を条件にした表から引く（雪の日に dry は出ない。もともとそう実装していたのでテストを足す）

### [7] R9・R6: 地図の操作・遅れて届いた背景・コントラスト

- 指摘: 地図を動かせるか未定義（スマホでスクロールを奪う）、8 秒で切り替えた後に届いたスタイル、`ink-faint` は ground 上で約 4.21:1、D タブの 44 px、ステッパーの「✓」が文字、名札の幅が固定
- 決定: 地図は動かさない（`interactive: false`、ルートの範囲に合わせ、大きさが変わったときだけ投影し直す）。一度背景なしにしたら、その表示のあいだは戻さない。ground 上の小さい文字は `ink-muted`。D タブは 44 × 44 px。完了の印は SVG のチェック。名札は文の長さで幅を変える

## 追加すべき Question

### [2] OSRM は冬の通行止めを知らない

- 指摘: 知床峠（国道 334 号）は 11 月上旬〜4 月下旬に通れない。直線の代わりを planRoute にかけると、通らないゾーンを「通過」と出す。線の端点が地点の座標と合うかのテストが無い
- 決定: 取得スクリプトが「冬に閉まる道の表」を持ち、知床峠の近くを通る線は斜里を経由して取り直す（ペルソナは 2 月。季節で線を変えず、通年で峠を通らない線にする）。どの線も峠の 2 km 以内を通らないこと、線の端点が地点の 5 km 以内であることをテストする。直線の代わりは `zones: []` にして、画面に「概算のルート」と出す

### [5] 旅の ID と応答の中身

- 指摘: タイルの要求の Referer で ID が外部に出る、api のアクセスログの path に ID が残る、応答の plan に泊まる町・人数・seed が入る、ID の形が「8 文字」と「4〜16 文字」で食い違う
- 決定: sim の HTML に `<meta name="referrer" content="strict-origin">`（外へは origin だけ）。ログの path は運用者だけが見るので残す（threat.md に理由）。応答は plan を丸ごと返す（A-7 と同じく ID を知る人に旅を見せる。seed で鹿の出方が分かってもシミュレーションの中の話）と threat.md に書く。ID は「受けるのはスキーマの 4〜16 文字、作るのは 8 文字」と書き分ける

## 甘い仮定

### [3] 「同じ旅・同じ日なら同じ DayPlan」はデータが変わらない前提

- 決定: DayPlan に `data`（routes の取得日・zones の hash・条件の版）を入れ、ビジネスルールを「同じ旅・同じ日・同じ data なら同じ」に改める。409 は days が作り直せないときだけ（関係の無い地点を足しても days が同じなら 409 にならない）。距離の物差しは間引いた線の長さ（planRoute の totalKm）に統一し、区間の時刻はその比で補間する

## 問題なし

同時性（GET だけ）、`?alert=off` と A6-4、保持期間（plan-trip で Deferred）、帰属表示（Rule と受け入れ基準の両方にある）。
