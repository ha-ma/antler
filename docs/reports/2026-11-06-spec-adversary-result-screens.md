## 取り込み（2026-11-06、メインセッション。推奨で決定）

- 戻る・再読み込みで祝いを繰り返さない: 祝いは 1 つの履歴（location.key）につき 1 回。出した履歴を sessionStorage に覚え、同じ履歴に戻っても出さない（R4）
- 新しいタブ・ブックマーク: 最後の日が完走なら出す（共有の記録の事実）。本人が OFF の衝突の直後に新しいタブで開く場合の誤りは残る。正確にするには TripRecord に「保存順で最後の run の結果」を足す（@antler/trip・api・SSR に及ぶ。Deferred）
- 古いキャッシュ: マウントのあとに取り直したデータが来るまで A-7 は「読み込み中」を出し、祝いは最初の描画で 1 回だけ決める（後から出さない・消さない）
- offResult のガードは入れない: 主なデモの流れ（OFF で衝突 → A-6 →「ON でやり直す」→ 完走）で祝いが出なくなるため。OFF の衝突のあとは合図・履歴の 1 回で防ぐ
- OFF だけの完走も「クリア」（鹿にぶつからずに走りきった事実は同じ）
- 「クリア」は見出しでない `<p tabIndex=-1>`（h1 は記録の見出しのまま、見出しの順を崩さない）。祝いを出すときだけフォーカスをここへ移し、h1 の ref を外す
- 導線の透明: `.loss-drop:focus-within` は動きを止めて即座に見せる
- DROP-2 は「DOM の順に 0 から抜けなく増える」で書く（決まった番号を書かない）
- 紙吹雪・円は pointer-events: none、紙吹雪は終わったら不透明度 0 で残る（aria-hidden）
- 同じファイルを書く件: drive-crash-spot への申し送り（共有のノート `result-screens-handover.md`）に、後からマージする側が取り込み直すことと、行の足し方を書く
