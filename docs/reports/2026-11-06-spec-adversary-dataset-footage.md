## Critical

### C1 [R4 確かめ] 焼き込みの残りの検査は、一番消したい桁を見逃し、何も見つからなくても通る

- 検査は「50% 以上のフレームで続く明るい縁の画素」だけを数える。GPS の下の桁と時刻の秒は 1 秒おきに変わるので、続く画素にならない
- 矩形が文字の途中で切れると、上の桁とラベルは矩形の中に入り、変わる下の桁（精密な位置）だけが外に残る。この場合、検査は 0 を数えて通る。ANON-4c の「動く明るいものは数えない」は、この見逃しをテストで固めてしまう
- 陽性対照が無い。焼き込みが平均 180 より暗い（黄色・縁取り文字など）か、矩形の位置が違うと、前も後も 0 で何も言わずに通る
- 50 画素の許容は、1080p の数字 1〜2 文字分の縁に近い
- 提案: (a) 矩形の左端が数字の列を切り、外に毎秒変わる数字が残る偽のフレームではエラー。(b) 矩形の中の塗る前の数が下限より少なければエラー。矩形を数十 px 広げた帯の中で、フレームごとに明るい縁があれば数える（続くかどうかを問わず、許容は 0）。`overlay_masks` が空のカメラで検査をどうするかを書く

### C2 [R7] `--redo` と同じ映像の二重登録で、分割の固定を迂回できる

- R7 は `--redo` で作り直せる差分に「走行・分割」を含めている。済みのクリップの `drive` を新しい test の走行に書き換えて `--redo` を回すと、既に学習に使ったかもしれないフレームが test に入る
- R1 は `id` の重複だけを見て、`sha256` の重複は見ない。同じ映像を別のフォルダに置いて 2 行登録すれば、同じフレームが train と test に入る
- 提案: `--redo` で変えてよいのは矩形・区間・間引き・検出器の設定だけ。済みのクリップの `drive` / `split` の変更は常にエラー。一覧の中と manifest 全体で元の `sha256` の重複をエラー

### C3 [R1・Questions] 撮影日で決める走行の境目に、日跨ぎと時計の食い違いの穴がある

- クリップの `id` の日付と `drive` の日付が違えばエラーなので、0 時を跨ぐ夜の走行は構造上 2 つの走行になり、続いた映像の片方を train、片方を test に置けてしまう
- 朝の映像もファイルの作成時刻は 2026-11-06。時計がずれていれば、朝の 1 本は夜の 4 本（train）と同じ日・同じ道の走行かもしれず、`fp_eval` は楽観的な数字になる
- 提案: 日を跨いだ夜の 2 クリップを 1 つの走行に置ける（走行の日付かその翌日を許す）。Question（ユーザー）: 走行の日付をどの時計で決めるか。朝の 1 本は夜の 4 本と同じ旅行か

### C4 [R1] Git に入る一覧に、時・分・秒が残る

- `id` の書式は `20261106_213512` を通す。`file` もドラレコの元の名前（多くは日付と時・分・秒入り）をそのまま書ける。一覧は Git（公開）に入り、manifest の `video` / `clips` は一覧の `id` をそのまま持つ
- 提案: `id` の接尾辞が 6 桁の数字・`file` に日付と時刻の形 → エラー。もしくは `file` を一覧から外す

## Warning

- W1 [R5] `--out` / `--raw` の置き場所に制限が無い。Git 対象のパスを渡すとフレームと manifest がコミットできる場所に出る。提案: `--out` の実体が `dataset/private/` の中、`--raw` の実体が `dataset/raw/` の中であることを必須にする
- W2 [R4] 検出の入力の大きさ（imgsz）を書いていない。車の箱の上半分（乗員の顔）はぼかさない。重みが無いと ultralytics は自分でダウンロードする。結果の保存（`save` / `runs/`）を止める規則が無い。提案: imgsz を書く、重みの存在と SHA-256 を照合、検出器はファイルを書かない。Question: 車の中の人の顔をぼかすか
- W3 [R3・R4] 確信度 0.15 の夜では鹿を `person` と出しやすく、鹿ありのフレームの鹿がモザイクになりうる。鹿なしの区間に映った鹿・目の反射が残ると負例と合成の背景を汚す。提案: 鹿の区間で `person` の箱が出たフレームに印。Question: 鹿なしのフレームを負例に使う前に人が確かめるか
- W4 [R5・R7・S-1] 未定義の状態: (a) 一覧から消したクリップが manifest に残る (b) manifest を消したが `frames/<id>/` が残る (c) kill で残った `.tmp-<id>/` (d) 改名の後、manifest を書く前に落ちた (e) 同じ manifest への同時の `ingest`。済みの比較に検出器（重み・確信度）が入っていない。提案: Example か S-3 以降にする。同時実行はロックでエラー。済みの比較に検出器と全設定
- W5 [R5] JPEG のメタデータの検査が禁止リスト方式（COM・APP14 などが通る）。提案: 許すマーカー（SOI・APP0（JFIF）・DQT・SOF・DHT・SOS・EOI・DRI・RST）以外をエラー
- W6 [ch5] 元の映像の保持期間が無い。`camera` に向き（前・後・車内）が無く、車内カメラの映像がそのまま通る。提案: `facing = "front"` を必須にし、それ以外はエラー。Question: 元の映像を残す期間と消す契機
- W7 [R6・後続] `files[].video` はクリップの id で、dataset-train の漏れの検査のグループは `video`。走行の単位の漏れ止めがこの manifest の外で効かない。`distribution: "not_allowed"` が合成画像に引き継がれる規則が無い。提案: 走行をグループにすることと、合成の出力が配布不可を引き継ぐことを後続の Deferred に書く

## Info

- I1 検出器の出力は機械と版で変わりうる。決定性は「同じ検出器の出力なら同じ manifest」に絞る
- I2 `start < margin_s`・`start = 0`・2 つの区間の間が `2 × margin_s` より狭い・`end` が長さを超える の Example が無い。`round` の丸め方を明文化する
- I3 opencv のフレーム数は推定値のことがある。順に読むことと、読めたフレーム数で長さを決めることを書く
- I4 「約 10 km より粗い」は検査できない。許す地域名の一覧にする案
- I5 元の映像の SHA-256 を Git に入れる意図を明文化する
- I6 昼に長く停車すると標識・白線が続く画素になりエラーになる。止まったときにどうするかを書く

## 問題なし

音声とコンテナのメタデータ・GPS のトラックは、JPEG のフレームだけを書く構造で出力に入らない。元の映像を読むだけにする約束、シンボリックリンクと `<raw>` の外の拒否、合成の背景を train の走行に限る `uses` の構造は妥当。
