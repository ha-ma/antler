# A-1 旅をつくる（A1_Plan、/plan）デザイン読み取り

出典: UI キャンバス v2 の `project/A1_Plan.dc.html`（1440 x 900、`expand: fill` のページ型）。読み取り専用。色は tokens.json のトークン名で書く。
注意: このアートボードはスマホ版が無い（スマホ版の `TripSetup_M` は v1 の旧案で別画面）。レスポンシブは flex-wrap と min 幅で表現されている。

## 1. レイアウト

- 全体: 背景 `ground`、文字 `ink`、Noto Sans JP。縦に「ヘッダー」「本文」。
- ヘッダー（左右余白 40px、下に 1px `line`）: 左にロゴ（山形の線画 SVG、`spruce` と `clay` の 2 本線）と「EZO ROAD」。中央にステップ 4 つ。右に言語セレクト。
  - ステップ: 1 旅をつくる（現在。`spruce` 背景に白文字の pill）／2 出発前チェック／3 ドライブ／4 旅の記録（`ink-faint`）。番号は IBM Plex Mono。
- 本文: 最大幅 1360px、padding 32 40 40、gap 40px、flex-wrap の 2 カラム。
  - 左（広い、最小 640px）: 見出し → 入力 6 欄 → 楽しみ選択（タブ・カウンター・カード格子）。
  - 右（aside、340〜380px）: 「旅のしおり」カード → 主ボタン → 補足 1 行。
  - 狭くなると右カラムが左の下に折り返す（約 1020px 未満）。スマホ専用の再配置は描かれていない。
- 左カラムの見出し: 「どんな北海道の旅を、楽しみにしていますか？」（30px / 900）。その下に説明 14px `ink-muted`:「ここで描いた旅が、そのまま3Dのドライブになります。あなたの仕事は、この旅を最後まで守りきること。」

| 順  | ラベル       | 種類                                     | 見本の初期値 |
| --- | ------------ | ---------------------------------------- | ------------ |
| 1   | 人数         | number（ステッパーではなく素の数値入力） | 4            |
| 2   | 運転できる人 | number                                   | 2            |
| 3   | 出発         | テキスト（日時ピッカーではない）         | 2/14 10:00   |
| 4   | 返却・帰国   | テキスト                                 | 2/18 17:00   |
| 5   | 出発地       | セレクト（新千歳空港／釧路空港／札幌駅） | 新千歳空港   |
| 6   | 予算（1人）  | テキスト、IBM Plex Mono                  | ¥120,000     |

- 「経験」の欄は無い（レンタカー経験・雪道経験などの入力は描かれていない）。要件に必要なら追加の判断が要る。
- ラベルは入力の上、12px / 500。入力の文字は 14〜15px。
- 枠色は `line` より濃い独自色が使われている（トークンに無い。実装は `line` に寄せるか、tokens.json に足すか要判断）。

## 3. エリアタブ・PleasureCard・カウンター

- セクション見出し: 「楽しみなことを選んで、重さをつける」（16px / 700）。補足 12px `ink-faint`:「重さが大きいほど日程で優先され、失ったときの痛みも大きくなります。」
- エリアタブ（右寄せ、role=tablist）: pill 状の 2 つ。選択中は `ink` 背景＋白文字、非選択は透明。各タブ末尾に選択数を Mono で付ける。
  - 「道東（釧路方面）6」（選択中）／「道央（札幌方面）1」
- カウンター: 「選択 7 / 10」。数字は Mono 16px / 600。見本は 7 だが、道東の選択済みカードは 6 枚で、タブの 6+1=7 とは合う（道央の 1 件はタブに隠れている）。
- カード格子: 4 列、gap 12px。見本は道東の 12 枚（選択 6、未選択 6）。
- PleasureCard の構造（radius-l、overflow hidden）:
  - 写真枠: 高さ 104px。実写は無く、パステル単色の面に「[写真：知床・流氷の上を歩く]」のような説明文を 11px で載せる（`photo-placeholder` 相当だが色は 1 枚ごとに違う淡い青・緑・紫・茶）。
  - 右上に 24px の丸バッジ: 選択済み＝`spruce` 地に白のチェック、未選択＝白地に「＋」。
  - 名称 14px / 700、その下に補足 11px `ink-faint`（「地名 ・ 条件」の形）。
  - 重さバー（選択済みのみ）: 「重さ」ラベル（11px）＋ 5 段の小さな長方形（22 x 14px、radius 3px）＋ 右に数値（Mono 13px）。埋まった段は `spruce`、空の段は `line`。各段は button（aria-label 1〜5）なので、段をタップして重さを決める。
  - 選択枠: 選択済みは 2px の `spruce` 枠、未選択は 1px の細い枠で、カード全体が button。重さバーは未選択には出ない。
- 見本の選択済み 6 枚（名称／補足／重さ）は第 7 節に載せる。
- 格子の下に 12px `ink-faint` の 1 行で、道央タブの内容の見本を列挙している（第 7 節）。

## 4. 右パネル「旅のしおり」（白面、radius-xl、1px `line`）

- 見出し行: 「旅のしおり」（13px / 700、字間広め、`ink-faint`）。右端に「4泊5日 ・ 1,180 km」（Mono 12px）。
- タイトル: 19px / 900、2 行。「流氷とタンチョウと、雪見の温泉。／道東をめぐる5日間。」（選択した楽しみから作る文章。自動生成の想定）
- 重さの配分バー: ラベル「重さの配分（合計 20）」。高さ 10px の横積みバーで、重さに比例した flex。色は `spruce` の濃淡 6 段階（濃い順に重い楽しみ）。下に各区間の短縮名と重さを並べる:「流氷 5／鶴 4／温泉 4／摩周 3／市場 2／豚丼 2」。
- D1〜D5 の行（Mono の「D1」＋ 13px の 1 行説明）。書かれているのは、移動の「元 → 先」、立ち寄り、宿の場所、一言の注記。長い説明文は無く 1 行で収まる:
  - D1 新千歳 → 釧路　和商市場は翌朝に
  - D2 鶴居でタンチョウ → 摩周湖 → 阿寒湖で雪見温泉
  - D3 知床・ウトロ　流氷ウォーク（重さ5＝丸1日）
  - D4 網走 → 帯広　豚丼
  - D5 帯広 → 新千歳　返却
  - 宿は独立した行ではなく、D2 の「阿寒湖で雪見温泉」のように楽しみの名前に含まれる。重さが日程の長さを決める（重さ 5 は丸 1 日）。

## 5. 「この旅が失われるリスク」

- パネル下部、点線の上罫（`line`）で区切った帯（`ground` 背景）。
- 1 行目: 左に「この旅が失われるリスク」（13px / 700）、右に判定語「高い」（`clay-deep`、13px / 700）。
- 2 行目: 高さ 8px の横バー。地は `line`、充填は `clay`、幅 78%。数値スコアは出さない（段階語＋バー）。赤（`alert-danger`）は使わない。
- 3 行目: 根拠文 12px `ink-muted`（行間 1.7）。見本:
  「道東 × 2月 × 日没16:30。釧路方面は2025年に1,751件の鹿事故が届け出られた地域です。夕方の移動のたびに多発区間を通ります。」
  - 構成は「エリア × 月 × 日没時刻。地域の実数（件数・年）。自分の旅程がそこをどう通るか」。
  - 注意: 実数 1,751 件・2025 年は画面に直書きされている。実装では `stats.json` から読み、出典を画面に出す（CLAUDE.md の MUST）。日没 16:30 も要データ化。

## 6. 言語・通貨・主ボタン

- 言語切替: ヘッダー右端のセレクト（高さ 36px）。選択肢は「日本語／English／繁體中文／한국어」（4 言語。AlertState の ja/en/zh/ko と対応）。
- 通貨併記: 見本には無い。予算欄は「¥120,000」の円のみで、他通貨の併記は描かれていない（ch5 の多言語要件に通貨併記があるなら別途判断）。
- 主ボタン: 右パネルの直下、幅いっぱい、高さ 56px、radius-l、`spruce` 地に `on-spruce` の文字、16px / 700。文言「この旅を守りに行く →」。押し込み影（shadow-press）は描かれていない。リンク先は A-2（`A2_Brief`）。依頼文の「この旅で出発」ではなくこの文言が正。
- 補足: ボタン下に 12px `ink-faint` で中央寄せ:「登録不要 ・ 3Dはブラウザで動きます ・ 所要 約12分」。

## 8. 実装時の注意（デザイン側の食い違い）

- 枠色・パステル写真色・濃淡の緑（配分バー）は tokens.json に無い独自色。実装は `line`・`photo-placeholder`・`spruce` の不透明度で代替するか、足す判断が要る。
- チェックと「＋」は文字（✓、＋）で描かれている。CLAUDE.md の MUST（絵文字不可・アイコンはインライン SVG）に合わせ、SVG にする。
- 出発・返却は自由記述のテキスト。実装では日時入力にしたほうが検証しやすいが、見本どおりでよいかは要確認。
- 「経験」欄と通貨併記は見本に無い。
