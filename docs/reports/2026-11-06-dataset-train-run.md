# dataset-train の実データでの 1 周（2026-11-06）

`dataset/train_l0.py`（docs/specs/dataset-train）を、いまある素材で build → train → export → evaluate まで回した記録。
**開発用の Mac（Apple M2・24 GB）での値で、車載の Mac mini（M1）の値ではない。** 書くのは件数と評価の数だけ（画像・ファイル名・Capture の id は書かない。dataset-train の Deferred W8）。

## 条件

- 素材: `dataset/train_sources.toml` の 2 つ。Commons（CC0 / CC BY、`use = train`）と Commons の BY-SA（`use = eval`）。Capture は 0 枚（A の「見つけた」はまだ無く、vehicle は使わない）
- build（run `r1`、seed 7）: train 19 枚 / val 10 枚（鹿 13 個）/ 評価側 100 枚（鹿 17 個。V006 の 12 個と V001（夜間）の 5 個）
- 学習: 元の重み COCO の `yolo26n.pt`、60 epoch、640、batch 8、MPS、seed 7、最終 epoch の重み。所要 199 秒
- 評価: L0 と同じ入力（640×480 に縮める）、IoU 0.5、確信度 0.25 と 0.4。TP / FN / FP（鹿なし画像で予測が出た枚数）

## 結果（確信度 0.25。括弧は 0.4）

| モデル                                                | 入力                       | val の TP / FN / FP         | 評価側の TP / FN / FP        | 評価側の鹿なし画像の誤報 |
| ----------------------------------------------------- | -------------------------- | --------------------------- | ---------------------------- | ------------------------ |
| 前のモデル（yolo26n-deer-20261105）                   | 640×640（L0 が引き伸ばす） | 1 / 12 / 0（0 / 13 / 0）    | 11 / 6 / 0（11 / 6 / 0）     | 0 枚                     |
| 前のモデル                                            | **640×480**                | **7 / 6 / 1**（3 / 10 / 0） | **12 / 5 / 0**（11 / 6 / 0） | 0 枚                     |
| 新しいモデル（yolo26n-deer-coco-r1、COCO から 19 枚） | 640×640                    | 0 / 13 / 0                  | 0 / 17 / 5                   | 4 枚                     |
| 新しいモデル                                          | 640×480                    | 0 / 13 / 1                  | 0 / 17 / 10（0 / 17 / 3）    | 7 枚                     |

- `.pt`（Ultralytics）と `.mlpackage`（L0 の読み込み）の数は、どの行も同じか 1 個違いだった
- 夜間の V001（5 個）は、どのモデル・どの入力でも 0 個
- L0 の読み込みでの速度（`cpu_and_ne`、評価側 100 枚）: 640×480 の入力で p50 8.4 ms・p95 9.8 ms（640×640 のときは p50 11.3 ms・p95 11.9 ms）

## 分かったこと

1. **L0 の引き伸ばしが精度を大きく落としていた。** 720p（16:9）の画像を 640×480 に縮め、さらに正方形の 640×640 へ余白なしで引き伸ばすと、縦が約 1.8 倍に歪む。前のモデルの val は、Ultralytics 本来の前処理（縦横比を保つ）なら 5/13（外部の研究の値と同じ）、引き伸ばしでは 1/13、640×480 の入力なら 7/13。edge-l0 の Deferred「精度が落ちるなら 640×480 の入力でエクスポートし直す」を実施し、`train_l0.py export` の既定を 640×480 にした
2. **データの流れは 1 周したが、19 枚では鹿を学べない。** COCO から学んだモデルは val・評価側とも 0。Ultralytics 自身の検証（縦横比を保つ・確信度の下限 0.001）でも mAP50 0.70 で、確信度は大半の画像で 0.25 未満だった。学習データを増やすこと（写真のラベル付け・A の Capture）が先
3. **前のモデルを 640×480 で書き出したもの（`yolo26n-deer-20261105-480.mlpackage`）が、いま手元で最もよい L0 の候補。** ただし CC BY-SA を含む学習の派生なので、採用は ch6 の判断のあと

## 数字の読み方の注意

- 評価側の V006（12 個）は、前のモデルの学習に入っていた動画。前のモデルの評価側の数は甘い。前のモデルが学習していないのは V001（夜間、5 個）だけで、そこは 0 個
- val の V003 は外部の研究でも評価に使われ、今回も結果を見てから入力の大きさを変えた。未見のテストではない
- 正解のラベルは「AI による目視の概算ラベル」（素材の manifest の注記）。1〜2 個の差は揺れの範囲
- 新しいモデルの seed は 1 つだけ。MPS では同じ seed でも学習は完全には一致しない
