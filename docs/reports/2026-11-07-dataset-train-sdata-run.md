**暫定。テスト専用の走行は無く、評価に自分の映像の鹿は入っていない。** 本当の評価は 2026-11-07 夜の鹿の走行の映像（テスト専用の走行）を匿名化した後に行う。

- 日付: 2026-11-07。開発用の Mac（M2・MPS）での値で、Mac mini の値ではない
- 道具: `dataset/compare_l0.py`（build・summarize）、`dataset/train_l0.py`（train・evaluate）。比較の全数は `dataset/out/compare/sd1.json`・`sd1.md`（Git の対象外）
- 書かないもの: 画像・ファイル名・撮影者名・評価の JSON の `by_group`（撮影者のハッシュ）

## 条件（2 つの arm で同じ）

| 項目       | 値                                                                                                                                                          |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 元の重み   | COCO の yolo26n.pt（SHA-256 `9b09cc8b…`、BY-SA を含まない）                                                                                                 |
| 学習       | 12 epoch・imgsz 640・batch 8・MPS・Ultralytics 8.4.202・seed 1 と 2・build の seed 7                                                                        |
| 評価       | `.pt`、640×480 に引き伸ばす（L0 と同じ入力）、IoU 0.5、閾値 0.25・0.4・0.8、後処理（l0-fp-filter の既定値: 面積 0.7・幅 0.85、無視する領域なし）あり / なし |

epoch は 2 つの arm で同じにした。mix は画像が 3.07 倍多いので、1 epoch のステップ数も 3.07 倍（28 と 86）。

## 結果（seed 1 / seed 2）

評価側の実写の鹿は eval-by-sa の 17 個だけ。後処理あり / なしの数は、この 4 つの重みではすべて同じだった（誤報の箱が小さく、面積・幅の規則に当たらない。無視する領域は空）。

| 評価側の実写の鹿 TP / 17（閾値 0.25）          | 1 / 0                | 0 / 1       |
| 評価側の実写の鹿 TP / 17（閾値 0.4・0.8）      | 0 / 0                | 0 / 0       |
| 評価側の実写の鹿の FP（閾値 0.25）             | 19 / 3               | 13 / 6      |

seed の最小〜最大の範囲が重ならなかった数（`separated`）は、どれも mix の誤報が多い側だった: Mapillary の誤報のある画像の割合（閾値 0.25・0.4）、朝の val の誤報のあるサンプル /分と箱の FP（閾値 0.25・0.4）。実写の鹿の再現率は両方ともほぼ 0 で、差は seed のばらつきの中。

## 読み方

- この条件（12 epoch・実写の鹿の箱のある画像 40 枚）では、どちらの arm も実写の鹿をほとんど見つけられない。S データを足しても、実写の鹿の再現率が上がったとは言えない（seed のばらつきの中）
- S データを足すと、昼の路面（Mapillary・朝の走行）での誤報が増えた（seed 2 つで範囲が重ならない）。S データは夜の背景だけで、昼の鹿なしの画像は学習側に無い。また mix はステップ数が 3 倍なので、差が S データの中身によるのか学習量によるのかは、この 1 回では分けられない
- 後処理は今回の誤報を減らしていない。無視する領域（ボンネット・ダッシュボードなど）を設定した後の評価は別に要る
- 自分の映像の鹿は、全部が学習の走行（2026-11-06、S データの背景と同じ走行）にあるので、評価に使えない。夜の走行の鹿なしのクリップ（S データの背景）も学習の走行なので、連続した誤報の評価に使っていない（朝の val の 3.2 分だけ）

## テストの走行と学習の走行の道路の重なり

テスト専用の走行がまだ無いので判定していない。eval-by-sa は外部の動画で、撮影地点のメタデータを持ち込んでいないため、学習の走行と同じ道路かは分からない。Mapillary の道東の画像は、学習の走行（道東）と同じ道路を含みうる（照合していない）。
