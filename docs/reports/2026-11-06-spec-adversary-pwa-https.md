# spec-adversary: pwa-https（2026-11-06）

対象: `docs/specs/pwa-https/functional.md`（最初のドラフト）。エージェントは読み取り専用のため、メインセッションが要約を書き写した。

## 指摘（重大度順）と取り込み

| #   | 指摘                                                                                                                                                                                | 取り込み                                                                                                                                                                                                                                                                                                                                  |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | edge-run が `ssl_context` を渡すまで AlertServer は ws のまま。https の PWA から ws は混在コンテンツで止まり、理由の出ない「未接続」になる（R2 の「黙った後退」が Deferred で残る） | `server.listening` に `tls` を出し、`[tls]` が空なら `tls.disabled` を warn に 1 回（R2）。`ca_cert` だけ書いて `cert`・`key` が空は ConfigError。入口への配線は edge-run と調整（Deferred の暫定挙動を「ws のまま、`tls.disabled` が出る」に）                                                                                           |
| 2   | 設定ページの `/healthz` の確認は別オリジン。素の `fetch` は CORS で必ず失敗し、PWA に移らない                                                                                       | `fetch(…, {mode: 'no-cors', cache: 'no-store'})`（不透明な応答＝TLS が通った）と決め、UC-4g を直した                                                                                                                                                                                                                                      |
| 3   | 証明書の SAN・期限と待ち受け・ビルドの一覧の食い違いを、スマホ側では「CA 未信頼」と見分けられない                                                                                   | pwa_server の起動時の自己検査（期限切れは起動しない、30 日未満は warn、`host` が IP なら SAN にあること、SAN の各 IP が dist の CSP にあること）を R4 と UC-4m に。IP が変わったら「証明書・ビルド・再起動」の 3 つを runbook に                                                                                                          |
| 4   | 握手が上限の外: ThreadingHTTPServer は枠の前にスレッドを作る、TLS では握手前に 503 を書けない、5 秒は受信ごと、AlertServer は握手のあとに数え、`ssl_handshake_timeout` が既定 60 秒 | pwa_server は枠をスレッドの前で数え（溢れたら握手せずに閉じる）、握手は枠の中のスレッドで 5 秒（受信ごと）。CaptureServer も握手は枠の中で、溢れたら TLS では閉じる。AlertServer は `ssl_handshake_timeout=open_timeout`（3 秒）。合計の期限を持たない点（少しずつ送る接続）は受け入れたリスクとして threat に書いた（AP の WPA2 が境界） |
| 5   | 証明書の警告を押し切った端末の振る舞いが未定義                                                                                                                                      | 決めた: 押し切りはサポートしない（ブラウザで違う）。設定ページ・runbook で「押し切らずに CA を入れる」。押し切った場合は PWA の既存の案内（未接続・位置情報が使えない）に落ちる                                                                                                                                                           |
| 6   | LibreSSL で名前の制約の IP の書き方、iOS / Android がユーザー CA の critical な名前の制約を守るか、AC-2 が「全面的に信頼」の画面を通らない、Android の確認が無い                    | IP はマスクで書く（`IP:a.b.c.d/255.255.255.255`）。テストは OpenSSL 3 と `/usr/bin/openssl`（LibreSSL 3.3.6）の両方で回す。iOS Simulator の確かめは「CA を入れたうえで https・wss が通る」までと明記し、実機（iOS・Android 各 1 台）の確認を Deferred（担当・期日・暫定挙動つき）に                                                       |
| 7   | 旅行者の端末に CA が残る。制約が RFC1918 全体と localhost を覆うので、鍵が漏れると利用者の家の私設 IP も中間者の対象                                                                | 名前の制約を `ezoroad.local` と `--ip` の各 IP（/32）だけに狭めた（localhost・私設の範囲全体をやめた）。IP を変えるときは `--new-ca`。設定ページと runbook に「返却したらプロファイルを消す」手順。`ca.key` は発行後に車外へ移す手順を runbook に                                                                                         |
| 8   | IPv6 のスコープ ID（`%`）で HTML が Host の検査を通り、設定ページに入る                                                                                                             | サーバーはページにホストを埋めない（ページの JS が `location.hostname` で組む）。pwa_server の Host は IPv4・`ezoroad.local`・`localhost` だけ（IPv6 は 421）                                                                                                                                                                             |
| —   | dist の読み込みでシンボリックリンクを辿らない・ドットファイルを載せない                                                                                                             | R4 に追記                                                                                                                                                                                                                                                                                                                                 |

## 問題なしとされた点

Capture の Origin 検査は https のページでもそのまま効く。HSTS を付けない・CA の鍵を配らない・397 日は妥当。
