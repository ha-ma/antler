## 採った案と理由

### 車両力学（vehicle.ts）

- **縦は「制動距離から逆算した一定の減速」**。a = v60² / (2 × 50 m × 路面係数)。半陰的オイラー（速さを先に更新）で 1/60 秒を積むと 50 − v·dt/2 ≈ 49.86 m（乾燥）で、±5% に収まる
- **横は道の座標 d を直接動かす**（車体は常に道の向き）。目標の横の速さ = ステア × 2.6 m/s × グリップ。追従の時定数（0.12 s）は路面で変えないので、1 秒の横移動の比がグリップの比（0.7・0.5）にそのままなる（UC-3e は toBeCloseTo 3 桁で一致）
- 吸着: ステアを離すと (−1.75 − d) × 0.7 /s（最大 1.2 m/s）× グリップ。止まっていると横に動かない（5 m/s まで速さに比例）
- 路肩（|d| > 4.5）の外で 30 km/h を超えていたら 9 m/s² で 30 km/h まで落とす（瞬時に 100 → 30 へ飛ばさない。雪の路肩に突っ込む感じ）。アクセルでは 30 km/h を超えない。|d| は 8 で止め、横の速さを 0 にする
- 後退: 走っている間の S は減速、0.5 km/h 未満になってから後退（2.5 m/s²、20 km/h まで）。s < 0 にならない（速さを 0 に）
- 0.5 km/h 未満で W も S も押していなければ速さを 0 にする（`isStopped` を export）

| 値                  | 決めたもの                                                                                                  |
| ------------------- | ----------------------------------------------------------------------------------------------------------- |
| アクセル            | 4.2 m/s² ×（1 − 0.75 × v/vmax）× 駆動の効き（0.5 + 0.5 × グリップ）。乾燥で 0→60 km/h は 6 秒以内（テスト） |
| 惰性                | 0.45 m/s² ＋ 0.012 × v（計算で 100 km/h から 1 秒に約 2.8 km/h 落ちる。テストは 1〜6 km/h）                 |
| グリップ            | 乾燥 1・湿潤 0.85（仮）・圧雪 0.7・凍結 0.5                                                                 |
| 制動距離（60 km/h） | 50・65・75・100 m の理論値から約 0.14 m 短い（v·dt/2）。テストで ±5% を確認                                 |

### 鹿の動き（deer-motion.ts）

- 位置は (s, d)、heading は collision.ts と同じ規約（前方 = (cos h, sin h)、正は右回り）
- **道を渡る鹿（横断・群れ・立ちすくみ）は d だけを動かし、s を変えない**（道を真横に渡る）。これで「動きの係数（動き出す距離 80〜100 m・速さ 2.6〜4.6 m/s・群れの遅れ）」を `deriveSeed(round(s × 100), candidateId / id)` から毎回引き直せる。s は候補の seed から決まるので、同じシードで同じ動き、違うシードで違う動き
  - 理由: `Deer` 型に seed の欄が無い（types.ts は変えない約束）。**Deer に `seed: number`（または `motionSeed`）を足してもらえれば、この回り道は要らない**（下の「頼みたいこと」）
- 段階は `pose` と `startedAt` で表す。**startedAt の意味は「いまの段階が始まった t」**（types.ts のコメントの「動き出した時刻」より広い）
  - 横断・群れ: idle/look（startedAt null）→ 群れの 2 頭目以降は startedAt を「先頭の発火 t ＋ i × 約 1000 ms（±150）」に置いて look で待つ → walk/run で渡る → |d| ≥ 14 で gone
  - 立ちすくみ: idle/look → walk で車線へ → d = −1.75 で止まり look（startedAt を打ち直す。体を車の方へ 135° 回す）→ 車が止まって 3 秒か 12 秒で run（来た向きのまま走り抜ける）→ gone
  - simulation.ts は startedAt を読んでいない（grep で確認）
- 路肩: |d| 4.4〜6.0、道に沿うか道の方を向く。林縁: |d| 9.5〜13.5、occluded 常に true、道（と近づく車）の方を向く。両方とも車が 130 m より近いと look（顔を上げる）
- 渡る鹿の occluded は |d| ≥ 9（林縁）で切り替える（群れの後ろの鹿は林の中にいる間は検知されない）
- 群れは同じ s で、奥へ 2.1 m ずつ一列に並ぶ（体長 1.6 m ＋ すき間。渡る間も重ならない）

### 目の反射（eyeshine.ts）

強さ = beam × facing × range（0〜1）。

- beam = ライトの向きと「ライト → 鹿の目」の内積を、光の円錐の端（30°）で 0・正面で 1 に写したもの
- facing = 鹿の目の向きと「目 → ライト」の内積（負は 0。背を向けると 0）
- range = 70 m までは 1、170 m で 0
- look の鹿は首を車の方へ回す（体から ±100° まで）。目の向きはその首の向き。描画（DeerModel）も同じ `gazeHeading` で頭を回す

### 視線（look.ts）

右・上が正（rad）。three.js への変換（rotation.y = 道の yaw − ヨー）は DriverCamera でする。時定数 0.25 s、1 回に 0.1 秒ぶんまで（タブを戻しても飛ばない）。
ジャイロ（mobile-landscape）も同じ 2 関数に渡せばよい。

### シーン（scene/）

- **World を React の state にしない**。`DriveScene` が useFrame（priority −100）で `onFrame(delta × 1000)` を呼び、−50 で World を読んで車の位置を `SceneFrame`（ref、Context で共有）に置く。部品は −20 で自分の物を置く。**正の priority は使わない**（自動描画が止まる）
- drei の Html（スマホの画面）が同じフレームの行列を読めるよう、カメラと車内は −20 で `updateMatrixWorld` まで済ませる（1 フレーム遅れて 100 km/h でスマホが 0.46 m ずれるのを防ぐ）
- 鹿は「id の並びが変わったときだけ setState」で keyed 描画（毎フレーム再描画しない）。1 頭 = `DeerModel` 1 つ（ch9 ③ が決まったらこの部品だけ差し替える）
- **道路**: 400 m の区間ごとに 1 メッシュ（頂点色、区間の始点を原点にした相対座標で float32 の精度を保つ）。横断面は 車線（±3.5、路面で色）・中央線（黄）・外側線（白）・路肩（±4.6）・除雪の雪の壁（高さ 0.55 m、±8.5 まで）。車の後ろ 80 m〜前 720 m の区間だけを作り、メッシュは 4 つを使い回す（外れた区間は dispose）
- **林と矢羽根**: 種類ごとに InstancedMesh 1 つ（トドマツ 1100・ミズナラ 650・シラカバ 350・矢羽根 64 が上限）。区間ごとに `deriveSeed(trip.seed, 'forest-<区間>')` で置き場所を決め、区間の窓が動いたときだけ行列を書き直す。曲がりの内側でほかの区間の道の上に木を立てない（toRoadCoords で 9 m 以内を捨てる）
- **雪原**: 2.4 km 四方の板 1 枚を車に付けて動かす（50 m 単位で寄せる）。polygonOffset で道路の奥へ押す
- **空とフォグ**: 頂点色のグラデーションの球（1 描画コール）をカメラに付ける。光の区分（world.light）ごとの空・フォグ・半球光・太陽を palette.ts の `SKY` に持ち、区分が変わったら 3 秒で寄せる。フォグの far（昼 650・薄暮 420・夜 300 m、天候で ×0.3〜1）を描画の窓より短くして端を隠す
- **ヘッドライト**: SpotLight 1 つ（左右の灯をまとめる。円錐 30° は eyeshine.ts と同じ）。intensity 900・decay 1.2・distance 190 m。昼は消す（`SKY.day.headlight = 0`）
- **影は落とさない**: 光源が運転者の目のすぐ前なので、ヘッドライトの影は鹿自身に隠れて運転席から見えない。代わりに鹿の足元にぼかしの影（板 1 枚）
- **鹿（自作のローポリ、PBR）**: MeshStandardMaterial（頂点色・roughness 0.92・flatShading）。胴（7 角の筒＋胸と尻の丸み）・臀の白斑（黒い縁）・尾・首と頭（鼻面・耳）・雄は 4 尖の角（id のハッシュで約 4 割）・脚 4 本（付け根で回す）。肩高 約 1.0 m、幅 約 0.45 m、鼻先から尾まで 約 1.7 m（首を前に出した形）。idle は首を下げて草をはむ、look は首を上げて車の方へ回す、walk 1.5 Hz・run 2.7 Hz で対角の脚が同じ位相
  - 目の反射は加算合成の Sprite（2 点のぼかしの DataTexture。canvas を使わないので jsdom でも作れる）。濃さ = eyeshine の強さ、大きさは距離 × 0.0075（最小 0.16 m）で遠くでも数ピクセル残す。fog を受けない（薄暮で最初に見える手がかり）
  - 最初の 3 フレームだけ鹿の材質を地面の下で描いてシェーダーを先に作る（最初の鹿が出た瞬間に固まらないように）
- **車内（右ハンドル）**: 目は車の中心から右 0.30・高さ 1.24・後ろ 0.35 m。ハンドル（右 0.44、A/D で ±1.1 rad 回る）とメーター（針だけ。数字は HUD）は画面の右寄り、ナビは中央（0.08）、スマホはナビの上のマウント（0.10、運転者の方へ 17° 回す）。動かない部品は 1 つの形にまとめる。Lambert のフラットに、光の区分ごとの自発光（夜に真っ黒にしない）
- **スマホの画面**: drei `<Html transform>`、180 × 360 CSS px の箱を 0.075 m 幅に合わせる（distanceFactor = 0.075 / 180 × 400）。`zIndexRange [1, 0]`・pointer-events none（HUD の DOM より下、ポインタを奪わない）。phone が null なら描かない
- `DriveCanvas`: dpr [1, 1.5]、antialias、ACES、カメラ fov 62°・near 0.08・far 1400、style は親いっぱい（absolute inset 0）

## 捨てた案と理由

| 案                                                | 捨てた理由                                                                                                               |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 車体の向きを持つ自転車モデル（ヨー角の積分）      | 仕様が (s, d) を真値にしていて、衝突（collision.ts）も車の箱を道の向きに置いている。グリップの比のテストが厳密にならない |
| 路肩の外は 30 km/h に即座に切る                   | 100 km/h で跨いだ瞬間に速さが飛ぶ。強い減速（9 m/s²）で 3 秒以内に 30 km/h                                               |
| 鹿の動きの係数を Deer に隠しプロパティで持たせる  | simulation.ts が別の形で作り直すと消える。型の約束の外                                                                   |
| 鹿の動きの係数を id だけから引く                  | 候補の id（`d0-3`）はシードによらないので、シードを変えても同じ動きになる                                                |
| 鹿をスロットのプールで描く                        | 「鹿の数がメッシュに出る」を数えにくい。鹿は十数頭までなので keyed 描画で足りる                                          |
| ルート全体（約 36 km、90 区間）の道路を最初に作る | 頂点 約 40 万・数十 MB。窓の 3 区間だけ作れば足りる                                                                      |
| ヘッドライト 2 灯 ＋ 影                           | ライトの数と影の描画で、内蔵 GPU の fragment の重さが倍。影は運転席から見えない                                          |
| 空に drei の Sky / Environment                    | HDR やシェーダーの読込、test-renderer で落ちやすい。頂点色の球で足りる                                                   |
| 計器・ナビに 3D の文字（drei Text）               | フォントの読込が要る。数字は HUD（DOM）が出す                                                                            |

## 頼みたいこと（メインへ）

1. **`Deer` に `seed: number` を足すか**（types.ts）。足せば deer-motion.ts の「s をハッシュの鍵にする」回り道を外せる。足さないなら、道を渡る鹿の s を simulation.ts 側で変えない約束を残す
2. **`Deer.startedAt` のコメントを「いまの段階が始まった t（群れの後続は未来の時刻で待つ）」に直す**か、別の欄を足す
3. HUD の重ねる層は `pointer-events: none`（ボタンだけ auto）にする。視線は R3F の pointer（Canvas の上のカーソル）で追うので、HUD がポインタを奪うと HUD の上で視線が止まる
4. `phone` に渡すものは props だけで描けるものにする（drei Html は別の React root に描くので、メインの Provider の文脈は届かない）
5. 内蔵 GPU（1440×900）の計測を performance-analyzer に（上の dev 用のグローバルを使える）
